# 日终确认清算：确认00表交易机构 / 归属机构赋值说明

> 范围：基金代销日终确认清算（**T210104**）对确认清算表（常用 **`tbdxfundtranscfm00`**，或分 TA 时为 `tbdxfundtranscfm{TA}`）中 **`branch_no`（交易机构）**、**`open_branch`（归属机构）** 的赋值规则。  
> 代码根目录：`.../T210104/`（尤其 `pub/Pub200104Service.java`、`action/Action207xxx.java`）。  
> 并排查其他节点对确认表机构字段的改写，避免遗漏。  
> 梳理日期：20260916。

---

## 1. 表名说明（何为「确认00表」）

`Pub200007Service.initTransVar` 按 TA 清算表模式设置 `TbTransCfmBak`：

| `clear_table_flag` | `TbTransCfmBak` | 说明 |
|--------------------|-----------------|------|
| 公用临时表（常见） | **`tbdxfundtranscfm00`** | 日终清算写机构、状态等，即俗称「确认00表」 |
| 分 TA 临时表 | `tbdxfundtranscfm` + TA代码 | 逻辑同 00 表 |
| 正式分片表（非清算临时） | `tbdxfundtranscfm` / `tbdxfundtranscfm{n}` | 日终结束后由 **T210110** 从 Bak 落入；清算当中 210104 主要改 Bak |

日终机构赋值的主战场是 **210104 写 Bak（00/分TA）→ modifyTransCfm 落库**；210110 一般只做 Bak→正式表拷贝，**不重算**机构。

---

## 2. 总链路

```
TA确认文件
    → tbdxfundtranscfmtmp（机构字段多为空格；T210103 通常不补 open_branch/branch_no）
    → 导入/同步到确认 Bak（transcfm00 等）
    → 【T210104】按业务码 Action207xxx 清算
         ├─ 有申请流水：transTransReqBakToCfmBak → 机构=流水
         ├─ 无流水/TA发起：setTransCfmVal → getTaTransBranch（BANK_BRANCH_SET）
         └─ 特例：142/144/145 参数覆盖；145 可改 branch_no；143 走分红明细
    → modifyTransCfm 写回确认00/Bak
    → 【T210110】Bak → 正式 tbdxfundtranscfm{n}（机构原样带出）
```

公共方法（`Pub200104Service`）：

1. **`transTransReqBakToCfmBak`**：`branch_no`/`open_branch` ← 申请流水。  
2. **`setTransCfmVal`**：TA 发起无流水时，`PubApiFactory.getTaTransBranch(签约机构, 银行卡开户机构, 理财账户开户机构)`，**两者常赋成同一值**。

`BranchService.getTaTransBranch`：

| 参数 `BANK_BRANCH_SET` | `open_branch` 与 `branch_no` |
|------------------------|------------------------------|
| **0**（默认） | 均为 **理财账户** `tbassetacc.open_branch` |
| **1** | 均为 **银行卡** `tbbankacc.open_branch` |

赋值后若存在在途机构撤并，会替换为并入机构。

## 3. T210104 按业务码：机构如何赋

> 「先 A 后 B」表示先走无流水赋值，再被流水覆盖。最终以 Action 内**最后一次 set** + `modifyTransCfm` 为准。

| 业务码 | Action | 主路径 | 交易机构 `branch_no` | 归属机构 `open_branch` |
|--------|--------|--------|----------------------|------------------------|
| 120 认购 | 207120 | **必须有流水** `transTransReqBakToCfmBak` | 流水 | 流水 |
| 122 申购 | 207122 | 同上 | 流水 | 流水 |
| 130 认购结果 | 207130 | 同上 | 流水 | 流水 |
| 139 定投 | 207139 | 同上 | 流水 | 流水 |
| 149 募集失败等 | 207149 | 有流水覆盖 | 流水 | 流水 |
| 152 | 207152 | 有流水覆盖 | 流水 | 流水 |
| 124 赎回 | 207124 | 有流水→覆盖；无→`setTransCfmVal` | 流水或 TA 规则 | 同左 |
| 126/127/128 转托管 | 207126~128 | 有流水 / 无流水分支 | 同上 | 同上 |
| 129 | 207129 | 同上 | 同上 | 同上 |
| 131/132 冻结解冻 | 207131/132 | 同上 | 同上 | 同上 |
| 135/136/137/138 过户转换 | 207135~138 | 同上 | 同上 | 同上 |
| 134 非交易过户入 | 207134 | **直接 `setTransCfmVal`**（典型无流水） | `BANK_BRANCH_SET` 规则 | 与 branch_no 相同 |
| 150 清盘等 | 207150 | `setTransCfmVal` | TA 规则 | TA 规则 |
| 157 | 207157 | `setTransCfmVal` | TA 规则 | TA 规则 |
| 198 | 207198 | 无流水 `setTransCfmVal` / 有流水覆盖 | 视是否有流水 | 视是否有流水 |
| **144 强增** | 207144 | ①`setTransCfmVal` ②若有流水再覆盖 ③若业务码在 `T210104_CFM_OPEN_BRANCH` 中再强制归属=银行卡开户 | 有流水用流水，否则 TA 规则 | 默认同左；参数命中则改为银行卡开户 |
| **142 强赎** | 207142 | `setTransCfmVal` + 可选 `T210104_CFM_OPEN_BRANCH` 覆盖归属 | TA 规则 | 默认同左；参数命中→银行卡开户 |
| **145 强减** | 207145 | `setTransCfmVal`；可选 `SHARE_DEL_BRANCH=1` 用原购买流水改 **branch_no**；可选 `T210104_CFM_OPEN_BRANCH` 改归属 | 默认同 TA；参数开则取原流水交易机构 | 默认同左；参数命中→银行卡开户 |
| **143 红利再投** | 207143（分红明细）→ 207990 写入确认 | **不走**上述两公共方法 | 有份额：=份额 `open_branch`；无份额：`OPEN_BRANCH` 第2位决定银行卡/理财账户 | 与 branch_no 同口径（分红侧两边常都用开户类机构；990 写入确认时 `open_branch`/`branch_no` 常都取分红 `branch_no`） |

### 3.1 关键参数

| 参数 | 默认 | 作用 |
|------|------|------|
| `BANK_BRANCH_SET` | 0 | TA 发起确认：0=理财账户开户机构，1=银行卡开户机构（`branch_no` 与 `open_branch` 同值） |
| `OPEN_BRANCH` | 系统级多位串 | **第2位**影响 143 无份额时机构来源（及份额新建等）；第1位主要影响联机流水归属 |
| `T210104_CFM_OPEN_BRANCH` | 空 | 配置业务码列表（如 `142,144,145`），命中则确认 **`open_branch` 强制=银行卡开户机构**（不改或另规则处理 branch_no，以各 Action 为准） |
| `SHARE_DEL_BRANCH` | 0 | 145 强减：1=交易机构取原份额明细对应购买流水的 `branch_no` |

### 3.2 落库

各 Action 在赋值后调用：

`DxFundServiceFactory.getTransCfmService().modifyTransCfm(transCfmBak, transVar.getTbTransCfmBak())`

即写回 **`tbdxfundtranscfm00`**（或分 TA Bak 表）。

## 5. 结论（给开发 / 联调）

1. **日终确认00表机构的主赋值点就是 T210104**；有流水跟流水，无流水跟 `BANK_BRANCH_SET`（理财账户或银行卡开户机构，且两字段常相同）。  
2. **143** 走分红路径，机构来自份额或 `OPEN_BRANCH` 第2位，再进确认。  
3. **142/144/145** 可通过 `T210104_CFM_OPEN_BRANCH` 把**归属**打成银行卡开户机构；145 另可用 `SHARE_DEL_BRANCH` 改交易机构。  
4. **T210103 / T210110** 不负责重算确认机构；遗漏排查时重点看：管理台改交易机构、行方机构迁移个性化（如 njyh/guangznsh 的 219024）、以及是否启用 210512 对确认表的撤并更新。  
5. 若业务要求「无流水确认归属=银行卡开户机构」，优先核对：`BANK_BRANCH_SET=1`，和/或把业务码配进 `T210104_CFM_OPEN_BRANCH`（仅覆盖 open_branch）。
