# 基金资金划拨流程梳理

## 一、流程概述

基金资金划拨是代销基金业务中的核心环节，负责处理银行与TA之间的资金划拨。整个流程包括数据汇总、划拨准备、划拨执行、资金勾对等多个阶段。

**资金划拨的两个方向**：

1. **认申购资金划拨**（银行向TA划款）：
   - 从认申购归集户（`debit_account`）划到TA账户
   - 通过资金划拨流程（T210025/T210026）处理
   - 认购款：划到募集期TA账户（`bank_acc_ver`）
   - 申购款：划到开放期TA账户（`bank_acc_up`）

2. **兑付资金划拨**（TA向银行划款）：
   - TA将兑付资金（赎回、分红、退款）划到银行的赎回归集户（`crebit_account`）
   - **TA主动发起划拨**（TA系统发起，不通过银行资金划拨流程）
   - 银行系统在 `tbdxfundpayment` 表中汇总 `tot_amt`，用于记录和对账
   - 银行通过入账流程（T210013）将资金给客户上账

**重要说明**：
- **银行资金划拨流程（T210025/T210026）只处理认申购资金的划拨**
- **兑付资金的划拨是TA主动发起的**，TA将资金划到银行的赎回归集户（`crebit_account`）
- **给客户兑付资金是入账节点（T210013）做的事情**，从赎回归集户通过生成入账文件发送到主机，由主机系统给客户上账

### 1.1 核心数据表

| 表名 | 说明 | 用途 |
|------|------|------|
| `tbdxfundsquare` | 资金清算表 | 记录各类业务的清算数据，包括赎回、分红、退款等 |
| `tbdxfundtranssum` | 交易汇总表 | 记录认申购确认金额和手续费 |
| `tbdxfundpayment` | 资金划付表 | 日终清算汇总生成的资金划付数据 |
| `tbdxfundautotransfer` | 自动划拨表 | 从资金划付表汇总生成的自动划拨数据 |
| `tbdxfundreceipt` | 资金录入表 | 记录实际到账的资金，用于勾对 |
| `tbdxfundprdbankacc` | 产品银行账户表 | 记录产品的各类银行账户信息 |

### 1.2 关键日期字段

| 字段 | 说明 | 计算规则 |
|------|------|---------|
| `trans_date` | 交易日期 | 业务日期，数据录入日期 |
| `clear_date` | 清算日期 | 资金实际划付的日期，通常为下一TA工作日 |
| `square_date` | 入账日期 | 资金实际入账的日期，根据勾对模式确定 |

## 三、详细流程说明

### 3.0 管理台资金划拨管理

**菜单路径**: 代销业务 → 资金划拨  
**核心Service**: `DxFundAutoTransferService`, `DxFundAutoTransferUpdateService`, `DxFundAutoTransferAuditService`

#### 3.0.1 查询资金划拨记录

**功能**: 查询 `tbdxfundautotransfer` 表中的资金划拨记录

**查询条件**:
- 划款日期（clear_date）
- TA代码（ta_code）
- 产品代码（prd_code）
- 划款状态（square_status）
- 资金用途（amt_usage）
- 划出账户（bank_acc）
- 划入账户（targ_bank_acc）
- 实时标志（real_flag）

**查询状态过滤**:
- 默认排除状态为 'H'（已删除）的记录
- 支持按状态筛选：'0'（未处理）、'1'（已处理）、'2'（失败）、'3'（未审批）、'4'（审批中）、'6'（划款中）、'7'（超时）、'8'（退回）、'9'（成功）、'A'（待复核）、'F'（失败）等

**明细查询**:
- 支持查询 `tbdxfundautotransferdetail` 表查看产品明细
- 明细表记录每个产品的划拨金额

#### 3.0.2 新增资金划拨记录

**功能**: 人工录入资金划拨记录

**处理流程**:
1. **数据校验**:
   - 检查是否已存在相同记录
   - 检查复核表中是否有待审批记录

2. **写入复核表**:
   ```java
   // 写入 tbdxfundautotransferasy 表
   // 状态：serial_status = '0'（待审批）
   // 操作类型：op_dir = '0'（新增）
   ```

3. **提交审批**:
   - 如果配置了工作流，启动工作流审批
   - 如果未配置工作流，直接审批通过

4. **审批通过后**:
   - 从复核表同步到正式表（tbdxfundautotransfer）
   - 状态更新为 '0'（未处理）

**关键字段**:
- `gen_type`: '1'（人工录入）或 '0'（系统生成）
- `entry_serial_no`: 审批流水号
- `entry_order_no`: 审批序号

#### 3.0.3 修改资金划拨记录

**功能**: 修改已存在的资金划拨记录

**可修改字段**:
- 划拨金额（amt）
- 划出账户（bank_acc）
- 划出账户名称（bank_acc_name）
- 划入账户（targ_bank_acc）
- 划入账户名称（targ_bank_acc_name）
- 开户行（open_bank）
- 备注（remark）

**处理流程**:
1. **参数控制**:
   - `TRANSFER_UPD_NEED_AUDI`: 修改是否需要审批，默认不需要

2. **如果需要审批**:
   - 检查复核表中是否有待审批记录
   - 写入复核表（op_dir = '1'，修改）
   - 提交审批

3. **如果不需要审批**:
   - 直接更新正式表
   - 更新状态为指定状态

4. **审批通过后**:
   - 从复核表同步到正式表
   - 保留原记录的其他字段

#### 3.0.4 提交划拨

**功能**: 将待划拨记录提交到批量系统执行划拨

**处理流程**:
1. **状态更新**:
   ```sql
   UPDATE tbdxfundautotransfer 
   SET square_status = '3',  -- 未审批
       oper_no = ?,          -- 操作柜员
       transfer_type = ?     -- 划拨方式（小额/大额）
   WHERE ...
   ```

2. **调用批量交易**:
   - 交易代码: T210026（J210026）
   - 传递参数: 划款日期、TA代码、产品代码、账户信息等
   - 批量系统执行实际划拨

3. **划拨方式**:
   - 小额划转: `transfer_type = '1'`
   - 默认大额: `transfer_type = '0'`

#### 3.0.5 审批/复核流程

**功能**: 对新增或修改的资金划拨记录进行审批

**审批方式**:
1. **工作流审批**（支持）:
   - 通过工作流引擎进行多级审批
   - 记录审批意见和审批人
   - 支持审批退回

2. **简单审批**（不支持工作流时）:
   - 直接审批通过
   - 更新状态为 '1'（已处理）

**审批状态**:
- `serial_status = '0'`: 待审批
- `serial_status = '4'`: 审批中
- `serial_status = '5'`: 审批通过
- `serial_status = '6'`: 审批不通过

**复核通过处理**:
1. **从复核表同步到正式表**:
   ```java
   // 使用 AsyncEntryAuditUtil.doAcceptEntity() 方法
   // 将 tbdxfundautotransferasy 的数据同步到 tbdxfundautotransfer
   ```

2. **如果是新增且需要发核心**:
   - 调用批量交易 T210026 执行划拨
   - 更新 `approve_remark` 记录审批意见

3. **如果是修改**:
   - 更新正式表对应记录
   - 保留审批意见

**复核不通过处理**:
1. **更新状态**:
   ```sql
   UPDATE tbdxfundautotransfer 
   SET square_status = ?  -- TRANSFER_AUDI_NO_PASS_STATUS 参数值，默认 '4'
   WHERE ...
   ```

2. **记录审批人**:
   - 更新 `auth_oper` 字段

#### 3.0.6 状态查询

**功能**: 查询资金划拨的执行状态

**状态说明**:
| 状态值 | 状态名称 | 说明 |
|--------|---------|------|
| '0' | 未处理 | 初始状态，待提交划拨 |
| '1' | 已处理 | 划拨成功 |
| '2' | 失败 | 划拨失败 |
| '3' | 未审批 | 已提交，待审批 |
| '4' | 审批中 | 工作流审批中 |
| '6' | 划款中 | 正在执行划款 |
| '7' | 超时 | 划款超时 |
| '8' | 退回 | 审批退回 |
| '9' | 成功 | 划款成功 |
| 'A' | 待复核 | 待复核状态 |
| 'F' | 失败 | 划款失败 |
| 'Z' | 处理中 | 批量处理中 |
| 'H' | 已删除 | 已删除（不显示） |

**状态自动更新**:
- 批量系统执行划拨后，自动更新状态
- 支持状态查询接口（T219487）自动更新状态

#### 3.0.7 报表导出

**PDF下载**:
- 功能: 下载资金划拨凭证（PDF格式）
- 模板: `dxautoTransferDef.docx`
- 内容: 划拨基本信息、账户信息、金额、审批意见等

**Excel下载**:
- 功能: 导出资金划拨明细（Excel格式）
- 模板: `ifmCXtglDxFundautotransferTemp.xls`
- 支持: 全部下载（分页打包）或当前页下载

#### 3.0.8 特殊功能

**认申购资金自动划拨**:
- 支持认申购资金自动划拨功能
- 通过参数 `FUND_AUTO_TRANSFER_BUY_AMT` 控制
- 自动生成划拨记录并执行

**两步划拨显示**:
- 如果配置了两步划拨（`AUTOTRANSFERMODE = '1'`）
- 第一步失败时，显示目标账户为统一过渡户
- 第一步成功时，显示划出账户为统一过渡户

**按产品汇总金额上限**:
- 支持控制按产品汇总划拨金额上限
- 参数: `AUTO_TRANSFER_PRD_AMT_LIMIT`
- 超过上限时，按产品拆分多条记录

#### 3.1.1 数据同步

#### 3.1.2 兑付资金汇总（用于记录和对账）

从 `tbdxfundsquare` 表汇总生成初始的划付记录：

```sql
INSERT INTO tbdxfundpayment 
(clear_date, square_date, prd_code, ta_code, curr_type, 
 red_amt, div_amt, refund_amt, trans_date, deal_status, area_id)
SELECT 
    clear_date, 
    clear_date,  -- 默认不入账时，square_date = clear_date
    prd_code, 
    ta_code, 
    curr_type,
    SUM(CASE WHEN busin_code IN ('124','163', '142', '125', '149', '151', '150') 
             THEN amt ELSE 0 END) red_amt,  -- 赎回金额
    SUM(CASE busin_code 
            WHEN '143' THEN amt 
            WHEN '743' THEN amt 
            ELSE 0 END) div_amt,  -- 分红金额
    SUM(CASE WHEN busin_code IN ('130', '888') 
             THEN amt ELSE 0 END) refund_amt,  -- 退款金额
    ? trans_date, 
    '0' deal_status,  -- 待支付
    ? area_id
FROM tbdxfundsquare
WHERE ta_code = ? 
  AND trans_date = ?
GROUP BY clear_date, prd_code, ta_code, curr_type
```

**业务代码说明**:
- **赎回**: 124(普通赎回)、163(快速赎回)、142(其他赎回)、125(预约赎回)、149(募集失败)、151(快速赎回)、150(快速赎回)
- **分红**: 143(分红)、743(分红)
- **退款**: 130(比例退款)、888(其他退款)

**重要说明**：
- 这些兑付资金汇总到 `tbdxfundpayment` 表用于**记录TA应划给银行的金额**，用于对账和确认
- **兑付资金的划拨流程**：
  1. **TA主动划拨**：TA根据 `tbdxfundpayment` 中的 `red_amt`、`div_amt`、`refund_amt` 或 `tot_amt`，**主动将资金划到银行的赎回归集户（`crebit_account`）**
  2. **银行记录**：银行在 `tbdxfundpayment` 中记录这些金额，用于确认TA是否已划款到位
  3. **银行对账**：银行可以通过 `tbdxfundreceipt`（资金录入表）记录TA实际划到赎回归集户的资金，与 `tbdxfundpayment` 进行勾对
  4. **客户上账**：银行通过入账流程（T210013）将赎回归集户中的资金给客户上账

**资金流向**：
```
TA确认兑付（赎回、分红、退款）
    ↓
tbdxfundsquare (清算确认) - 记录兑付清算数据
    ↓
tbdxfundpayment (日终汇总) - 汇总red_amt/div_amt/refund_amt（TA应划给银行的金额）
    ↓
TA系统主动发起划拨
    ↓
TA账户 → 赎回归集户（crebit_account）- TA主动划拨，不通过银行资金划拨流程
    ↓
tbdxfundreceipt (资金录入) - 银行记录TA实际划到赎回归集户的资金
    ↓
资金勾对 (T210013) - 勾对确认TA是否已划款到位
    ↓
入账流程 (T210013) - 生成入账文件
    ↓
主机系统处理入账文件
    ↓
客户账户收到兑付资金
```

### 5.2 数据流向

#### 5.2.1 认申购资金划拨流向

```
客户认申购资金
  ↓
tbdxfundsquare (清算确认) - 记录认申购清算数据
  ↓
tbdxfundtranssum (交易汇总) - 汇总认申购确认金额
  ↓
tbdxfundpayment (日终汇总) - 汇总cfm_amt（认申购确认金额）
  ↓
tbdxfundautotransfer (划拨准备) - 生成认申购资金划拨记录
  ├─ bank_acc: 认申购归集户（debit_account）- 划出账户
  └─ targ_bank_acc: TA账户（bank_acc_ver/bank_acc_up）- 划入账户
  ↓
主机划拨接口 (400011) - T210026 - 执行资金划拨
  ↓
状态查询 (300407) - T210027 - 查询划拨状态
  ↓
tbdxfundreceipt (资金录入) - 记录TA到账资金
  ↓
资金勾对 (T210013) - 勾对确认
  ↓
更新 square_date 和 deal_status
```

#### 5.2.2 兑付资金流向（TA主动划拨）

```
TA确认兑付（赎回、分红、退款）
  ↓
tbdxfundsquare (清算确认) - 记录兑付清算数据
  ↓
tbdxfundpayment (日终汇总) - 汇总red_amt/div_amt/refund_amt（TA应划给银行的金额）
  ↓
TA系统主动发起划拨（TA系统处理，不通过银行资金划拨流程）
  ├─ TA根据tbdxfundpayment中的金额信息
  └─ TA主动将资金划到银行的赎回归集户（crebit_account）
  ↓
tbdxfundreceipt (资金录入) - 银行记录TA实际划到赎回归集户的资金
  ↓
资金勾对 (T210013) - 勾对确认TA是否已划款到位
  ↓
入账流程 (T210013) - 生成入账文件
  ├─ 从tbdxfundsquare查询兑付记录
  ├─ 生成入账文件
  └─ 发送到主机系统
  ↓
主机系统处理入账文件
  ├─ 从赎回归集户（crebit_account）扣款
  └─ 主机系统给客户上账
  ↓
客户账户收到兑付资金
```

**重要说明**：
- **认申购资金**：通过银行资金划拨流程（T210025/T210026），从认申购归集户划到TA账户
- **兑付资金**：
  - **TA主动划拨**：TA根据 `tbdxfundpayment` 中的金额信息，主动将资金划到银行的**赎回归集户（`crebit_account`）**
  - **银行记录对账**：银行在 `tbdxfundpayment` 中记录TA应划金额，通过 `tbdxfundreceipt` 记录TA实际划款，进行勾对确认
  - **客户上账**：银行通过入账流程（T210013）将赎回归集户中的资金给客户上账
- **资金划拨流程（T210025/T210026）不处理TA向银行的兑付资金划拨**，只处理银行向TA的认申购资金划拨

## 七、特殊场景处理

### 6.1 募集失败处理

**场景**: 同一天同一条流水既有120（认购成功）又有149（募集失败）

**处理逻辑**:
1. 如果参数 `RETURN_AMT_FROM_ACCOUNT = '1'` (使用认申购归集户返款)
2. 从 `cfm_amt` 中扣除对应的120金额
3. 120不向TA划款

### 6.2 余额宝产品

**场景**: 余额宝产品支持T+1划拨

**处理逻辑**:
1. 通过 `table_num = 'YebSub'` 标识余额宝业务
2. 在查询和删除时增加 `table_num` 条件

### 6.3 两步划拨

**场景**: 配置了两步划拨模式（`AUTOTRANSFERMODE = '1'`）

**处理逻辑**:
1. **第一步**: 从归集户划到中间账户
2. **第二步**: 从中间账户划到TA账户
3. 中间账户信息通过参数配置

### 6.4 手续费单独划拨

**场景**: 产品配置了手续费单独划拨（`square_way = '1'`）

**处理逻辑**:
1. 认申购款划拨时扣除手续费
2. 手续费单独生成一条划拨记录（`amt_usage = '2'`）
3. 手续费划到手续费专户（`charge_account`）

## 八、注意事项

### 7.1 数据一致性

1. **主键唯一性**: `tbdxfundpayment` 表主键由 `area_id`, `table_num`, `clear_date`, `prd_code`, `ta_code`, `curr_type`, `trans_date` 组成
2. **删除操作**: 删除时使用 `ta_code` + `trans_date`（+ `table_num`）作为条件
3. **数据同步**: 从交易片区同步到公共片区时，需要确保数据一致性

### 7.2 日期处理

1. **clear_date**: 资金清算日期，通常为下一TA工作日
2. **square_date**: 资金入账日期，根据勾对模式确定
3. **trans_date**: 业务日期，数据录入日期
4. **产品工作日**: 部分银行可能支持按产品工作日划款（个性化逻辑）

### 7.3 金额计算

1. **认申购款**: 根据 `square_way` 判断是否扣除手续费
2. **手续费**: 普通TA按比例分配，中登TA直接取代理费
3. **总金额**: `tot_amt = red_amt + div_amt + refund_amt + other_amt`

### 7.4 状态管理

1. **deal_status**: '0' (待支付) → '1' (已处理)
2. **square_status**: '0' (未处理) → 'Z' (处理中) → '6'/'9'/'F'/'7' (最终状态)
3. **check_status**: 'K_GDZT_NO' (未勾对) → 'K_GDZT_YES' (已勾对)

### 7.5 错误处理

1. **余额不足**: 划款前建议校验内部账户余额（如果银行实现了此功能）
2. **划款失败**: 记录错误信息和错误代码
3. **超时处理**: 支持超时状态查询和重试

## 十二、总结

基金资金划拨流程是一个复杂的多阶段过程，涉及数据汇总、日期调整、划拨准备、划拨执行、资金勾对等多个环节。每个环节都有其特定的业务规则和处理逻辑，需要严格按照流程执行，确保资金划拨的准确性和及时性。

### 12.1 资金划拨范围

**银行资金划拨流程（T210025/T210026）处理**：
1. **认申购资金划拨**（银行向TA划款）：
   - 从认申购归集户（`debit_account`）划到TA账户
   - 认购款：划到募集期TA账户（`bank_acc_ver`）
   - 申购款：划到开放期TA账户（`bank_acc_up`）

2. **手续费划拨**（银行向手续费专户划款）：
   - 从认申购归集户（`debit_account`）划到手续费专户（`charge_account`）

**银行资金划拨流程不处理**：
- **兑付资金（赎回、分红、退款）不通过银行资金划拨流程（T210025/T210026）**

**兑付资金的划拨流程**（TA主动发起）：
1. **TA主动划拨**：
   - TA根据 `tbdxfundpayment` 中的 `red_amt`、`div_amt`、`refund_amt` 或 `tot_amt`
   - TA主动将资金划到银行的**赎回归集户（`crebit_account`）**
   - 这个划拨由TA系统发起，不通过银行的资金划拨流程

2. **银行记录对账**：
   - 银行在 `tbdxfundpayment` 中记录TA应划金额（`red_amt`、`div_amt`、`refund_amt`、`tot_amt`）
   - 通过 `tbdxfundreceipt`（资金录入表）记录TA实际划到赎回归集户的资金
   - 进行勾对确认TA是否已划款到位

3. **客户上账**：
   - 银行通过入账流程（T210013）将赎回归集户中的资金给客户上账
   - 从 `tbdxfundsquare` 表生成入账文件
   - 发送入账文件到主机系统
   - 主机系统处理入账文件，给客户上账

### 12.2 关键账户说明

| 账户类型 | 账户字段 | 用途 | 资金流向 |
|---------|---------|------|---------|
| 认申购归集户 | `debit_account` | 客户认申购资金的归集账户 | 客户 → 认申购归集户 → TA账户（通过资金划拨） |
| 赎回归集户 | `crebit_account` | TA兑付资金的归集账户 | TA主动划拨 → 赎回归集户 → 客户（通过入账流程） |
| 募集期TA账户 | `bank_acc_ver` | 认购款划入账户 | 认申购归集户 → 募集期TA账户（资金划拨） |
| 开放期TA账户 | `bank_acc_up` | 申购款划入账户 | 认申购归集户 → 开放期TA账户（资金划拨） |
| 手续费专户 | `charge_account` | 手续费划入账户 | 认申购归集户 → 手续费专户（资金划拨） |

### 12.3 关键要点

1. **数据准确性**: 确保各阶段数据计算的准确性
2. **日期处理**: 正确处理清算日期和入账日期
3. **账户选择**: 根据业务类型选择正确的账户
4. **状态管理**: 正确更新和处理各种状态
5. **异常处理**: 妥善处理各种异常情况
6. **审批流程**: 管理台操作需要遵循审批流程，确保资金安全
7. **工作流支持**: 支持工作流审批，提高审批效率和规范性
8. **流程区分**: 明确区分资金划拨流程和入账流程的职责范围
