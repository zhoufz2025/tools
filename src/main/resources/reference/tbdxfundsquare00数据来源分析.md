# tbdxfundsquare00 表数据来源详细分析

## 一、概述

在清算过程中，`tbdxfundsquare00` 表（或根据参数使用 `tbdxfundsquare` 正式表）是资金清算入账表的临时表，用于存储清算过程中生成的所有账务记录。本文档详细分析清算过程中向该表插入数据的各个业务场景。

## 二、数据插入方式

### 2.1 表名获取方式

清算过程中，所有对 `tbdxfundsquare` 的操作都通过 `TransVar200007.getTbSquareBak()` 方法获取表名：

```java
String tbSquareBak = transVar.getTbSquareBak();
// 可能是 "tbdxfundsquare00" 或 "tbdxfundsquare"
```

**表名确定逻辑**（`Pub200007Service.initTransVar()`）：
- 如果 `T210104_SQUARE_00TT='1'`：使用 `tbdxfundsquare00`（临时表）
- 否则：使用 `tbdxfundsquare`（直接使用正式表）

### 2.2 数据插入方法

主要有以下几种方式：

1. **直接SQL插入**：
   ```sql
   INSERT INTO {tbSquareBak} SELECT ... FROM ...
   ```

2. **通过服务接口插入**：
   ```java
   DxFundServiceFactory.getSquareService().addSquare(square, tbSquareBak);
   DxFundServiceFactory.getSquareService().addSquareWithoutClientInfo(square, tbSquareBak);
   ```

3. **通过ClearEndFunc的addSquare方法**：
   ```java
   this.addSquare(square);  // 内部使用tbdxfundsquare1
   ```

## 三、主要业务场景数据来源

### 3.1 T210104节点（交易类确认数据清算）

**节点位置**：`T210104HSAdapter.java`

**说明**：T210104节点是清算过程中最重要的节点，负责处理TA确认后的各种交易数据，生成对应的账务记录。

**处理方式**：
- 通过 `TransCfmFunc.businClear()` 方法
- 从 `tbbusinorder` 表查询业务处理顺序
- 按照 `order_no` 字段的顺序依次执行各个Action类
- 每个Action类负责处理对应的业务代码（busin_code）

**关键代码**（`TransCfmFunc.java`）：
```java
// 查询业务顺序配置
dataset = session.getDataSet(
    "select * from tbbusinorder where ta_code=? and area_type=? order by order_no",
    request.getString(ITag.TaCode) + squareType, 
    IDict.K_PQLB.K_PQLB_TRANS  // 交易类，值为'1'
);

// 按顺序执行各个Action
dataset.beforeFirst();
for (int i = 0; i < dataset.getRowCount(); i++) {
    dataset.next();
    transCode = dataset.getString("busin_code");  // 如"207143"
    action = getAction(transCode);  // 获取Action类，如Action207143
    action.action(context);  // 执行业务处理
}
```

#### 3.1.1 分红业务（Action207143）

**文件位置**：`Action207143.java`

**业务代码**：`143`（现金分红）

**处理顺序**：`order_no = 9`

**协议说明**：
- **业务定义**：现金分红（协议定义：现金分红）
- **业务场景**：基金公司将基金收益以现金形式分配给投资者，投资者获得现金红利，不增加基金份额
- **账务处理**：贷方（增加客户资金），支付现金红利
- **注意**：Action207143中的"143"对应协议文档中的业务码143（现金分红）

**插入方式**：直接SQL插入

**插入逻辑**：
```sql
INSERT INTO {tbSquareBak}{tableNum} 
(square_no, trans_date, clear_date, square_date, serial_no, from_flag, 
 trans_code, busin_code, client_type, in_client_no, bank_no, client_no,
 bank_acc, bank_acc_kind, channel, branch_no, open_branch, ta_code, prd_code,
 liqu_dir, amt, curr_type, cash_flag, unfrozen_amt, frozen_amt, amt_flag, 
 check_status, cost_income_flag, vol_cumulate, prd_account, prd_account_kind, 
 summary, status, reserve2)
SELECT 
    a.cfm_no,                    -- square_no: 使用确认流水号
    a.cfm_date,                  -- trans_date: 确认日期
    {clearDate},                  -- clear_date: 清算日期
    {squareDate},                 -- square_date: 入账日期
    a.cfm_no,                     -- serial_no: 确认流水号
    '0',                          -- from_flag: 来自TA
    {functionId},                 -- trans_code: 功能ID（210104或170407）
    a.busin_code,                 -- busin_code: 业务代码（143）
    a.client_type,                -- client_type: 客户类型
    a.in_client_no,               -- in_client_no: 内部客户号
    a.bank_no,                    -- bank_no: 银行代码
    a.client_no,                  -- client_no: 客户号
    a.bank_acc,                   -- bank_acc: 银行账号
    a.client_type,                -- bank_acc_kind: 账号类型
    'TA',                         -- channel: 渠道（TA）
    a.branch_no,                  -- branch_no: 机构代码
    a.open_branch,                -- open_branch: 开户机构
    {taCode},                     -- ta_code: TA代码
    a.prd_code,                   -- prd_code: 产品代码
    '1',                          -- liqu_dir: 账务方向（1-贷，分红是增加资金）
    a.cfm_amt + {frozenAmt},      -- amt: 金额（确认金额+冻结金额）
    a.curr_type,                  -- curr_type: 币种
    {cashFlag},                   -- cash_flag: 钞汇标志
    0.0,                          -- unfrozen_amt: 解冻金额
    {frozenAmt},                  -- frozen_amt: 冻结金额
    {amtFlag},                    -- amt_flag: 金额标志（区分普通分红和智能投顾分红）
    '0',                          -- check_status: 核对状态（未核对）
    '1',                          -- cost_income_flag: 成本收益标志
    a.vol_cumulate,               -- vol_cumulate: 累计份额
    {divAccount},                 -- prd_account: 产品账户（分红账户）
    '2',                          -- prd_account_kind: 产品账户类型
    '分红资金入帐',                -- summary: 摘要
    '0',                          -- status: 入账标志（未入账）
    {reserve2}                    -- reserve2: 保留字段（日启清算标记）
FROM tbdxfunddivdetail{taCode} a
WHERE a.cfm_date = ? 
    AND a.busin_code = '143'
  AND a.status = ?
```

**数据来源表**：
- `tbdxfunddivdetail{taCode}`：分红明细表

**关键字段说明**：
- `liqu_dir = '1'`：分红是贷方，增加客户资金
- `amt_flag`：区分普通分红（`K_ZJLB_NORMAL`）和智能投顾分红（`K_ZJLB_GRP_DIV`）
- `prd_account`：从产品配置的分红账户获取

**文件位置**：`Action207120.java`

**业务代码**：`120`（认购确认）

**处理顺序**：`order_no = 10`

- **特殊场景**：在处理认购确认时，如果产品发行失败或认购失败，会生成退款账务（贷方）
- **注意**：Action207120中的"120"对应协议文档中的业务码120（认购确认）

**插入方式**：通过服务接口

**数据来源**：
- `tbdxfundtranscfm{taCode}`：确认表

## 七、注意事项

### 7.1 临时表使用

   - `T210104_SQUARE_00TT='1'`：使用临时表 `tbdxfundsquare00`
   - 否则：直接使用正式表 `tbdxfundsquare`

2. **表名获取**：
   - 所有插入操作都通过 `transVar.getTbSquareBak()` 获取表名
   - 确保使用正确的表名

### 7.2 数据一致性

1. **事务控制**：
   - 每个业务处理都在事务中完成
   - 确保数据一致性

2. **分表处理**：
   - 需要循环处理所有分表（1-16）
   - 根据 `in_client_no` 分片

### 7.3 汇总处理

1. **智能投顾汇总**：
   - 在T210110节点进行汇总
   - 将明细记录更新为已入账
   - 插入汇总记录

2. **汇总时机**：
   - 必须在所有明细记录插入完成后进行
   - 确保汇总数据的准确性

## 八、业务清算顺序的重要性

### 8.1 顺序依赖关系

**关键依赖**：

1. **Action207000（数据准备）**：
   - 必须最先执行（`order_no = 1`）
   - 将TA文件导入的临时表数据转移到清算临时表
   - 为后续所有业务处理提供数据基础

2. **分红业务（Action207143）**：
   - 通常在申购和赎回之前处理（`order_no = 9`）
   - 分红金额基于份额数据计算
   - 份额数据来自申购、赎回等业务

3. **申购业务（Action207122）**：
   - 在赎回之前处理（`order_no = 11`）
   - 申购确认后增加份额
   - 为后续业务提供份额基础

4. **赎回业务（Action207124）**：
   - 在申购之后处理（`order_no = 23`）
   - 赎回确认后减少份额
   - 需要基于已有的份额数据

5. **Action207990（统计汇总）**：
   - 必须最后执行（`order_no = 54`）
   - 汇总所有业务处理的结果
   - 更新产品账户等信息

### 8.2 顺序错误的影响

如果业务处理顺序错误，可能导致：

1. **数据计算错误**：
   - 分红金额计算错误（份额数据不准确）
   - 份额余额计算错误

2. **数据不一致**：
   - 份额表与账务表不一致
   - 产品账户余额错误

3. **业务逻辑错误**：
   - 某些业务依赖前面业务的结果
   - 顺序错误会导致依赖关系断裂

### 8.3 顺序配置建议

1. **标准顺序**：
   - 按照 `tbbusinorder-dxfund_TA.sql.vm` 中的标准顺序配置
