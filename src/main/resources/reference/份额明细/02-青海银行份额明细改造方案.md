# 青海银行份额明细与交易机构保有量：改造方案

> 对照需求：基金代销份额明细登记、日终拆分规则、归属机构、存量补算、换卡、归档、报表影响、新增「交易机构保有量报表」。  
> 对照基线：标准节点 **T210839** 及保有量汇总（见同目录《01-标准份额明细流程与支持能力》）。  
> **前提：青海银行低柜不上线，渠道以手机银行等电子渠道为主；归属机构口径统一按银行账号开户机构，不再区分低柜/电子二分。**  
> 银行代码建议：`qhyh_dxfund`。梳理日期：20260916。

---

## 1. 支持程度总览

| 需求点 | 标准支持 | 青海落地建议 |
|--------|----------|--------------|
| 1. 全部代销产品登记份额明细供报表 | **参数/调度开通即可** | 下发 210839、`*_SD`、调度挂 J210110 后 |
| 2a. 增份额业务一笔一明细（122/130/139/136入/127/144/133入/134） | **已支持** | 配置业务顺序；无需改 Java |
| 2b. 143 首次一条、后续累加 | **已支持**（`ShareDtl143Mode=2`） | 下发参数=2；注意首次 `cfm_date/cfm_no` 保留，后续累加不改主键确认号 |
| 2c. 扣减 FIFO | **基本支持**（按 `serial_no`） | 与「按确认日+确认流水号」文字略异；模式2分红最后扣，与举例一致。若行方强制 cfm 排序，需改 `ConsignShareDtlService`（评估后定） |
| 2d. 其他业务不处理 | **已支持** | 不配入 `_SD` 即可 |
| 3. 明细归属机构统一取**银行账号开户机构**（有/无流水、143 同口径） | **不完全支持** | **需改造或参数对齐**（见 §4）；低柜不上线，无「低柜取交易机构」分支 |
| 4. 存量补算 | **已支持** | 210840/841 + 模式2 + 窗口压测 |
| 5. 仅报表、不改主交易流程 | **已满足** | 保持 |
| 6. 换卡更新明细 bank_acc | **已支持** | 白名单 + 可选 `T210839_DEAL_CHG_CARD` |
| 7. 清零归档历史表 | **已支持** | T210015 + Archiving.days；注意报表性能 |
| 8. 流水所属机构取**开户机构**，影响保有量/确认汇总「按开户机构」 | **参数可基本覆盖** | `OPEN_BRANCH` 第1位=`1`，必要时个性化兜底（见 §5） |
| 9. 管理台「交易机构保有量报表」 | **数据能力有、专用菜单弱** | 复用 `SHAREDTL_FEYEHZ`/`FEYEHZ_BY_DTL` + 新增/改造菜单页（见 §6） |

**结论：** 拆分主链路约 **70%+ 可配置复用**。低柜不上线后，归属规则**收敛为统一开户机构**，改造点少于原「渠道二分」方案；剩余差距主要在 **（1）明细/143 强制开户机构**、**（2）流水 open_branch 与报表口径**、**（3）交易机构保有量菜单落地**。

## 2. 目标架构（青海）

```
联机交易（电子渠道）
  └─ 流水 open_branch 取银行账号开户机构（§5）
         │
日终 J210110 确认清算
         │
         ▼
J210839 DXFUND210839
  · ShareDtl143Mode=2
  · 明细 open_branch：统一开户机构（§4）
  · FIFO 扣减 → tbdxfundsharedtl
         │
         ▼
J210014 保有量
  · SHAREDTL_FEYEHZ=12  → hisfeyehz（sum_flag 0 交易机构 / 1 归属）
  · FEYEHZ_BY_DTL=1     → hisfeyedtlhz（明细机构保有量，可选）
         │
         ├─ 归档 T210015
         └─ 管理台
              · 「保有量/确认汇总-按开户机构」随流水/明细 open_branch=开户机构
              · 新增「交易机构保有量报表」（sum_flag=0，按明细 branch_no）
```

原则：

- **不改**份额表主余额、确认入账、客户交易主路径。  
- **不做**低柜归属分支；改造尽量 **参数 + 银行包**。

## 4. 归属机构规则改造（需求 3）——核心差距

### 4.1 需求口径（低柜不上线后的简化）

| 场景 | 归属机构（明细 `open_branch`） |
|------|-------------------------------|
| 122/130/139/136目标/127/144/133入/134 等（有或无申请流水） | **银行账号开户机构** |
| 143 红利再投 | **银行账号开户机构** |
| 其他无申请流水的增加类 | **银行账号开户（开卡）机构** |

同时登记 `channel`（有流水时取流水渠道，供留痕/查询，**不参与**归属机构分支判断）。

> 原需求中「低柜取交易机构」分支：**青海不实施**。

### 4.2 与标准差异

- 默认模式：明细 `open_branch`≈流水 `open_branch`；若流水已按 §5 取开户机构，多数有流水场景可对齐，但 **143/无流水** 仍可能落确认机构或根机构。  
- `SHARE_DTL_OPEN_BRANCH_MODE=1`：客户经理链，**不等于**「一律开户机构」。  
- 143：标准取确认机构或根机构，**不是**强制开户机构 → **仍需改造**。

### 4.3 改造方案（推荐）

**方案 A（推荐）：明细侧统一强制开户机构**

1. 扩展参数（如 `SHARE_DTL_OPEN_BRANCH_MODE=2` 表示「强制银行账号开户机构」），或 `qhyh` 个性化 Bean。  
2. `PubFunction210839` 增加解析：`BankAccInfo.openBranch`（必要时查账户中心）；空值策略与产品约定。  
3. 增加类 Action 及 **143** 在落库前覆盖 `open_branch`。  
4. `branch_no`（交易机构）仍保留流水/确认上的交易机构字段，供「交易机构保有量」；与 `open_branch` 分离，**不要**因归属改造而抹掉 `branch_no`。

**方案 B：** 联机流水已统一开户机构（§5）+ 210839 模式 0 跟流水；**仅 143/无流水** 在明细侧补开户机构。  

- 改造面更小，适合低柜不上线、渠道单一场景。  
- **建议以 B 为主、A 兜底 143/无流水**，避免确认补处理漏归属。

### 4.4 电子渠道开户机构来源

手机银行等须能落到开户机构：  

- 优先本地 `tbbankacc.open_branch`；缺失时查账户中心或要求报文上送。  
- 联调：电子渠道申购、定投、转换入、红利再投确认后查明细 `open_branch`。

## 5. 交易流水所属机构调整（需求 8）

### 5.1 需求（按电子渠道落地）

- 电子渠道：交易归属机构（流水 `open_branch`）= **银行账号开户机构**。  
- （低柜=交易机构：**不上线，不改造、不测试。**）  
- 影响：  
  - 基金代销保有量统计报表-**按开户机构**；  
  - 基金代销交易确认汇总报表-**按开户机构**。

### 5.2 现状

`BranchSetService`：`OPEN_BRANCH` 第1位 `0`=理财账户归属，`1`=银行账号开户机构。  
电子渠道场景下，将第1位配为 **`1`** 即可贴近需求，多数情况**无需**再写低柜分支个性化。

### 5.3 改造建议

1. 优先配置 `OPEN_BRANCH` 第1位=`1`，验证电子渠道流水 `open_branch` 是否等于账号开户机构。  
2. 仍不一致时再上青海 `SetAccBranchImpl` 强制覆盖（只处理电子渠道）。  
3. 评估历史报表是否重跑（通常仅新数据生效，与业务确认）。  
4. 回归：手机银行购买 → 流水 open_branch → 确认汇总/保有量按开户机构。

## 6. 「交易机构保有量报表」（需求 9）

### 6.1 数据层

开通后 `SHAREDTL_FEYEHZ` 含 **1** 时，210014 按明细 `branch_no` 写入 `sum_flag=0`（`K_HZFS.HZFS_JYJG`）。  
或 `FEYEHZ_BY_DTL=1` 写入 `tbdxfundhisfeyedtlhz`（`DxfundFemxBylService` 已查此表）。

说明：低柜不上线后，电子渠道明细的 `branch_no` 可能与开户机构接近或相同（视渠道上送与 `BranchSet` 规则）；**交易机构保有量仍按 `branch_no` 汇总**，与「按开户机构」报表（`open_branch` / `sum_flag=1`）维度分离，避免混用。

### 6.2 菜单与查询

需求字段与标准保有量（产品/TA/机构三维）高度同构：

| 维度 | 查询条件 | 结果要点 |
|------|----------|----------|
| 按产品 | 统计层数、机构、TA、基金类型、产品、模板、客户类型、起止日期(必输) | 机构、产品、模板、TA、净值、基金类型、余额份额/金额、有效户数、客户类型、日期 |
| 按 TA | 层数、机构、TA、基金类型、产品、客户类型、起止日期 | 机构、TA、份额/金额、户数、客户类型、日期 |
| 按机构 | 层数、机构、TA、基金类型、产品、客户类型、起止日期 | 机构、份额/金额、户数、客户类型、日期 |

**落地选项：**

| 选项 | 做法 | 适用 |
|------|------|------|
| **复用增强** | 复制 `ifmCDyglDxfundByltj` / `FemxByltj`，默认 `sumFlag=0`，菜单名改为「交易机构保有量报表」 | 推荐，工期短 |
| **新建菜单** | `ifmCDyglDxfundJyjgByltj`（注意长度≤32），后端可委托现有 Byl/Femx Service，固定 sum_flag=0 | 菜单权限独立时 |

前端：当前工程 `console-dxfund-vue` 未见 `FemxByltj` 页面文件时，需**补 Vue + 路由**（对齐 `ifmCDyglDxfundByltj` 三 Tab：产品/TA/机构）。

后端已有参考：

- `DxfundBylService`（`tbdxfundhisfeyehz`）  
- `DxfundFemxBylService`（`tbdxfundhisfeyedtlhz`）

按产品模板、基金类型等条件：复用 Byl 现有过滤与 `DxFundProduct` 缓存翻译；缺口字段在 Service `getHss` / `datasetTranslate` 补齐。

## 7. 存量补算、换卡、归档、性能（需求 4/6/7）

### 7.1 上线补算

1. 清空或隔离未启用前的试验明细数据。  
2. 按份额表 `tot_vol>0` 灌底数（参考东莞/华融 210840 脚本）。  
3. `SHARE_DTL_RE_CALC_ACTION=2`，配置回溯起止日，跑 **210840 → 210841**。  
4. 回溯须走 §4「开户机构」归属逻辑，保证与上线后日终口径一致。  
5. 窗口：按 300 万级约 5 小时预留；生产前压测；可分 TA 并行。

### 7.2 换卡

- 确认换卡白名单含 `tbdxfundsharedtl*.bank_acc`。  
- 清算异常时配置 `T210839_DEAL_CHG_CARD`。  
- 换卡后若开户机构变化，评估是否需重算明细 `open_branch`（默认换卡只更 `bank_acc`，与产品确认）。

### 7.3 归档与报表性能

- 开启 `DxFundShareDtlArchiving`，避免当前表膨胀。  
- 报表：`hisfeyehz` / `hisfeyedtlhz` 按日期、机构索引；查询强制起止日期；大区间走归档年表策略。  
- 测试要点：明细生成耗时、210014 汇总耗时、交易机构保有量大数据量查询/下载。

## 9. 需求举例与标准行为核对

举例：买 3000、买 4000 → 两笔明细；红利再投 100 → 第三笔；赎 3100 → 第一笔清零、第二笔剩 3900、红利 100；再投 120 → 红利变 220；再买 2000 → 第四笔。

| 步骤 | `ShareDtl143Mode=2` + FIFO(serial) |
|------|-------------------------------------|
| 两笔购买 | 两笔明细 ✅ |
| 首次 143 | 新增一条（serial `zz…`）✅ |
| 赎 3100 | 先扣较早 serial（3000 清零 + 100 从 4000）→ 0 / 3900 / 100 ✅ |
| 再 143 | 累加到 143 明细 → 220 ✅ |
| 再购买 | 新明细 2000 ✅ |

与需求一致；前提是 143 使用模式 **2**（模式 0 会每次新增分红明细，赎回顺序也不同）。  
归属：上述各笔明细 `open_branch` 均应为对应账号**开户机构**。

## 10. 测试要点（摘要）

**正向**

1. 配置开通后，上述举例份额正确；明细 `open_branch`=开户机构（含 143）。  
2. 电子渠道购买/定投/转换入：流水与明细归属均为开户机构。  
3. `sum_flag=0/1` 保有量与明细勾稽；交易机构保有量三维查询/下载。  
4. 换卡后明细 `bank_acc` 更新；次日清算正常。  
5. 清零明细进入历史表。

**反向**

1. 未开 210839：无明细、主交易不受影响。  
2. `SHAREDTL_FEYEHZ=02`：应报错/禁止。  
3. 本地无开户机构且无法查得：明确报错或降级策略（需产品定）。  
4. 重复跑 210839：sharecfm 防重不双增。

**性能**

1. 210839/210840 大数据量耗时。  
2. 交易机构保有量跨月查询与下载。

**不做**：低柜渠道归属/交易机构二分相关用例。
