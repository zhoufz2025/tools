# 基金代销标准份额明细：流程、参数与支持能力

> 梳理范围：GIT-IFM6.0 基金代销标准实现（核心节点 **T210839**）及下游保有量/报表链路。  
> 对照用途：评估青海银行等行需求时，先看本文件「标准已具备什么、默认怎么走」。  
> 梳理日期：20260915

---

## 1. 总体结论

标准已具备完整的「日终按 TA 确认拆分份额明细 → 汇总保有量 → 管理台报表查询」能力，**默认关闭**（不开调度、不配 `tbbusinorder *_SD`、关键参数为 0 时不按明细统计）。  
份额明细仅用于登记与报表统计，**不改变**正常申赎确认、入账、份额表主流程。

落地参考扩展包：

- `sql-dxfund/.../extradata/shareDetailHz/shareDetailHz.sql`
- `sql-dxfund/.../extradata/FloatManageFeeExt/FloatManageFee.sql`
- 银行样例：东莞 `dgyh`（调度 J210839、业务顺序 `_SD`、回溯 210840 等）


## 3. 份额明细拆分规则（标准）

### 3.1 驱动方式

- 数据源：当日确认备份表（`TransVar200007` 中的 `tbTransCfmBak`），`detail_flag=汇总`。
- 防重：`tbdxfundsharecfm` 已存在同 `ta_code+cfm_date+cfm_no` 且 status≠0 则跳过。
- 执行顺序：`tbbusinorder` 中 `ta_code = {TA}_SD`，`busin_code` 形如 `839122`（类名 `Action839122`）。

东莞样例顺序（节选）：120/122/130/139 增加类，124/126/128/135/138/142/145/150/151 扣减类，143 分红，990 续处理等。

### 3.2 增加类（一笔确认 → 一笔明细）

| 业务码 | Action | 行为 |
|--------|--------|------|
| 122 申购确认 | Action839122 | 新增明细，登记确认日/确认流水号 |
| 130 认购结果 | Action839130 | 同上 |
| 139 定投申购确认 | Action839139 | 同上 |
| 127 转托管入 | Action839127 | 同上 |
| 134 非交易过户入 | Action839134 | 同上 |
| 136/137 转换入（目标方） | Action839136/137 | 目标方增加 |
| 144 强增 | Action839144 | 同上 |
| 133 非交易过户（目标方） | Action839133 | 目标方增加 |

公共赋值：`PubFunction210839.updateConsignShareDtl`  

- 有确认：写 `cfm_date`、`cfm_no`、产品客户账号等；先落确认上的 `open_branch`/`branch_no`。  
- 有申请流水：覆盖 `open_branch`、`branch_no`、`channel`、`client_manager`、`entry_serial_no`。

### 3.3 红利再投 143（参数 `ShareDtl143Mode`）

| 参数值 | 行为 | 默认 |
|--------|------|------|
| **0** | 每次分红**新增**一条明细 | **代码默认** |
| **1** | 按现有明细份额**比例累加**到各条（`amt2` 记分红份额） | |
| **2** | **汇总为一条** `busin_code=143` 明细：首次新增，后续累加；`serial_no` 以 `zz` 开头，赎回优先级最低 | 扩展包常下发 **2** |

补充：

- `SHAREDTL143MODE_2_4=1`：模式 2 下货币产品可合并至原明细。  
- `T210839_143_CONCURRENT=1` 且笔数>1000：多线程处理。  
- 143 **默认不绑申请流水**：`channel` 空；机构取确认 `open_branch`/`branch_no`，否则根机构。

### 3.4 扣减类（FIFO）

| 业务码 | 说明 |
|--------|------|
| 124 赎回 | FIFO 释放；可按比例分摊浮动管理费到明细/`sharedtlmftmp` |
| 145 强减 | FIFO |
| 126/128 转托管出 | FIFO |
| 136/138 转换出（发起方） | FIFO |
| 133/135 非交易过户出 | FIFO |
| 142 强赎 | FIFO |
| 150 清盘 / 151 终止 | FIFO；不足时可强制清零剩余 |
| 163 定赎 / 198 快速过户 | 复用扣减逻辑 |

实现：`ConsignShareDtlService.releaseConsignShareDtl`  

- 排序：`order by serial_no asc`（注释：**先进先出**）。  
- **不是**按 `cfm_date + cfm_no` 排序（与部分行方文字描述略有差异；实务上 `serial_no` 与确认先后基本一致；模式 2 分红因 `zz` 前缀最后扣）。

### 3.5 其他业务

未在 `tbbusinorder *_SD` 配置的业务码**不做**份额明细处理。

## 4. 核心表与字段

| 表 | 用途 |
|----|------|
| `tbdxfundsharedtl1~N` | 当前份额明细（域对象 `ConsignShareDtl`） |
| `tbdxfundsharecfm1~N` | 增减留痕 |
| `tbdxfundhissharedtl1~N` | 清零归档历史 |
| `tbdxfundsharedtlmftmp` | 浮动管理费临时 |
| `tbdxfundhisfeyehz` / `*sync` | 标准保有量汇总 |
| `tbdxfundhisfeyedtlhz` / `*sync` | 按明细汇总的机构保有量（`FEYEHZ_BY_DTL=1`） |

明细关键字段：

| 字段 | 含义 |
|------|------|
| `serial_no` | 主键；FIFO 排序键 |
| `cfm_date` / `cfm_no` | 确认日 / 确认流水号 |
| `open_branch` | **归属机构**（保有量「开户/归属」维度多取此字段） |
| `branch_no` | **交易机构**（`sum_flag=0` 交易机构保有量取此字段） |
| `channel` | 交易渠道（有申请流水时写入） |
| `bank_acc` | 银行账号（换卡可更新） |
| `tot_vol` 及冻结字段 | 余额 |
| `busin_code` / `source_flag` | 业务来源 |

## 5. 归属机构 / 渠道登记（标准默认）

字段约定：明细 **`open_branch`=归属机构**，**`branch_no`=交易机构**，**`channel`=渠道**。  
公共赋值入口：`PubFunction210839.updateConsignShareDtl(明细, 确认, 申请流水可null)`。

### 5.1 赋值总顺序（增加类）

1. **确认非空**：先写入确认上的 `open_branch`、`branch_no`（以及客户/产品/确认日号等）。  
2. **申请流水非空**：再**覆盖**为流水的 `open_branch`、`branch_no`、`channel`、`client_manager`、`entry_serial_no`。  
3. **`SHARE_DTL_OPEN_BRANCH_MODE=1`**（部分增加类）：仅再覆盖 **`open_branch`**（客户经理链，见 5.3）；**不改** `branch_no`/`channel`。  
4. **无申请流水**的专用分支（见 5.2）：多数业务按「确认机构 → 否则根机构」落 `open_branch`+`branch_no`，`channel`/`entry_serial_no` 置空。

### 5.2 有申请流水 vs 无申请流水

| 情形 | `open_branch`（归属） | `branch_no`（交易机构） | `channel` | 典型业务 |
|------|----------------------|-------------------------|-----------|----------|
| **有申请流水**（默认模式 0） | 取流水 `open_branch` | 取流水 `branch_no` | 取流水 `channel` | 122/130/139 等（无流水通常直接报错中断） |
| **无申请流水**（允许缺流水） | 确认 `branch_no` 非空 → 用确认的 `open_branch`；否则用**机构树根节点** | 同上：确认 `branch_no` 或**根机构** | 置空 `' '` | 143 红利再投；134 非交易过户入；127/136/137/144 等「查不到流水」分支 |
| **无流水 + 模式 1** | 在上表基础上再覆盖为客户经理链结果（见 5.3）；链上也查不到时落到**账号开户机构** | **仍保持**确认/根机构，不因模式 1 改变 | 仍为空 | 127/134/137/144 等实现了模式 1 的 Action；**143 标准不走模式 1** |

补充说明：

- **强依赖流水的业务**（如 122 申购、130 认购、139 定投）：按确认 `serial_no` 取不到申请备份则抛 `ERR_TRANSCLEAR`，不存在「无流水仍落明细」的成功路径。  
- **可无流水的业务**（143/134；以及 127/137/144 等 else 分支）：`updateConsignShareDtl(..., null)` 后显式按确认/`BranchCache.getRoot()` 写机构，并 `entry_serial_no=' '`、`channel=' '`。  
- 144 强增：先按无流水规则用确认/根机构，**若随后查到流水**再覆盖为流水机构与渠道（与「有流水」一致）。  
- 扣减类（124 等）不新建归属，按 FIFO 改已有明细余额，机构字段沿用原明细。

### 5.3 `SHARE_DTL_OPEN_BRANCH_MODE`

| 模式 | 参数值 | 行为 |
|------|--------|------|
| 默认 | **0** | 不额外改归属；有流水跟流水，无流水跟确认/根机构（5.2） |
| 模式1 | **1** | 增加类落库前覆盖 `open_branch`：`queryClientManagerBranch` —— 流水客户经理所属机构 → 签约客户经理所属机构 → **银行账号开户机构**；`branch_no` 不变 |

注意：模式 1 是**客户经理所属机构链**，不是「一律取银行账号开户机构」。无流水时该方法往往跳过「流水客户经理」步，落到签约经理或开户机构。青海等行若要求有/无流水一律开户机构，需另配/改造（见改造方案）。

### 5.4 交易流水侧（影响确认汇总/部分保有量口径）

`BranchSetService.getAccBranch` + 系统参数 `OPEN_BRANCH`（至少 3 位）：

- 第 1 位：流水 `open_branch` —— `0` 理财账户归属机构（默认）；`1` 银行账号开户机构。  
- 实体渠道（`CHANNEL_TRANS_BRANCH` 包含的渠道）：`branch_no`=报文交易机构；非实体渠道：`branch_no`=`open_branch`。  
- 可挂个性化 `SetAccBranchImpl`（如北京银行 `BJYH_BRANCH_MODE`）。

有申请流水的明细在默认模式下**继承流水**的 `open_branch`/`branch_no`，故流水归属规则变化会传导到明细与「按开户机构」类报表；**无流水明细不读流水**，只跟确认机构字段或根机构（及可选模式 1）。

### 5.5 确认表上的 `open_branch` / `branch_no` 从哪来？

210839 无流水时读的「确认归属/交易机构」，**不是 TA 文件直接带的机构号**，而是日终 **T210104**（及分红 143）写进确认备份后再落到正式确认表。链路如下：

```
TA确认文件 → transcfmtmp/divdetailtmp（机构字段默认多为空格，T210103一般不补机构）
    → T210104 清算赋值 open_branch / branch_no
    → T210110 原样落入正式确认表（不重算机构）
    → T210839 无流水时按确认（或根机构）写明细
```

| 场景 | 确认 `open_branch` / `branch_no` 如何赋值 |
|------|------------------------------------------|
| **有申请流水**（122/130/139 等） | `Pub200104Service.transTransReqBakToCfmBak`：**两者均从申请流水覆盖**（流水本身由联机 `BranchSet` + `OPEN_BRANCH` 等决定） |
| **无申请流水的 TA 发起类**（如 **134**，以及走 `setTransCfmVal` 的同类） | `PubApiFactory.getTaTransBranch(...)`：**`open_branch` 与 `branch_no` 赋成同一值**。参数 **`BANK_BRANCH_SET`**：`0`（默认）→ 理财账户 `tbassetacc.open_branch`；`1` → 银行卡 `tbbankacc.open_branch`。若有在途机构撤并再替换为并入机构 |
| **143 红利再投**（分红明细路径） | 有份额：两者均取 **份额表 `tbdxfundshare.open_branch`**。无份额：看系统参数 **`OPEN_BRANCH` 第 2 位**——`1` 取银行卡开户机构，否则取理财账户开户机构；都取不到则可能仍为空格 |
| **参数 `T210104_CFM_OPEN_BRANCH`** | 配置业务码列表（如 142/144/145）时可强制确认 `open_branch`=银行卡开户机构；**标准不含 143/134** |
| **确认仍空** | 210839 判定确认 `branch_no` 为空 → 明细改用**机构树根节点**（见 5.2） |

要点：无流水场景下，确认上的「交易机构」与「归属机构」在标准实现里**经常被赋成同一个开户类机构**（理财账户或银行卡，取决于参数），并不区分联机那种「实体渠道交易机构 ≠ 归属机构」的二元结构。

## 6. 关键参数一览（默认值与含义）

| 参数 | 默认 | 含义 / 建议 |
|------|------|-------------|
| `ShareDtl143Mode` | **0** | 0逐条 / 1比例累加 / **2汇总一条**（分红累加场景建议 2） |
| `SHAREDTL143MODE_2_4` | 0 | 模式2下货币是否合并 |
| `SHARE_DTL_OPEN_BRANCH_MODE` | **0** | 0跟流水/无流水跟确认或根机构；1仅改归属为客户经理链（可落到开户机构） |
| `SHAREDTL_FEYEHZ` | **0** | 0份额表按归属；**1**明细按**交易机构**；**2**明细按**归属**；可 `01`/`12`；**禁止同时 0+2** |
| `FEYEHZ_BY_DTL` | **0** | 1=额外汇总到 `tbdxfundhisfeyedtlhz`（明细机构保有量报表） |
| `T210839_CLEAR_SHARE_DTL_MF_TMP` | **1** | 是否清理管理费临时表 |
| `T210839_DEAL_CHG_CARD` | 空 | 换卡需对齐的临时表名（逗号分隔） |
| `T210839_143_CONCURRENT` | 0 | 143 并发 |
| `SHARE_DTL_RE_CALC_ACTION` | 1 | 0旧/1新/2新2（东莞等多用 **2**） |
| `SHARE_DTL_RE_CALC_DATE` 等 | 空 | 回溯起始/销户表/底数标志 |
| `RED_CHARGE_BY_SHARE_DTL` | 0 | 110873 赎回试算是否按明细（浮动管理费常开 1） |
| `BYL_REPERT_ADD_CLIENT_TYPE` | 0 | 保有量报表是否加客户类型 |
| `DxFundShareDtlArchiving.days` | 配置，常见 -30 | 0 份额归档相对系统日偏移（1=当日可归档） |

字典 `K_HZFS`：`0`=交易机构，`1`=开户/归属机构（写入汇总表 `sum_flag`）。

## 7. 存量补算 / 换卡 / 归档

| 能力 | 节点/机制 | 说明 |
|------|-----------|------|
| 存量回溯 | **T210840**（交易片区）+ **T210841**（公共同步） | 按日回放 `businClear`；需配 `SHARE_DTL_RE_CALC_*`、起止日期；可从份额表灌底数 |
| 换卡更新明细账号 | `IChgCardWhiteEnum.TBDXFUNDSHAREDTL1_BANKACC` | 批量换卡白名单更新 `bank_acc` |
| 清算前旧卡对齐 | `T210839_DEAL_CHG_CARD` | 用当前份额表 `bank_acc` 刷临时确认表 |
| 清零归档 | **T210015** → `DxFundShareDtlArchiving` | `tot_vol=0` 且 `cfm_date < 归档日` → `tbdxfundhissharedtl` 后删当前表 |

上线首日全量回溯耗时长属预期（行方曾反馈约 300 万交易量约 5 小时量级，需压测与窗口规划）。

## 8. 报表与管理台（标准）

| 报表/菜单 | 数据源 | 机构维度 |
|-----------|--------|----------|
| 基金代销保有量统计 `ifmCDyglDxfundByltj*` | `tbdxfundhisfeyehz` | 默认 `sum_flag=1`（开户/归属）；可查 `sum_flag=0`（若汇总已生成） |
| 份额明细机构保有量 `ifmCDyglDxfundFemxByltj` | `tbdxfundhisfeyedtlhz` | 依赖 `FEYEHZ_BY_DTL=1`；默认 sum_flag=1 |
| 交易确认汇总等 | `tbdxfundhisqrhz` 等 | 跟确认/流水机构字段，非严格「明细归属专用」 |
| 份额明细对账差错 `ifmCDyglDxfundFemxdz` | 对账差错表 | 扩展包下发 |

说明：标准**没有**单独命名为「交易机构保有量报表」的菜单文案；数据能力上通过 `SHAREDTL_FEYEHZ` 含 `1` 或 `FEYEHZ_BY_DTL` + `sum_flag=0` 即可按交易机构出保有量。`FemxByltj` 后端已有，前端 Vue 需确认工程是否已挂路由页面。
