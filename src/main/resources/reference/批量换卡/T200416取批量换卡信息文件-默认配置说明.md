# T200416 取批量换卡信息文件 — 默认配置说明

> 源码：`T200416HSAdapter`（Bean：`TPUB200416HSAdapter`）  
> 职责：从主机/文件服务器拉取批量换卡文件到本地 `{IFMBASEPATH}/detail`。  
> 默认模式：**只取文件，不解析入库**（入库与拆单由后续 `PUB200417` 完成）。

---

## 一、默认正常执行流程

```mermaid
flowchart LR
  A["调度 J200416T01"] --> B["PUB200416"]
  B --> C["拼文件名 cardinfo.{initDate}"]
  C --> D["SFTP/FTP 按 HOSTFILE 取文件"]
  D --> E["校验本地文件存在"]
  E --> F["结束（不入库）"]
```

| 步骤 | 方法 | 默认行为 |
|------|------|----------|
| 1 | `transRequest` | 文件名=`cardinfo.{sysArg.initDate}`；本地路径=`{IFMBASEPATH}/detail`；不取 `.ok` |
| 2 | `getHostFile` → `receiveFile` | 使用配置段 `HOSTFILE` 从远端拉取该文件 |
| 3 | 本地存在性校验 | 文件不存在则报错 `换卡文件不存在` |
| 4 | 入库判断 | 参数默认「由 417 处理」，本节点跳过 `dealTbbatchgcard` |

成功标志：批量日志出现「取批量换卡信息文件结束」，且本地已有对应换卡文件。

## 二、默认必配项（不开扩展也能跑通）

### 2.1 调度与交易

| 配置 | 默认/要求 |
|------|-----------|
| Job | `J200416`（父节点现场按日终链挂接，基线示例父节点 `J200016`） |
| Task | `J200416T01`，`function_id=PUB200416` |
| Registry | 指向实际承载 pub-batch 的服务（基金例：`lcpt-dxfund-pub-batch` + `/dxfund/pub/batch`） |
| `tbtrans` | `trans_code=200416`，`enable_flag=1`，`trans_type=4` |
| Spring Bean | `@Service("TPUB200416HSAdapter")` 已部署在对应 pub-batch |

### 2.2 应用配置（pub-batch 的 application / 配置中心）

| 配置项 | 默认作用 | 说明 |
|--------|----------|------|
| `lcpt.config.IFMBASEPATH` | 本地基路径 | 落地目录 `{IFMBASEPATH}/detail`，须可写 |
| `lcpt.config.HOSTFILE.HostCheckPath` | 远端目录 | **必填**；可含 `YYYYMMDD`，默认按系统日期 `initDate` 替换 |
| `lcpt.config.HOSTFILE.ServerIP` | 文件服务器 IP | **必填** |
| `lcpt.config.HOSTFILE.Port` | 端口 | 如 SFTP 22 |
| `lcpt.config.HOSTFILE.UserID` / `Password` | 账号密码 | 按传输方式配置 |
| `lcpt.config.HOSTFILE.TransferWay` | 传输方式 | 模板常见 `SFTP` |

示例：

```properties
lcpt.config.IFMBASEPATH=/home/ifm60/dxfund/pub-area0
lcpt.config.HOSTFILE.HostCheckPath=/path/to/host/chgcard/YYYYMMDD
lcpt.config.HOSTFILE.ServerIP=x.x.x.x
lcpt.config.HOSTFILE.Port=22
lcpt.config.HOSTFILE.UserID=xxx
lcpt.config.HOSTFILE.Password=xxx
lcpt.config.HOSTFILE.TransferWay=SFTP
```

### 2.3 默认参数取值（代码内 default，未显式下发时生效）

| 参数 ID | 默认值 | 默认含义 |
|---------|--------|----------|
| `T200416_FILE` | `HOSTFILE` | 取文件走 `HOSTFILE` 配置段 |
| `PLHK_USE_PHYDATE` | `0` | 文件名日期用 **系统清算日** `sysArg.initDate` → `cardinfo.{initDate}` |
| `GET_FILE_PHYDATE` | `0` | 远端路径中 `YYYYMMDD` 用 **initDate** 替换 |
| `T200416_GETOKFILE` | `0` | **不**同时下载/校验 `.ok` 索引文件 |
| `T200416_NOTWARN_WITHNOFILE` | `0` | 无文件（或文件名为空）时 **仍按失败处理**（抛业务异常） |
| `T200416_OR_T200417_DEAL_TBBATCHCHGCARE` | `1` | **417** 负责解析写入 `tbbatchchgcard`；416 只取文件 |
| `CARD_CHANGE_FILE`（SysConfig） | 空 | 未配置时使用默认名 `cardinfo.{日期}` |
| 个性化 Bean | 不存在 | 走标准 `getHostFile` / `receiveFile`，不走银行个性化取数 |

默认文件落地路径示例：

```text
{IFMBASEPATH}/detail/cardinfo.20260809
```

## 三、未开启参数说明（可选开启）

以下参数默认关闭或取“标准模式”值；开启后会改变 416 行为，按需下发。

### 3.1 文件名 / 路径日期

| 参数 | 取值 | 作用 |
|------|------|------|
| `PLHK_USE_PHYDATE` | `0`（默认） | `cardinfo.{initDate}` |
| | `1` | `cardinfo.{物理日期 DateUtil.getSysDate()}` |
| | `2` | `cardinfo.{物理日期-1}` |
| | `3` | `cardinfo.{sysArg.prevDate}`（前一系统日） |
| `GET_FILE_PHYDATE` | `0`（默认） | `HostCheckPath` 中 `YYYYMMDD` → initDate |
| | `1` | → 物理日期 |
| | `2` | → 物理日期-1 |
| `CARD_CHANGE_FILE` | 非空模板 | 覆盖默认文件名，支持 `YYYYMMDD` 占位，如 `PLHK_YYYYMMDD.txt` |
| `T200416_FILE` | 非 `HOSTFILE` | 改用其它 SysConfig 段名（须同步配置 `lcpt.config.{段名}.*`） |
| Context `HostFilePath` | 有值 | 运行时覆盖 `HostCheckPath`（仍做 `YYYYMMDD` 替换） |

### 3.2 取文件策略

| 参数 | 默认 | 开启（常见置 `1`）后的作用 |
|------|------|---------------------------|
| `T200416_GETOKFILE` | `0` | 同时拉取「同主名 `.ok`」；本地数据文件与 `.ok` 都必须存在，否则报「换卡索引文件不存在」 |
| `T200416_NOTWARN_WITHNOFILE` | `0` | 当主机文件名为空时直接 return 成功，不告警（配合某些核心无文件场景） |

### 3.3 入库时机（与 417 分工）

| 参数 | 默认 `1` | 置 `0` 时 |
|------|----------|-----------|
| `T200416_OR_T200417_DEAL_TBBATCHCHGCARE` | 416 只取文件，417 解析入库 | **416 内**执行 `dealTbbatchgcard`：读本地文件 → `tbbatchchgcardtmp` → 预处理 → 写入 `tbbatchchgcard` |

置 `0` 时，416 还会用到（多数默认仍偏“标准入库逻辑”）：

| 参数 | 默认 | 作用 |
|------|------|------|
| `FUND_200417FILESPLIT` | 空 | 有值则行分隔符为 `\|@\|`，否则 `\|` |
| `T200417_TARG_BANKACC_FIRST` | `0` | `1`=文件中新卡号在前、旧卡在后 |
| `200417DELERROLDBKACC`（`T200417DELERROLDBANKACC`） | `1` | 是否按规则处理旧卡不存在/状态异常记录 |
| `FAIL_CHGCARD_REDO` | `0` | `1` 时重导历史失败换卡流水 |
| `COMMIT_COUNT` | `2000` | 批量提交笔数 |
| `IFMS_MUTI_BANK` | `0` | 多法人时按法人循环处理 |

### 3.4 从核心缓存文件名

| 参数 | 默认 | 作用 |
|------|------|------|
| `T200416_CHANGE_CARD_FILENAME` | 一般无有效值 | 由 `ChangeCardFileGetHostService` 等写入；格式约 `{initDate}%#%{文件名}`。在 416 兼做入库路径的 `setHostFileName` 中读取；日期不匹配会报「未从核心获取到当天的换卡文件」 |

## 四、未注册个性化接口说明（默认不开启）

标准运行时 **不注册** 下列 Bean；注册后会替换或增强取文件逻辑。

### 4.1 `ChangeCardFileService`（`IChangeCardFileService`）

| 方法 | 何时调用 | 作用 |
|------|----------|------|
| `getHostFileName` | `transRequest` 中 Bean 存在时 | 个性化改写主机文件名 |
| `getHostFile` | `action` 中 Bean 存在时 | **整段替代**标准 `getHostFile`/`receiveFile`（SFTP 不再走默认） |
| `getLocalFileName` | 416 兼入库时的 `transRequest1` | 对齐本地读取路径（与 417 一致） |
| `loadChgCardInfoFile` | 416 兼入库且 Bean 存在 | 个性化解析导入临时表 |
| `batchChgCard` | 接口预留 | 个性化批量换卡扩展（416 主流程默认不调） |

典型使用：银行文件命名/传输方式与标准 HOSTFILE 不一致、ECIF 对接等。

### 4.2 `ChangeCardFileGetHostService`（`IChangeCardFileGetHostService`）

| 方法 | 何时调用 | 作用 |
|------|----------|------|
| `getHostFileName` | `getHostFileNameByImp` | 向主机/核心查询真实换卡文件名；返回非 null 则覆盖 `transVar.hostFileName` |

与 `T200416_CHANGE_CARD_FILENAME` 常配合：先问核心要文件名，再按该名取文件。

## 五、默认成功检查清单

1. 调度能路由到 pub-batch，且加载 `TPUB200416HSAdapter`。
2. `{IFMBASEPATH}/detail` 存在且可写。
3. `HOSTFILE`（或 `T200416_FILE` 指向段）的 IP/路径/账号齐全。
4. 远端存在默认规则文件：`cardinfo.{initDate}`（或已配 `CARD_CHANGE_FILE`）。
5. 传输完成后本地文件存在。
6. **未**误开 `T200416_GETOKFILE`（若开了则远端须有同名 `.ok`）。
7. 日志有「取批量换卡信息文件结束」。

常见失败对照：

| 现象 | 排查 |
|------|------|
| `主机文件路径ServerPath未配置` | 补 `lcpt.config.HOSTFILE.HostCheckPath` |
| `换卡文件不存在：.../detail/xxx` | 远端无文件、日期规则不符、传输失败 |
| `换卡索引文件不存在：*.ok` | 开了 `T200416_GETOKFILE` 但无 ok 文件 |
| 调度找不到服务 | Registry 的 `app_name`/`app_url` 与实际微服务不一致 |

## 六、与 417 的边界（默认）

| 节点 | 默认职责 |
|------|----------|
| **200416** | 取主机换卡文件到本地 |
| **200417** | 解析文件、写 `tbbatchchgcard`、拆单调联机换卡（如 `100003`） |

仅当 `T200416_OR_T200417_DEAL_TBBATCHCHGCARE=0` 时，入库前移到 416；否则保持「416 取文件 → 417 处理」标准链。
