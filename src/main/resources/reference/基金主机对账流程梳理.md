# 基金业务主机对账流程分析

## 一、需求背景

### 1.1 业务背景

在基金代销业务中，基金销售系统（IFMS）与银行核心系统（主机）是两个独立的系统，客户的基金交易涉及资金的划转，需要在两个系统之间进行账务处理：

1. **销售系统**：负责基金业务逻辑处理（开户、购买、赎回、分红等）
2. **主机系统**：负责资金账务处理（冻结、扣款、入账等）

由于两个系统独立运行，可能存在以下问题：
- **数据不一致**：销售系统记录的交易与主机系统记录的资金流水可能不一致
- **账务差异**：销售系统认为已扣款的交易，主机系统可能未扣款成功
- **流水遗漏**：某些交易在一方系统有记录，另一方系统无记录
- **金额不符**：同一笔交易在两个系统记录的金额不一致

### 1.2 监管与风险要求

根据监管要求和风险控制需要：

1. **资金安全**：
   - 确保客户资金安全，防止资金损失
   - 及时发现资金划转异常，避免资金风险

2. **账务准确**：
   - 保证销售系统与主机系统账务一致
   - 确保客户账户余额准确无误

3. **合规要求**：
   - 满足监管机构对账务核对的要求
   - 提供完整的账务对账记录和审计轨迹

4. **运营管理**：
   - 及时发现系统异常和业务问题
   - 为日终结算提供依据

### 1.3 主机对账的作用

主机对账是通过比对销售系统和主机系统的交易流水，发现并处理两个系统之间的账务差异：

**1. 数据一致性校验**
- **销售商有主机无**：销售系统有交易记录，但主机系统未找到对应的资金流水
  - 可能原因：主机扣款失败、主机未收到请求、网络超时等
  - 处理方式：重新发送主机交易或撤销销售端流水

- **主机有销售商无**：主机系统有资金流水，但销售系统未找到对应的交易记录
  - 可能原因：销售系统未入账、销售系统异常、数据同步失败等
  - 处理方式：补录销售端流水或退款处理

- **销售商与主机不平**：两个系统都有记录，但关键信息不一致
  - 金额不平：可能是手续费计算错误、金额录入错误等
  - 账号不平：可能是换卡、账号变更等
  - 币种不平：可能是币种设置错误等
  - 处理方式：根据具体情况调账或补账

**2. 业务异常发现**
- **交易状态异常**：发现挂起、超时、失败的交易
- **账务状态异常**：发现冻结未扣款、扣款未入账等异常状态
- **系统通信异常**：发现主机通信故障、网络超时等问题

**3. 风险控制**
- **资金风险**：防止资金多扣、少扣、重复扣款等
- **业务风险**：防止客户份额与资金不匹配
- **系统风险**：及时发现系统故障和数据错误

### 1.4 对账时机

主机对账通常在**日终批量处理**时执行，具体时机：

1. **当日对账**（`CHECK_DATE=0`）：
   - 对账当日（T日）的交易
   - 适用于当日交易当日结算的场景
   - 要求主机当日提供对账文件

2. **隔日对账**（`CHECK_DATE=1`，默认）：
   - 对账前一日（T-1日）的交易
   - 适用于主机隔日提供对账文件的场景
   - 给主机系统留出充足的账务处理时间

### 1.5 对账流程的必要性

主机对账是基金销售业务日终处理的**必备环节**：

1. **前置条件**：
   - 对账成功是日终批量处理继续进行的前提
   - 对账不平会阻止后续的TA申请文件导出等操作

2. **后续影响**：
   - 对账结果直接影响客户份额确认
   - 对账不平需要及时处理，否则影响客户体验
   - 长期对账不平会累积业务风险

3. **系统可靠性**：
   - 通过每日对账确保系统数据准确性
   - 及时发现和修复系统问题
   - 为系统稳定运行提供保障

### 1.6 对账结果处理

对账完成后，根据对账结果进行不同处理：

**1. 对账成功**（`NoAccFailNum = 0`）：
- 表示销售系统与主机系统账务一致
- 可以继续后续的日终批量处理
- 正常进入TA申请文件导出等流程

**2. 对账失败**（`NoAccFailNum > 0`）：
- 产生对账差错记录（`tbdxfundbkcompdetail`）
- 需要人工核查对账不平原因
- 根据不平类型进行相应处理：
  - **销售商有主机无**：检查主机交易是否失败，考虑重新发送或撤销
  - **主机有销售商无**：检查销售端是否有遗漏，考虑补录或退款
  - **金额不平**：核查手续费、金额计算是否正确，进行调账
  - **账号不平**：确认是否换卡等情况（账号不平可能不影响对账成功）

**3. 特殊处理**：
- **换卡场景**（`CardChgHostCheckDiff=1`）：账号不平不影响对账成功
- **实时赎回**（`CHKREALREDFLAG=1`）：对账不平自动更新流水状态为失败
- **对账豁免**：某些交易可配置不参与对账（`NOCHECK_TRANS_CODE`）

### 1.7 业务价值总结

主机对账为基金销售业务提供了重要的价值：

1. **保障资金安全**：确保客户资金准确无误
2. **提高数据质量**：及时发现和纠正数据错误
3. **满足监管要求**：提供完整的账务核对记录
4. **支持运营管理**：为业务决策提供准确数据
5. **降低业务风险**：防止账务差异累积造成重大损失
6. **提升客户体验**：确保客户账户信息准确，避免纠纷

## 二、流程概述

基金业务主机对账流程分为两个阶段：
1. **公共片区（PUB）处理**：获取主机对账文件，格式化并拆分到各交易片区
2. **交易片区（TRANS）处理**：获取拆分后的文件，导入对账表，执行对账处理

## 三、流程图

```
主机对账
    ↓
[公共片区] 取主机对账文件子流程 (T210210-PUB)
    ├─ 获取主机文件名和路径
    ├─ 获取文件到本地
    ├─ 格式化为标准主机对账文件
    └─ 文件拆分（发送不同交易片区）
    ↓
[交易片区] 取拆分的主机对账文件子流程 (T210210-TRANS)
    ├─ 获取文件到本地
    ├─ 清空对账表
    └─ 将文件导入对账表
    ↓
[交易片区] 交易片区与主机对账子流程 (T210201)
    ├─ 数据预处理
    ├─ 数据校验
    ├─ 本地对账处理
    └─ 导出对账结果
```

## 四、详细流程分析

### 4.1 公共片区处理流程（T210210-PUB）

**位置**：`lcpt-dxfund-pub-batch-bootstrap/src/main/java/com/hundsun/lcpt/dxfund/pub/batch/adapter/T210210/T210210HSAdapter.java`

#### 4.1.1 获取主机文件名和路径

**通用标准实现**：
- 根据参数 `CHECK_HOST_BY_TA` 判断是否分TA对账
- 根据参数 `CHECK_DATE` 判断对账日期（0-当日，1-隔日）
- 根据参数 `HOST_FILE_NAME_MODE` 判断文件名格式
- 文件名规则：
  - 分TA模式：`bkdetail_{taCode}_{bankNo}.{version}.{date}` 或 `bkdetail_{taCode}_{bankNo}.{date}`
  - 不分TA模式：`bkdetail_{bankNo}.{version}.{date}` 或 `bkdetail_{bankNo}.{date}`
- 本地路径：`{IFMBASEPATH}/detail`

**可个性化点**：
- ✅ **文件名格式**：可通过参数 `HOST_FILE_NAME_MODE` 控制
- ✅ **文件路径**：可通过配置 `210210.LocalPath` 个性化
- ✅ **获取文件方式**：可通过实现 `IGetHostFileService` 接口个性化（见3.1.2）

#### 4.1.2 获取文件到本地

**通用标准实现**：
- 默认实现：不获取远程文件（`getHostFile` 方法为空实现）
- 通过内部文件传输机制获取文件（`GenericFileTransferUtil.receiveFile`）
- 文件路径：`{localPath}/{hostFileName}_{areaId}`

**可个性化点**：
- ✅ **文件获取方式**：可通过实现 `IGetHostFileService` 接口完全个性化
  - 接口位置：`com.hundsun.lcpt.pub.services.interfaces.IGetHostFileService`
  - Bean名称：`T210210_GetHostFileService`
  - 个性化示例：
    - `Szyh210210GetHostFileServiceImpl`（苏州银行）
    - `Shnsh210210GetHostFileServiceImpl`（上海农商）
    - `MTSH210210GetHostFileService`（民泰银行）
    - `Hbyh210210GetHostFileServiceImpl`（河北银行）
    - 等等

#### 4.1.3 格式化为标准主机对账文件

**通用标准实现**：
- 如果配置了 `IGetHostFileService`，格式化逻辑在个性化服务中实现
- 标准文件格式：管道符分隔（`|`），UTF-8编码
- 文件字段顺序：
  ```
  trans_date|to_host_serial|host_serial|host_trans_code|amt|curr_type|bank_acc|status|liqu_dir|amt2|cash_flag|reserve1
  ```

**可个性化点**：
- ✅ **文件格式转换**：在 `IGetHostFileService.getHostFile()` 方法中实现
- ✅ **文件编码**：可通过个性化服务控制
- ✅ **字段映射**：可通过个性化服务调整字段顺序和内容

#### 4.1.4 文件拆分（发送不同交易片区）

**通用标准实现**：
- 方法：`splitAreaFile(IContext context, TransVar210210 transVar)`
- 拆分逻辑：
  1. 读取主机对账文件，逐行处理
  2. 根据银行账号（`bank_acc`）查询内部客户号（`in_client_no`）
     - 优先从 `tbclientmap` 查询
     - 如果查不到，从 `tbaccreq` 或 `tbhisaccreq` 查询（交易码='100003'）
  3. 根据内部客户号计算交易片区ID：`ShardingUtil.getAreaId(inClientNo, CPLX_FUND)`
  4. 将记录写入对应片区的文件：`{hostFileName}_{areaId}`
  5. 通过 `DfsPubBatchInnerFileTransferUtil.sendFile` 发送到分布式文件服务器

**可个性化点**：
- ✅ **内部客户号查询逻辑**：可通过参数 `T210210_IGNORE_PRDBANKACC` 控制是否忽略内部户
- ✅ **文件拆分目录**：可通过参数 `T210210_TRANS_AREA_PATH` 个性化交易片区文件目录（V6.0.0.5新增）
- ✅ **过滤逻辑**：
  - 可通过参数 `HOSTCHECK_EXCLUDE_AUTOTRANSFER_DATA` 过滤资金划拨数据
  - 可通过参数 `AUTOTRANSFER_CHECK_SERIAL` 控制对账流水号字段

**个性化示例**：
- 某些银行可能需要特殊的客户号查询逻辑
- 某些银行可能需要过滤特定的交易类型

### 4.2 交易片区处理流程（T210210-TRANS）

**位置**：`lcpt-dxfund-trans-batch-bootstrap/src/main/java/com/hundsun/lcpt/dxfund/batch/adapter/T210210/T210210HSAdapter.java`

#### 4.2.1 获取文件到本地

**通用标准实现**：
- 从分布式文件服务器获取拆分后的文件
- 文件名：`{hostFileName}_{currentAreaId}`
- 文件路径：通过 `ResourceUtil.getInnerFileLocalPath(InnerFileType.SQUARE)` 获取

**可个性化点**：
- ✅ **文件获取路径**：可通过配置个性化
- ✅ **文件获取方式**：可通过实现个性化服务扩展

#### 4.2.2 清空对账表

**通用标准实现**：
- 对账表名：
  - 分TA模式：`tbdxfundbkcomp_{taCode}_{bankNo}`
  - 不分TA模式：`tbdxfundbkcomp`
- 清空方式：
  - 分TA模式：删除表后重建（临时表模式）或 `TRUNCATE`（正式表模式）
  - 不分TA模式：根据 `bank_no` 删除数据

**可个性化点**：
- ✅ **表名规则**：通过参数 `CHECK_HOST_BY_TA` 控制
- ✅ **清空方式**：通过参数 `CREATE_TEMP_TABLE` 控制（0-正式表，1-临时表）
- ✅ **清空后更新**：可通过实现 `IDxFundUpdateCompService` 接口个性化更新对账表数据
  - Bean名称：`DxFundUpdateCompService`
  - 方法：`updateComp(IContext context, String tableName)`

#### 4.2.3 导入对账文件到对账表

**通用标准实现**：
- 读取文件，按管道符分隔解析字段
- 字段映射：
  ```
  trans_date (0) → trans_date
  to_host_serial (1) → to_host_serial
  host_serial (2) → host_serial（可能组合日期）
  host_trans_code (3) → host_trans_code
  amt (4) → amt
  curr_type (5) → curr_type
  bank_acc (6) → bank_acc
  status (7) → status
  liqu_dir (8) → liqu_dir
  amt2 (9) → amt2
  cash_flag (10) → cash_flag
  reserve1 (11) → reserve1
  ```
- 批量插入，每2000条提交一次（可通过参数 `COMMIT_COUNT` 配置）

**`host_serial` 和 `to_host_serial` 字段说明**：

**1. `to_host_serial`（发送主机流水号）字段**：
- **字段含义**：系统发送给主机的流水号，用于标识该笔交易请求
- **数据来源**：
  1. **生成时机**：在发送主机交易请求时生成
  2. **生成方式**：
     - 通过序列号生成器生成：`DxFundSequenceFactory.getSequence().getSerialNo()`
     - 或使用流水表的 `serial_no` 字段
     - 或使用流水表的 `ex_serial` 字段
  3. **保存位置**：
     - 保存到流水表（`tbdxfundtransreq`、`tbdxfundhistransreq`、`tbdxfundbatchreq`）的 `to_host_serial` 字段
     - 在发送主机请求时，通过 `hostRequest.setToHostSerial()` 设置
  4. **对账文件来源**：
     - 主机对账文件的第二字段（索引1）
     - 代码位置：`T210210HSAdapter.java` 的 `LoadTransResultFile()` 方法
     - 代码示例：`paramList.add(getString(fieldValue, 1, " "));`
- **字段格式**：字符串类型，通常为数字字符串
- **对账用途**：
  - 当参数 `CHECK_SERIAL='1'` 时，使用 `to_host_serial` 作为对账流水号
  - 用于匹配系统发送的流水号与主机返回的流水号

**2. `host_serial`（主机流水号）字段**：
- **字段含义**：主机返回的流水号，用于标识主机处理该笔交易的流水号
- **数据来源**：
  1. **主要来源**：主机交易响应中的 `ITag.HostSerial` 字段
  2. **获取时机**：
     - 在交易处理流程中，当收到主机响应后，通过 `transVar.setHostSerial(hostEvent.getString(ITag.HostSerial))` 设置
     - 然后更新到流水表（`tbdxfundtransreq`、`tbdxfundhistransreq`、`tbdxfundbatchreq`）的 `host_serial` 字段
     - 示例代码位置：`T110500HSAdapter.java` 的 `toHost()` 方法中
  3. **对账文件来源**：
     - 主机对账文件的第三字段（索引2）
     - 代码位置：`T210210HSAdapter.java` 的 `LoadTransResultFile()` 方法
     - 代码示例：`paramList.add(getString(fieldValue, 2, " "));`
  4. **特殊处理**：
     - 如果参数 `HOSTSERIALUNIQUE=NO` 且 `CHECK_SERIAL=0`，则组合日期和流水号：
       - `host_serial = trans_date + host_serial`
       - 代码示例：`paramList.add(getString(fieldValue, 0, "0")+getString(fieldValue, 2, " "));`
- **字段格式**：字符串类型，通常为数字字符串
- **对账用途**：
  - 当参数 `CHECK_SERIAL='0'` 时（默认），使用 `host_serial` 作为对账流水号
  - 用于匹配系统记录的主机流水号与主机对账文件中的流水号

**3. 对账流水号选择**：
- **参数控制**：`CHECK_SERIAL` 参数控制使用哪个字段作为对账流水号
  - `CHECK_SERIAL='0'`（默认）：使用 `host_serial` 对账
  - `CHECK_SERIAL='1'`：使用 `to_host_serial` 对账
- **匹配逻辑**：
  - 从本地记录表（`tbdxfundbkcomplocal`）中选择对账流水号字段（`checkSerial`）
  - 与主机对账文件表（`tbdxfundbkcomp`）中对应的字段进行匹配
  - 匹配条件：`tbdxfundbkcomplocal.checkSerial = tbdxfundbkcomp.checkSerial`

**`trans_date` 字段说明**：
- **字段含义**：主机对账文件中的交易日期，表示主机记录的该笔交易的日期
- **数据来源**：
  1. **主要来源**：主机对账文件的第一字段（索引0）
     - 主机对账文件格式：管道符（`|`）分隔的文本文件
     - 第一字段（`fieldValue[0]`）为交易日期
     - 代码位置：`T210210HSAdapter.java` 的 `LoadTransResultFile()` 方法
     - 代码示例：`paramList.add(Integer.valueOf(getString(fieldValue, 0, "0")));`
  2. **文件格式**：
     - 文件格式：`trans_date|to_host_serial|host_serial|host_trans_code|amt|curr_type|bank_acc|status|liqu_dir|amt2|cash_flag|reserve1`
     - 第一字段 `trans_date` 为主机记录的交易日期
  3. **字段格式**：整数类型（如：`20240101`），表示YYYYMMDD格式的日期
- **对账用途**：
  - 当参数 `CheckByHostDate='1'` 时，对账需要匹配 `host_date = trans_date`
  - 用于确保主机对账文件中的交易日期与流水表中的主机日期一致
  - 匹配条件：`tbdxfundbkcomplocal.host_date = tbdxfundbkcomp.trans_date`

**可个性化点**：
- ✅ **主机流水号处理**：
  - 参数 `HOSTSERIALUNIQUE`：控制主机流水号是否唯一
  - 参数 `CHECK_SERIAL`：控制对账流水号字段（0-host_serial，1-to_host_serial）
  - 如果 `HOSTSERIALUNIQUE=NO` 且 `CHECK_SERIAL=0`，则组合日期和流水号
- ✅ **法人行编号更新**：
  - 参数 `ISUPDCOMPBNAKNO`：控制是否更新对账表中的法人行编号
  - 默认从 `tbdxfundtransreq`、`tbdxfundhistransreq`、`tbdxfundbatchreq` 更新

### 4.3 交易片区与主机对账流程（T210201）

**位置**：`lcpt-dxfund-trans-batch-bootstrap/src/main/java/com/hundsun/lcpt/dxfund/batch/adapter/T210201/T210201HSAdapter.java`

#### 4.3.1 数据预处理

**通用标准实现**：
- 初始化对账参数：
  - `CHECK_HOST_BY_TA`：是否分TA对账
  - `CHECK_DATE`：对账日期模式（0-当日，1-隔日）
  - `CHECK_RECORD`：对账记录类型（4位：撤单|抹账|被撤单|被抹账）
  - `CHECK_SERIAL`：对账流水号字段
  - `CHECK_BANKACC`：是否核对银行账号
  - `CHECK_MODE`：对账模式（0-本地对账，1-非本地对账）
  - `CHECK_DETAIL_ONCE`：对账不符记录是否只核对一次
  - `CANCLE_OVER_TIME`：是否支持撤单超时后继续撤单
  - `CHKREALREDFLAG`：是否校验实时赎回数据
  - `CheckByHostDate`：是否根据host_date对账
  - `CheckByTransAccount`：是否根据交易账号对账

**可个性化点**：
- ✅ **所有对账参数**：均可通过系统参数配置个性化
- ✅ **参数优先级**：某些参数支持基金级参数（如 `CHECK_SERIAL`）

#### 4.3.2 数据校验

**通用标准实现**：
- 检查是否有待冲正流水（`tbdxfundrepeal` 表中 `repeal_status='0'`）
- 如果有待冲正流水：
  - 参数 `T210201_WARNFLAG` 控制行为：
    - `NO`：抛出异常，中断跑批
    - `YES`：仅提示警告，不中断跑批

**可个性化点**：
- ✅ **校验逻辑**：可通过参数 `T210201_WARNFLAG` 控制
- ✅ **警告信息**：可通过个性化服务扩展

#### 4.3.3 本地对账处理

**通用标准实现**：

本地对账处理是主机对账的核心环节，通过比较主机对账文件数据和本地交易流水数据，找出对账不平的记录。

##### 步骤1：准备对账数据

**1.1 确定参与对账的交易状态**
- 默认参与对账的交易状态包括：
  - `'0'`：预处理
  - `'1'`：处理中
  - `'2'`：已导出
  - `'S'`：确认成功
  - `'P'`：部分完成
  - `'F'`：确认失败
  - `'3'`：已入账
  - `'4'`：认购确认
- 根据 `CHECK_RECORD` 参数，可能还包括：
  - 撤单流水（`CHECK_RECORD[0]='1'`）：状态 `'S'`（成功）
  - 被撤单流水（`CHECK_RECORD[2]='1'`）：状态 `'2'`（已撤单）
  - 被抹账流水（`CHECK_RECORD[3]='1'`）：状态 `'3'`（已抹账）

**1.2 确定参与对账的账务状态**

- **余额宝产品过滤**：

  - 如果为0，过滤货币型产品（`CurrencyPrdMode='1'`）
- **组合宝产品过滤**：
  - 通过 `DxFundGrpTypeUtil.isYebZh()` 判断是否存在组合宝业务
  - 如果存在，组合宝对账数据通过 `insertBkCompLocalFromZhb()` 单独处理
  - 参数 `ZHB_NOCHECK_TRANS_CODE`：组合宝产品不参与对账的交易码
- **智能投顾过滤**：
  - 参数 `ZNTG_HXKKMS`（0-参与，1-不参与，默认0）
  - 如果为1，过滤控制位29位为'0'或'1'的流水
- **控制位过滤**：
  - 过滤控制位72位为'1'的流水（不参与对账）
  - 过滤控制位62位为'1'的子流水（组合宝子流水）

**1.4 获取产品列表**
- 调用 `PubDxFundApiFactory.getQueryPrdList(filterMap)` 获取参与对账的产品列表
- 产品列表用于后续按产品并发处理对账数据

##### 步骤2：删除历史对账数据

**2.1 删除对账差错表数据**（`deleteBkCompDetail()`）
- 表名：`tbdxfundbkcompdetail`
- 删除条件：
  - `trans_date = 对账日期`
  - 如果分TA对账：`ta_code = TA代码`
  - 如果分法人行对账：`bank_no = 银行编号`
- 目的：清空上次对账的差错记录，准备本次对账结果

**2.2 删除本地记录表数据**（`deleteBkCompLocal()`）
- 表名：`tbdxfundbkcomplocal`
- 删除条件：
  - 如果分TA对账：`ta_code = TA代码`
  - 如果分法人行对账：`bank_no = 银行编号`
  - 如果不分法人行：删除全部数据
- 支持并发删除（参数 `BatchExecuteSplit` 控制）
- 目的：清空上次对账的本地记录，准备本次对账数据

**2.3 删除文件导入表不参与对账数据**（`deleteBkComp()`）
- 表名：`tbdxfundbkcomp`（主机对账文件导入表）
- 删除条件：
  - 如果 `CHECK_RECORD[2]='0'`（不核对被撤单流水）：
    - 删除被撤单的流水（`status='2'` 或 `status='3'`）
    - 排除组合宝子流水（控制位62位='1'）
  - 如果 `CHECK_RECORD[3]='0'`（不核对被抹账流水）：
    - 删除被抹账的流水（`status='3'`）
- 目的：从主机对账文件中删除不参与对账的记录

##### 步骤3：插入本地对账数据

**3.1 从当前流水表插入**（`insertBkCompLocal()`）
- **数据源**：`tbdxfundtransreq{1-16}`（分表）
- **插入方式**：
  - 使用线程池并发处理（参数 `HOSTCHCK_THREADNUM` 控制线程数，默认5）
  - 按产品列表并发插入，每个产品一个任务
  - 支持批量执行拆分（参数 `BatchExecuteSplit` 控制）
- **插入字段映射**：
  ```
  trans_date → trans_date（交易日期）
  serial_no → serial_no（流水号）
  to_host_serial → to_host_serial（发送主机流水号）
  status → status（交易状态）
  ta_code → ta_code（TA代码）
  in_client_no → in_client_no（内部客户号）
  client_no → client_no（客户编号）
  bank_no → bank_no（法人行编号）
  client_type → client_type（客户类型）
  bank_acc/trans_account → bank_acc（银行账号，根据CheckByTransAccount参数选择）
  branch_no → branch_no（机构号）
  curr_type → curr_type（币种）
  amt → amt（金额，特殊交易码需要加手续费）
  liqu_status → liqu_status（账务状态）
  host_date → host_date（主机日期）
  host_trans_code → host_trans_code（主机交易代码）
  host_serial → host_serial（主机流水号，可能组合日期）
  to_host_serial → to_host_serial（发送主机流水号）
  debit_account → debit_account（借方账号）
  amt2 → amt2（外收费金额，根据主机交易代码计算）
  liqu_dir → liqu_dir（账务方向）
  cash_flag → cash_flag（钞汇标识）
  prd_code → prd_code（产品代码）
  ```

**`host_date` 字段说明**：
- **字段含义**：主机交易日期，表示主机处理该笔交易的日期
- **数据来源**：
  1. **主要来源**：主机交易响应中的 `ITag.HostDate` 字段
     - 当系统向主机发送交易请求（如购买、赎回等）时，主机返回响应
     - 响应中包含 `HostDate` 字段，表示主机处理该笔交易的日期
     - 系统从响应中获取 `HostDate` 并更新到流水表的 `host_date` 字段
  2. **更新时机**：
     - 在交易处理流程中，当收到主机响应后，通过 `transVar.setHostDate(hostEvent.getInt(ITag.HostDate))` 设置
     - 然后更新到流水表（`tbdxfundtransreq`）的 `host_date` 字段
     - 示例代码位置：`T110500HSAdapter.java` 的 `toHost()` 方法中
  3. **特殊情况**：
     - 撤单交易：继承原交易的 `host_date`
     - 抹账交易：继承原交易的 `host_date`
     - 实时赎回：使用主机响应的 `HostDate`
     - 批量交易：使用系统日期（`DateUtil.getSysDate()`）或主机响应的 `HostDate`
- **字段格式**：整数类型（如：`20240101`），表示YYYYMMDD格式的日期
- **对账用途**：
  - 当参数 `CheckByHostDate='1'` 时，对账需要匹配 `host_date = trans_date`
  - 用于确保主机对账文件中的交易日期与流水表中的主机日期一致

**`host_serial` 和 `to_host_serial` 字段说明**：

**1. `to_host_serial`（发送主机流水号）字段**：
- **字段含义**：系统发送给主机的流水号，用于标识该笔交易请求
- **数据来源**：
  1. **生成时机**：在发送主机交易请求时生成
  2. **生成方式**：
     - 通过序列号生成器生成：`DxFundSequenceFactory.getSequence().getSerialNo()`
     - 或使用流水表的 `serial_no` 字段
     - 或使用流水表的 `ex_serial` 字段
  3. **保存位置**：
     - 保存到流水表（`tbdxfundtransreq`、`tbdxfundhistransreq`、`tbdxfundbatchreq`）的 `to_host_serial` 字段
     - 在发送主机请求时，通过 `hostRequest.setToHostSerial()` 设置
     - 在收到主机响应后，通过 `transVar.setToHostSerial(hostEvent.getString(ITag.ExSerial))` 更新
  4. **对账文件来源**：
     - 主机对账文件的第二字段（索引1）
     - 代码位置：`T210210HSAdapter.java` 的 `LoadTransResultFile()` 方法
     - 代码示例：`paramList.add(getString(fieldValue, 1, " "));`
- **字段格式**：字符串类型，通常为数字字符串
- **对账用途**：
  - 当参数 `CHECK_SERIAL='1'` 时，使用 `to_host_serial` 作为对账流水号
  - 用于匹配系统发送的流水号与主机对账文件中的流水号

**2. `host_serial`（主机流水号）字段**：
- **字段含义**：主机返回的流水号，用于标识主机处理该笔交易的流水号
- **数据来源**：
  1. **主要来源**：主机交易响应中的 `ITag.HostSerial` 字段
  2. **获取时机**：
     - 在交易处理流程中，当收到主机响应后，通过 `transVar.setHostSerial(hostEvent.getString(ITag.HostSerial))` 设置
     - 然后更新到流水表（`tbdxfundtransreq`、`tbdxfundhistransreq`、`tbdxfundbatchreq`）的 `host_serial` 字段
     - 示例代码位置：`T110500HSAdapter.java` 的 `toHost()` 方法中
  3. **对账文件来源**：
     - 主机对账文件的第三字段（索引2）
     - 代码位置：`T210210HSAdapter.java` 的 `LoadTransResultFile()` 方法
     - 代码示例：`paramList.add(getString(fieldValue, 2, " "));`
  4. **特殊处理**：
     - 如果参数 `HOSTSERIALUNIQUE=NO` 且 `CHECK_SERIAL=0`，则组合日期和流水号：
       - `host_serial = trans_date + host_serial`
       - 代码示例：`paramList.add(getString(fieldValue, 0, "0")+getString(fieldValue, 2, " "));`
- **字段格式**：字符串类型，通常为数字字符串
- **对账用途**：
  - 当参数 `CHECK_SERIAL='0'` 时（默认），使用 `host_serial` 作为对账流水号
  - 用于匹配系统记录的主机流水号与主机对账文件中的流水号

**3. 对账流水号选择**：
- **参数控制**：`CHECK_SERIAL` 参数控制使用哪个字段作为对账流水号
  - `CHECK_SERIAL='0'`（默认）：使用 `host_serial` 对账
  - `CHECK_SERIAL='1'`：使用 `to_host_serial` 对账
- **匹配逻辑**：
  - 从本地记录表（`tbdxfundbkcomplocal`）中选择对账流水号字段（`checkSerial`）
  - 与主机对账文件表（`tbdxfundbkcomp`）中对应的字段进行匹配
  - 匹配条件：`tbdxfundbkcomplocal.checkSerial = tbdxfundbkcomp.checkSerial`
- **特殊处理**：
  - 如果 `CheckByTransAccount='1'`，使用 `trans_account` 作为银行账号
  - 如果 `HOSTSERIALUNIQUE=NO` 且 `CHECK_SERIAL=0`，组合日期和流水号
  - 冻结、解冻、解冻扣款类交易，金额需要加上手续费
  - 根据主机交易代码计算外收费金额（`amt2`）

**3.2 从历史流水表插入**（`insertBkCompLocalFromHis()`）
- **数据源**：`tbdxfundhistransreq{1-16}`（分表）
- **插入方式**：与当前流水表相同，使用线程池并发处理
- **字段映射**：与当前流水表相同
- **目的**：处理历史流水中的对账数据（如隔日对账场景）

**3.3 从批量流水表插入**
- **数据源**：`tbdxfundbatchreq`
- **插入条件**：
  - `prd_code = ' '`（产品代码为空，用于日日金垫资户划款对账）
  - 其他条件与流水表相同
- **目的**：处理批量流水中的对账数据

**3.4 处理基金优惠券**（`dealCoupon()`）
- **触发条件**：参数 `COUPON_FLAG='1'`
- **处理逻辑**：
  - 从 `tbdxfundcoupon` 表查询优惠券金额
  - 更新 `tbdxfundbkcomplocal` 中的金额：
    - 如果 `asso_serial = serial_no`，则 `amt = amt - coupon_amt`
    - 如果 `asso_serial2 = serial_no`，则 `amt = amt - coupon_amt`
- **目的**：优惠券金额不参与对账，需要从对账金额中扣除

**3.5 处理余额宝两借一贷**（`updateYebBKCompLocal()`）
- **触发条件**：参数 `DXFUND_YEB_BORROWLEND_MODE='1'`
- **处理逻辑**：
  - 更新110415交易的金额为关联110516交易的份额（`vol`）
  - 删除110416交易的对账记录（如果存在对应的110415交易）
- **目的**：余额宝两借一贷业务的对账金额需要特殊处理

**3.6 处理组合宝对账数据**（`insertBkCompLocalFromZhb()`）
- **触发条件**：存在组合宝业务（`DxFundGrpTypeUtil.isYebZh()` 返回true）
- **处理逻辑**：
  - 从 `tbdxfundtransreq` 或 `tbdxfundhistransreq` 插入组合宝对账数据
  - 组合宝交易码：`118200`（购买）、`118516`（快赎）
  - 只处理主流水（控制位62位='0'）
  - 购买交易使用 `amt` 对账，快赎交易使用 `vol` 对账
- **可个性化点**：
  - 可通过实现 `IDxFundZHCheckService` 接口个性化组合宝对账逻辑
  - Bean名称：`DxFundZHCheckService`

##### 步骤4：执行个性化处理（可选）

**4.1 个性化处理接口**（`ICompIndividual`）
- **调用时机**：在删除历史对账数据之后，插入本地对账数据之前
- **接口方法**：`individualProcess(IContext context, TransVar210201 transVar)`
- **Bean名称**：`CompIndividualService`
- **功能**：可进行数据预处理、过滤、转换等个性化操作

##### 步骤5：执行对账比较

对账比较通过SQL查询找出三种类型的对账不平记录，并插入到 `tbdxfundbkcompdetail` 表中。

**`host_date` 与 `trans_date` 匹配说明**：

当参数 `CheckByHostDate='1'` 时，对账需要同时匹配流水号和日期：

1. **`host_date` 的来源和赋值**：
   - **来源**：主机交易响应中的 `ITag.HostDate` 字段
   - **赋值时机**：
     - 在交易处理流程中，当收到主机响应后，通过 `transVar.setHostDate(hostEvent.getInt(ITag.HostDate))` 设置
     - 然后更新到流水表（`tbdxfundtransreq`、`tbdxfundhistransreq`、`tbdxfundbatchreq`）的 `host_date` 字段
     - 示例代码位置：`T110500HSAdapter.java` 的 `toHost()` 方法中
   - **字段含义**：主机处理该笔交易的日期（主机账务日期）
   - **字段格式**：整数类型（如：`20240101`），表示YYYYMMDD格式的日期

2. **`trans_date` 的来源和赋值**：
   - **来源**：主机对账文件的第一字段（索引0）
   - **赋值时机**：
     - 在导入对账文件时，从文件的第一字段读取
     - 代码位置：`T210210HSAdapter.java` 的 `LoadTransResultFile()` 方法
     - 代码示例：`paramList.add(Integer.valueOf(getString(fieldValue, 0, "0")));`
   - **字段含义**：主机对账文件中记录的该笔交易的日期（主机账务日期）
   - **字段格式**：整数类型（如：`20240101`），表示YYYYMMDD格式的日期

3. **日期匹配逻辑**：
   - **匹配条件**：`tbdxfundbkcomplocal.host_date = tbdxfundbkcomp.trans_date`
   - **匹配目的**：确保对账时，流水表中的主机日期与对账文件中的交易日期一致
   - **使用场景**：
     - 当主机对账文件中的交易日期与流水表中的主机日期不一致时，可能导致对账失败
     - 例如：跨日交易、主机日期变更等情况
   - **SQL示例**（主机有销售商无）：
     ```sql
     -- 如果 CheckByHostDate='1'
     and tbdxfundbkcomplocal.host_date = tbdxfundbkcomp.trans_date
     and tbdxfundbkcomplocal.host_serial = tbdxfundbkcomp.host_serial
     ```

4. **日期一致性保证**：
   - **正常情况下**：`host_date` 和 `trans_date` 应该一致，因为都来自主机的账务日期
   - **可能不一致的情况**：
     - 跨日交易：交易发起日期与主机处理日期不同
     - 主机日期变更：主机系统日期变更导致日期不一致
     - 对账文件延迟：对账文件生成时间与交易处理时间不同
   - **处理方式**：
     - 如果 `CheckByHostDate='0'`（默认），则不对日期进行匹配，只匹配流水号
     - 如果 `CheckByHostDate='1'`，则必须同时匹配流水号和日期，确保日期一致

**5.1 主机有销售商无**（`hostHaveAndFssNo()`）
- **对账逻辑**：
  - 从主机对账文件表（`tbdxfundbkcomp`）中查找记录
  - 条件：`status='1'`（有效记录）
  - 且不存在于本地记录表（`tbdxfundbkcomplocal`）
  - 且不存在于当前流水表（`tbdxfundtransreq`）
  - 且不存在于历史流水表（`tbdxfundhistransreq`）
- **匹配字段**：
  - 默认：`checkSerial`（根据 `CHECK_SERIAL` 参数，可能是 `host_serial` 或 `to_host_serial`）
  - 如果 `CheckByHostDate='1'`：还需要匹配 `host_date = trans_date`
    - **`host_date`**：流水表中的主机日期，来自主机交易响应
    - **`trans_date`**：主机对账文件中的交易日期，来自主机对账文件的第一字段
- **插入字段**：
  ```
  unequa_flag = '2'（主机有销售商无）
  unequa_name = '主机有销售商无'
  host_amt = amt（主机金额）
  sys_amt = 0.0（系统金额）
  ```
- **补充信息**（如果参数 `Tlyhspccompare='1'`）：
  - 从 `tbdxfundtransreq`、`tbdxfundhistransreq`、`tbdxfundbatchreq` 补充：
    - `ta_code`、`in_client_no`、`client_type`、`status`、`branch_no`

**5.2 销售商有主机无**（`hostNoAndFssHave()`）
- **对账逻辑**：
  - 从本地记录表（`tbdxfundbkcomplocal`）中查找记录
  - 且不存在于主机对账文件表（`tbdxfundbkcomp`）
  - 条件：主机对账文件表中 `status='1'`
- **匹配字段**：
  - 默认：`checkSerial`
  - 如果 `CheckByHostDate='1'`：还需要匹配 `host_date = trans_date`
- **插入字段**：
  ```
  unequa_flag = '1'（销售商有主机无）
  unequa_name = '销售商有主机无'
  host_amt = 0.0（主机金额）
  sys_amt = amt（系统金额）
  ```

**5.3 销售商与主机不平**（`hostAndFssVariance()`）
- **对账逻辑**：
  - 从本地记录表（`tbdxfundbkcomplocal`）和主机对账文件表（`tbdxfundbkcomp`）中查找匹配的记录
  - 匹配条件：`checkSerial` 相同，且 `status='1'`
  - 不平条件（根据 `CHECK_DETAIL_ONCE` 参数）：
    - **如果 `CHECK_DETAIL_ONCE='1'`**（不平记录不重复显示）：
      - 金额不平：`abs(A.amt - B.amt) > 0.001` 或 `abs(A.amt2 - B.amt2) > 0.001`
      - 或备用字段不平：`A.reserve1 != B.reserve1`
      - 或币种不平（如果 `DXFUND_NOCHECK_CURRTYPE='1'`）：`A.curr_type != B.curr_type`
      - 或银行账号不平（如果 `CHECK_BANKACC='1'`）：`A.bank_acc != B.bank_acc`
      - 插入一条记录，`unequa_flag = '3'`（销售商与主机不平）
    - **如果 `CHECK_DETAIL_ONCE='0'`**（不平记录分别显示）：
      - **金额不平**：
        - 条件：`abs(A.amt - B.amt) > 0.001` 或 `abs(A.amt2 - B.amt2) > 0.001`
        - `unequa_flag = '4'`（金额不平）
      - **银行账号不平**（如果 `CHECK_BANKACC='1'`）：
        - 条件：`A.bank_acc != B.bank_acc`
        - `unequa_flag = '5'`（银行账号不平）
      - **钞汇不符**（如果 `NOCHECK_CASHFLAG='0'`，默认对账）：
        - 条件：`A.cash_flag != B.cash_flag`
        - `unequa_flag = '6'`（钞汇不符）
      - **币种不符**（如果 `DXFUND_NOCHECK_CURRTYPE='1'`）：
        - 条件：`A.curr_type != B.curr_type`
        - `unequa_flag = '7'`（币种不符）
- **插入字段**：
  ```
  host_amt = B.amt（主机金额）
  sys_amt = A.amt（系统金额）
  host_bk_acc = B.bank_acc（主机银行账号）
  sys_bk_acc = A.bank_acc（系统银行账号）
  ```
- **特殊处理**：
  - **换卡处理**（如果参数 `CardChgHostCheckDiff='1'`）：
    - 如果存在换卡记录（`tbdxfundtransreq` 中 `trans_code='110003'` 且 `status='S'`）
    - 且对账不平类型为 `'3'`（销售商与主机不平）或 `'5'`（银行账号不平）
    - 则更新 `reserve2='1'`，标记为换卡导致的不平
  - **实时赎回处理**（如果参数 `CHKREALREDFLAG='1'`）：
    - 如果实时赎回交易（`trans_code='110265'`，控制位3位='1'）对账结果为"销售商有主机无"
    - 则更新流水状态为 `'F'`（确认失败）

##### 步骤6：判断对账结果

**6.1 统计对账失败数量**（`checkHostResult()`）
- 查询 `tbdxfundbkcompdetail` 表中的记录数：
  - 条件：`trans_date = 对账日期`
  - 如果分TA对账：`ta_code = TA代码`
  - 如果分法人行对账：`bank_no = 银行编号`
- 设置 `transVar.setFailNum(recNum)`：总失败数量

**6.2 统计非账号不符的失败数量**
- 查询 `tbdxfundbkcompdetail` 表中 `unequa_flag <> '5'`（银行账号不平）的记录数
- 设置 `transVar.setNoAccFailNum(recNum)`：非账号不符的失败数量
- **说明**：账号不符由于考虑换卡，可以返回成功；其他类型的不符必须返回失败

**6.3 返回对账结果**
- 在应答包中返回：
  - `FailNum`：总失败数量（`tbdxfundbkcompdetail` 表中的记录数）
  - `NoAccFailNum`：非账号不符的失败数量（排除 `unequa_flag='5'` 的记录）
  - `ResultFile`：对账结果文件路径（非本地对账模式）
  - `RecordCount`：对账结果文件记录数（非本地对账模式）
- **对账结果判断**：
  - 如果 `NoAccFailNum > 0`：对账失败（账号不符除外）
  - 如果 `NoAccFailNum = 0`：对账成功（账号不符不影响成功状态）

##### 步骤7：导出对账结果（见4.3.4）

**对账结果表（tbdxfundbkcompdetail）字段说明**：
- `trans_date`：对账日期
- `to_host_serial`：发送主机流水号
- `host_serial`：主机流水号
- `check_status`：对账状态（从本地记录表获取）
- `ta_code`：TA代码
- `in_client_no`：内部客户号（如果参数 `Tlyhspccompare='1'` 会补充）
- `client_no`：客户编号
- `bank_no`：法人行编号
- `client_type`：客户类型（如果参数 `Tlyhspccompare='1'` 会补充）
- `host_bk_acc`：主机银行账号
- `sys_bk_acc`：系统银行账号
- `branch_no`：机构号（如果参数 `Tlyhspccompare='1'` 会补充）
- `host_amt`：主机金额
- `sys_amt`：系统金额
- `unequa_flag`：不平标志
  - `'1'`：销售商有主机无
  - `'2'`：主机有销售商无
  - `'3'`：销售商与主机不平（CHECK_DETAIL_ONCE='1'时）
  - `'4'`：金额不平（CHECK_DETAIL_ONCE='0'时）
  - `'5'`：银行账号不平（CHECK_DETAIL_ONCE='0'时）
  - `'6'`：钞汇不符（CHECK_DETAIL_ONCE='0'时）
  - `'7'`：币种不符（CHECK_DETAIL_ONCE='0'时）
- `unequa_name`：不平名称
- `deal_status`：处理状态（从本地记录表获取，如果参数 `Tlyhspccompare='1'` 会补充）
- `reserve2`：备用字段2（换卡标志，如果 `CardChgHostCheckDiff='1'` 会设置）

**本地记录表（tbdxfundbkcomplocal）字段说明**：
- 与对账结果表类似，但包含完整的本地交易信息
- 用于对账比较的中间表，对账完成后可清空

**技术细节**：

1. **并发处理**：
   - 插入本地对账数据使用线程池并发处理
   - 线程数：参数 `HOSTCHCK_THREADNUM`（默认5）
   - 队列大小：参数 `HOSTCHCK_QUEUESIZE`（默认5）
   - 按产品列表并发，每个产品一个任务

2. **批量执行拆分**：
   - 支持批量执行拆分（参数 `BatchExecuteSplit` 控制）
   - 用于提高大数据量场景下的执行效率
   - 适用于删除、插入、更新等操作

3. **对账精度**：
   - 金额比较精度：`0.001`（`abs(A.amt - B.amt) > 0.001`）
   - 外收费金额比较精度：`0.001`（`abs(A.amt2 - B.amt2) > 0.001`）

4. **对账流水号处理**：
   - 默认使用 `host_serial` 对账
   - 如果 `CHECK_SERIAL='1'`，使用 `to_host_serial` 对账
   - 如果 `HOSTSERIALUNIQUE=NO` 且 `CHECK_SERIAL=0`，组合日期和流水号：`rtrim(to_char(host_date))||host_serial`

5. **对账日期匹配**：
   - 默认：只匹配流水号
   - 如果 `CheckByHostDate='1'`：还需要匹配 `host_date = trans_date`

6. **特殊业务处理**：
   - **基金优惠券**：从对账金额中扣除优惠券金额
   - **余额宝两借一贷**：更新110415交易金额为关联110516交易的份额
   - **组合宝**：购买使用金额对账，快赎使用份额对账
   - **换卡**：标记换卡导致的对账不平（`reserve2='1'`）
   - **实时赎回**：如果对账不平，更新流水状态为失败

**注意事项**：

1. **对账顺序**：
   - 必须先删除历史数据，再插入本地数据，最后执行对账比较
   - 个性化处理接口在删除之后、插入之前调用

2. **对账结果表**：
   - 对账结果存储在 `tbdxfundbkcompdetail` 表中
   - 对账结果会同步到 `tbdxfundbkcompdetailsync` 表（用于BC同步）
   - 对账结果会导出为文件（见3.3.4）

3. **对账失败处理**：
   - 账号不符（`unequa_flag='5'`）不影响对账成功状态
   - 其他类型的不符都会导致对账失败
   - 对账失败后需要人工处理对账不平记录

4. **性能优化**：
   - 使用线程池并发处理提高性能
   - 支持批量执行拆分减少数据库压力
   - 对账比较使用SQL的 `NOT EXISTS` 子查询优化性能

**可个性化点**：

  - Bean名称：`CompIndividualService`

## 七、注意事项

1. **分TA对账模式**：
   - 分TA模式下，对账表名包含TA代码和银行编号
   - 分TA模式下，文件名包含TA代码
   - 分TA模式下，必须指定TA代码

2. **文件拆分**：
   - 文件拆分基于内部客户号计算交易片区
   - 如果查不到内部客户号，会抛出异常（除非配置了忽略内部户）
   - 拆分后的文件会发送到分布式文件服务器

3. **对账表管理**：
   - 分TA模式使用临时表，每次对账前删除重建
   - 不分TA模式使用正式表，每次对账前清空数据
   - 可通过参数 `CREATE_TEMP_TABLE` 控制表类型

4. **对账流水号**：
   - 默认使用 `host_serial` 对账
   - 如果主机流水号不唯一，需要组合日期和流水号
   - 可通过参数 `CHECK_SERIAL` 切换为 `to_host_serial` 对账

5. **个性化服务**：
   - 个性化服务通过Spring Bean配置，如果未配置则使用默认实现
   - 个性化服务可以完全替换标准实现，也可以扩展标准实现
