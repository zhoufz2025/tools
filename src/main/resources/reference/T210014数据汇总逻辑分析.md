## 3. 公共片区通用加工基础设施

来自 `BaseStatsTask`（公共）：

```sql
-- getBnData(syncTable) 内部（DataInOne='1' 时整段跳过）
TRUNCATE TABLE {syncTable};
-- 按 totAreaNum 拉取各片区文件 → StandardFileReader 导入

-- updateInternalBranch(syncTable)
UPDATE {syncTable} a
SET a.internal_branch = (
  SELECT internal_branch FROM tbbranch WHERE branch_no = a.branch_no
);
-- 若 sync 中 branch_no 不在 tbbranch，直接抛错

-- 机构前缀匹配（MySQL/DB2 典型写法；Oracle 亦可用 like）
AND substr(a.internal_branch, 1, length(Rtrim(pb.internal_branch))) = pb.internal_branch
```

**标准公共加工流水线**（多数报表）：

```
TRUNCATE sync → getBnData → updateInternalBranch（可选）
→ DELETE 正式表当日
→ for j=0..maxBranchLevel: INSERT sync SELECT ... JOIN tbbranch（table_num='BC00'）
→ DELETE sync WHERE table_num<>'BC00'
→ INSERT 正式表 SELECT * FROM sync
```

### 3.1 机构层级 rollup 详解（`j = 0 .. maxBranchLevel`）

#### 含义一句话

把交易片区送来的**叶子机构（网点/开户行）明细汇总结果**，按 `tbbranch` 组织树**自下而上（实际是按层级分别汇总）**，为**每一个上级机构**各生成一行「本机构 + 下属全部」的汇总数据。

#### 关键字段（`tbbranch`）

| 字段 | 作用 |
|------|------|
| `branch_no` | 机构号（业务可见） |
| `internal_branch` | **机构内码**，用前缀表达父子关系（子机构内码以父机构内码开头） |
| `branch_level` | **机构层级**：通常 `0`=总行，`1`=一级分行，`2`=二级分行/支行……数字越大越靠下 |
| `maxBranchLevel` | 全行最深层级（Adapter 里 `getMaxBranchLevel()`），循环上界 |

**内码前缀示例**（示意，实际以银行 `tbbranch` 配置为准）：

```
level0 总行     internal_branch = '11'
level1 省分行   internal_branch = '1101'      （前缀 '11' → 属于总行）
level2 市分行   internal_branch = '110101'    （前缀 '1101' → 属于该省分行）
level3 网点A    internal_branch = '11010101'
level3 网点B    internal_branch = '11010102'
```

匹配条件（rollup 核心）：

```sql
substr(a.internal_branch, 1, length(Rtrim(pb.internal_branch))) = pb.internal_branch
```

即：**明细行 a 的内码以汇总目标机构 pb 的内码为前缀** ⇒ a 归属 pb 及其下级，应计入 pb 的合计。

#### `j` 循环在做什么

```java
for (int j = 0; j <= maxBranchLevel; j++) {
    // INSERT ... FROM sync a, tbbranch pb
    // WHERE pb.branch_level = j
    //   AND substr(a.internal_branch,...) = pb.internal_branch
    // GROUP BY pb.branch_no, pb.internal_branch, 业务维度...
}
```

| 当 j= | 选出的 pb | 汇总效果 |
|-------|-----------|----------|
| `0` | 所有 `branch_level=0` 的机构（总行） | 把全行叶子数据 SUM 到总行一行 |
| `1` | 所有一级分行 | 每个省分行各自 SUM 其下属全部网点 |
| `2` | 所有二级机构 | 每个市分行/支行 SUM 其下属 |
| … | … | … |
| `maxBranchLevel` | 最底层机构 | 通常等于叶子自身（或同层汇总），保证最底层也有 `BC00` 行 |

**不是**「先算 j=max 再层层向上递推」的串行依赖；而是**对每一层独立做一次「叶子数据 → 该层机构」的 SUM**。源数据始终是 getBnData 导入后、尚未标成 `BC00` 的叶子行（或等价明细行）。

#### 数据怎么汇总（以份额余额为例）

假设 sync 里只有网点叶子数据（交易片区导出）：

| branch_no | internal_branch | prd_code | tot_vol |
|-----------|-----------------|----------|---------|
| 网点A | 11010101 | P001 | 100 |
| 网点B | 11010102 | P001 | 200 |
| 网点C | 11020101 | P001 | 50 |

执行 `j=2`（假设市分行 level=2，内码 `110101`、`110201`）：

- 市分行 `110101`：匹配 A+B → `tot_vol=300`，写入 `branch_no=市分行1`，`table_num='BC00'`
- 市分行 `110201`：匹配 C → `tot_vol=50`

执行 `j=1`（省分行 `1101`）：

- 省分行 `1101`：匹配 A+B（前缀 1101）→ `tot_vol=300`（若 C 属于另一省则不计入）

执行 `j=0`（总行 `11`）：

- 总行：匹配 A+B+C → `tot_vol=350`

最终 `DELETE WHERE table_num<>'BC00'` 后，正式表里同时保留**总行、省、市、网点各层级**的汇总行，报表可按任意机构层级查询「含下属」口径。

#### 与交易片区的分工

| 片区 | 机构粒度 | 做什么 |
|------|----------|--------|
| 交易 | 叶子 `branch_no`/`open_branch` | 按网点汇总业务量，写出 sync（`table_num=00`） |
| 公共 | 先 `updateInternalBranch` 补全内码，再按 level 循环 | 生成各级「含下属」汇总（`table_num=BC00`） |

#### 注意点

1. **sum_flag**：若同时有交易机构/开户机构两套叶子数据，rollup 通常对 `sum_flag=JYJG`、`KHJG` **各跑一遍**（或 SQL 里带上 sum_flag 过滤）。  
2. **client_num 等计数**：rollup 是 `SUM(client_num)`，跨网点去重不在此做；客户数在叶子已算好后是「网点客户数之和」，可能与全行去重客户数不同。  
3. **无 rollup 的报表**（如 YEBDZHZ、SJBS）：只按产品/业务码跨片区 SUM，不按机构树上卷。
