# 电子合同功能说明文档

## 一、电子合同背景

电子合同是基金代销系统中用于管理客户与销售机构、管理人、托管人之间电子合同签署、补正、确认的重要功能模块。根据监管要求，公募基金产品需要客户签署电子合同，系统通过电子合同功能实现：

1. **合同签署**：客户首次签署电子合同
2. **合同补正**：对已签署但需要修改的合同进行补正
3. **合同确认**：管理人、托管人对合同进行审核确认
4. **合同查询**：支持客户和管理人员查询电子合同信息
5. **文件接口**：与TA系统进行电子合同数据的导入导出

系统通过交易、批量任务、文件接口等方式实现电子合同的完整生命周期管理。

## 三、交易代码

### 3.1 电子合同签署/补正交易

**交易代码**：110258

**交易名称**：电子合同签署/补正

**功能说明**：
- 支持客户首次签署电子合同
- 支持对已签署但需要补正的合同进行修改
- 签署类型包括：合同签订（401）、合同补正（402）

**交易参数**：
- enable_flag：启用标志（1-启用）
- channels：支持渠道（01234569G）
- host_online：主机在线标志（1-在线）
- trans_type：交易类型（2-普通交易）
- cancel_flag：可撤销标志（1-可撤销）
- erase_flag：可抹账标志（1-可抹账）

**业务规则**：
1. 首次签署：检查客户是否已签署电子约定书，未签署则不允许签署电子合同
2. 合同补正：仅允许"需补正"状态的合同进行补正
3. 风险匹配：校验客户风险等级与产品风险等级是否匹配
4. 产品控制：通过产品control_flag第51位控制产品是否为电子合同产品

### 3.2 电子合同查询交易

**交易代码**：110380

**交易名称**：电子合同查询

**功能说明**：
- 支持客户和管理人员查询电子合同信息
- 支持按合同编号、客户编号、产品代码等条件查询

**交易参数**：
- enable_flag：启用标志（1-启用）
- channels：支持渠道（01234569G）
- host_online：主机在线标志（0-离线）
- trans_type：交易类型（3-查询交易）
- cancel_flag：可撤销标志（0-不可撤销）
- erase_flag：可抹账标志（0-不可抹账）

### 4.4 字段映射查询

使用以下SQL可以查询电子合同文件与系统表的字段映射关系：

```sql
-- 通用查询SQL，替换${TEMPLET}和${FILE_TYPE}为实际值
-- TEMPLET可选值：'ZD20'、'ZD21'、'ZD22'
-- FILE_TYPE可选值：'31'（电子合同签约文件，ZD21模板）、'32'（电子合同确认文件，ZD21模板）、'43'（电子合同签约文件）、'44'（电子合同确认文件）
select b.*,a.sys_field,a.key_no,a.field_no 
from tbfieldmap a, tbtadict b 
where a.templet = '${TEMPLET}' 
  and a.file_type = '${FILE_TYPE}' 
  and a.templet = b.templet 
  and a.idno = b.idno 
order by a.field_no asc;
```


**说明：**
- `tbfieldmap`：字段映射表，定义文件字段与系统字段的对应关系
- `tbtadict`：TA字典表，定义字段的字典信息（字段名称、数据类型、长度等）
- `templet`：模板代码（ZD20/ZD21/ZD22），替换${TEMPLET}
- `file_type`：文件类型（31/32/43/44），替换${FILE_TYPE}
- `sys_field`：系统字段名，对应系统表中的字段
- `key_no`：关键字段标识，用于字典转换（如K_YWLB、K_ZJLX等）
- `field_no`：文件字段序号，表示字段在文件中的位置
- `idno`：字段序号，关联tbtadict表中的字段定义

**映射表结构说明：**

- **tbfieldmap（字段映射表）**
  - `templet`：模板代码（ZD20/ZD21/ZD22）
  - `file_type`：文件类型（31/32/43/44）
  - `idno`：字段序号，关联tbtadict表
  - `sys_field`：系统字段名，如'prd_code'、'contract_no'等
  - `key_no`：关键字段标识，用于字典转换，如'K_YWLB'（业务类别）、'K_ZJLX'（证件类型）等
  - `field_no`：文件字段序号，表示字段在文件中的位置顺序

- **tbtadict（TA字典表）**
  - `templet`：模板代码
  - `idno`：字段序号
  - `field_name`：字段名称（英文），如'ContractType'、'SerialNo'等
  - `data_type`：数据类型（C-字符型，N-数值型，A-字符型等）
  - `field_len`：字段长度
  - `scale`：小数位数
  - `field_desc`：字段描述（中文），如'合同类型'、'流水号'等

## 五、业务流程

### 5.1 电子合同签署流程

1. **客户发起签署**
   - 客户通过柜面、网银等渠道发起电子合同签署交易（110258）
   - 系统校验客户是否已签署电子约定书
   - 系统校验产品是否需要电子合同（通过产品control_flag第51位判断）

2. **风险匹配校验**
   - 系统校验客户风险等级与产品风险等级是否匹配
   - 记录风险匹配情况（risk_match）

3. **合同信息记录**
   - 生成合同编号：prd_code + seller_code + init_date + serial_no(后8位)
   - 记录签署日期、签署时间、操作柜员、分支机构等信息
   - 合同状态初始化为"待核对"（HTZT_EXPORT）或"待处理"（HTZT_PROCESS）
   - 写入tbdxfundeleccontract表

4. **文件导出**
   - 批量任务将已签署的合同数据写入tbdxfundeleccontractexp表
   - 生成43号文件导出到TA系统

5. **TA系统处理**
   - TA系统接收43号文件
   - 管理人、托管人审核合同
   - 生成44号文件返回

6. **文件导入**
   - 系统接收44号文件
   - 将数据写入tbdxfundeleccontractcfmtmp临时表
   - 批量任务处理临时表数据，更新tbdxfundeleccontract表的审核状态
   - 将确认数据写入tbdxfundeleccontractcfm表

### 5.2 电子合同补正流程

1. **客户发起补正**
   - 客户通过柜面、网银等渠道发起电子合同补正交易（110258）
   - 系统校验合同状态，仅允许"需补正"（HTZT_CFM_FAIL）状态的合同进行补正

2. **合同信息更新**
   - 更新合同相关信息（风险匹配、风险等级等）
   - 更新最后修改日期（last_modify_date）
   - 合同状态更新为"待核对"（HTZT_EXPORT）或"待处理"（HTZT_PROCESS）
   - 清空导出文件编号（export_no）和导入文件编号（impin_no）
   - 清空管理人、托管人审核状态

3. **文件导出**
   - 批量任务将补正后的合同数据写入tbdxfundeleccontractexp表
   - 生成43号文件导出到TA系统（签署类型为402-合同补正）

4. **后续流程**
   - 与签署流程相同，等待TA系统审核确认

### 5.3 购买类交易电子合同校验

在客户进行认购、申购等购买类交易时，系统会校验电子合同是否已签署：

1. **产品控制检查**
   - 检查产品control_flag第51位，判断产品是否需要电子合同
   - 如果产品不需要电子合同，则跳过校验

2. **交易代码检查**
   - 通过参数ELECCON_NOT_CHK_TRANS_CODE配置不需要校验电子合同的交易代码
   - 如果交易代码在配置列表中，则跳过校验

3. **合同状态检查**
   - 检查客户是否已签署电子合同
   - 如果未签署，则不允许交易
   - 通过参数ELECCON_CHK_STATUS控制"待补正"状态是否允许交易

### 6.4 批量任务

电子合同相关的批量任务处理涉及多个节点，从文件导入到清算结束的完整流程如下：

#### 6.4.1 210012节点（申请数据导出）

**功能说明**：将电子合同签署/补正交易流水导入到导出表，准备生成43号文件。

**处理逻辑**（`T210012HSAdapter.transReqToElecContractExp`方法）：

1. **数据筛选**：
   - 筛选交易代码为110258（电子合同签署/补正）的流水
   - 筛选状态为"1"（受理）或"5"（待确认）的流水
   - 根据产品状态和募集期配置决定导出时机

2. **数据导入**：
   - 将符合条件的交易流水数据插入到`tbdxfundeleccontractexp`表
   - 字段包括：serial_no、ta_code、bank_no、prd_code、asset_acc、in_client_no、client_type、seller_code、trans_date、trans_time、channel、oper_no、branch_no等

3. **数据更新**：
   - 根据`tbdxfundeleccontract`表更新导出表的合同编号（contract_no）、签署类型（sign_type）、风险匹配（risk_match）等字段
   - 根据客户信息更新导出表的联系方式（tel、mobile、email、address等）和风险等级（risk_level）
   - 更新交易流水状态为"导出"（JYZT_EXPORT）
   - 更新电子合同状态为"待核对"（HTZT_EXPORT）

4. **特殊处理**：
   - 处理待补正状态的电子合同申请（contract_status='2'）
   - 支持多交易账号模式（通过MULT_ELEC_FLAG参数控制）
   - 支持募集期当天导出/非募集期导出（通过DXFUND_PRD_BOOK_DAY_EXP_TYPE参数控制）

**代码位置**：
- `app/lcpt-server/sale/lcpt-dxfund/lcpt-dxfund-trans/lcpt-dxfund-batch-bootstrap/src/main/java/com/hundsun/lcpt/dxfund/batch/adapter/T210012/T210012HSAdapter.java`

**功能说明**：准备清算数据，将正式表数据导入备份表，处理电子合同确认数据。

**处理逻辑**：

**Task207000（清算数据准备任务）**：

## 十、注意事项

### 10.1 合同编号生成规则

合同编号生成规则：prd_code + seller_code + init_date + serial_no(后8位)

**说明**：
- prd_code：产品代码
- seller_code：销售商代码
- init_date：系统初始化日期
- serial_no：流水号后8位

### 10.2 合同状态流转

1. **首次签署**：
   - 如果TA需要43/44文件接口：状态为"待处理"（HTZT_PROCESS）
   - 如果TA不需要43/44文件接口：状态为"待核对"（HTZT_EXPORT）

2. **补正后**：
   - 如果TA需要43/44文件接口：状态为"待处理"（HTZT_PROCESS）
   - 如果TA不需要43/44文件接口：状态为"待核对"（HTZT_EXPORT）
   - 管理人、托管人状态均重置为"待核对"（HTZT_EXPORT）

3. **TA确认后**：
   - 通过44号文件导入管理人、托管人审核状态
   - 如果管理人、托管人均确认成功，合同状态更新为"已成功"（HTZT_CFM_SUCC）
   - 如果管理人、托管人任一确认失败，合同状态更新为"需补正"（HTZT_CFM_FAIL）

### 10.3 电子约定书前置条件

客户签署电子合同前，必须先签署电子约定书（交易代码：100105）。

**校验规则**：
- 如果客户未签署电子约定书，不允许签署电子合同
- 如果电子约定书状态异常，根据参数UNAGREEMENT_CHANNEL控制是否允许签署

### 10.4 多交易账号模式支持

系统支持多交易账号模式，通过ta_client字段记录TA交易账号。

**说明**：
- 在单交易账号模式下，ta_client字段为空
- 在多交易账号模式下，ta_client字段记录具体的TA交易账号

### 10.5 文件接口版本

系统支持多个版本的电子合同文件接口：
- **ZD20**：基础版本
- **ZD21**：增强版本，字段定义更详细
- **ZD22**：最新版本，字段长度更长

不同TA系统可能使用不同版本的文件接口，需要在tbfieldmap表中配置对应的字段映射关系。
