# 基金 6.0 基金参数从 TA 自动化同步（C 类文件）实现说明

> 整理日期：20260918  
> 范围：GIT-IFM6.0 基金代销（dxfund）公共片区。  
> 对应关系：中登/基金公司接口里的基金参数文件，在本系统统称 **C 类文件**（C1～C6）。  
> 07 文件是行情文件，不是 C 类；本文只在边界处说明，避免和参数同步混在一起。

---

## 1. 一句话结论

C 类文件走「配置决定收哪些文件 → 公共片区取文件 → 按字段映射灌入临时表 → 日启节点把临时表落到产品/费率/转换关系正式表」。

标准链路（按 TA 跑，公共片区）：

| 顺序 | 节点 | 类 | 做什么 |
|------|------|----|--------|
| 1 | 210203 | `T210203HSAdapter` | 从 TA 服务器取文件到本地，校验后写入 `tbfileinfo` |
| 2 | 210204 | `T210204HSAdapter` | 把已到文件按 `tbfiletype` + `tbfieldmap` 导入临时表 |
| 3 | 210202 | `T210202HSAdapter` | 行情汇总之后，把 C 类临时表同步到正式表，并刷新产品缓存 |

管理台勾选 C1～C5 时，会自动下发参数文件索引、并把 `FUND_LOAD_C_FILE=1`、`IMP_C_MODE=0`（日启导入）。

另有一条 **中登个养** 链路（210610 取、210611 导入），C1/C2 落到平台产品表、平台参与人表，不走 `tbdxfundproduct`。见第 12 节。

## 2. 文件类型对照

字典：`IDict.K_TAFILETYPE`、`IDxFundGeneralConstant.FILE_TYPE_C1`～`C6`。  
文件方向：`IDict.K_ZXFUNDWJLB`。

| 文件 | 业务含义 | 导入临时表 | 正式落点 | 典型 `file_dir` |
|------|----------|------------|----------|-----------------|
| 00 | 参数类索引 | 不落业务表 | — | `3` 参数文件。文件名规则 `OFC_SSS_RRR_YYYYMMDD.TXT` |
| C1 | 基金基础参数（产品信息） | `tbdxfundproductexp` | `tbdxfundproduct`、`tbdxfundprdassign`、`tbdxfundproductadd`、`tbprdparamvalue` | `3` |
| C2 | 基金代理关系（交收天数等） | `tbtaparamc2tmp` | `tbtaparamc2`；可选回写产品交收天数 | `3` |
| C3 | 基金转换关系 | `tbdxfundprdchglimittmp` | `tbdxfundprdchglimit` | `3` |
| C4 | 基金分红方案 | `tbtaparamc4tmp` | `tbtaparamc4`（只保留本行已有产品） | `3` |
| C5 | 基金费率 | `tbtaparamc5tmp` | `tbtaparamc5`，再可选写入 `tbdxfundfeerate` 或 `tbdxfundallfeerate` | `3` |
| C6 | 可赎回日期 | `tbdxfundprdreddaytmp` | `tbdxfundprdredday` | 示例脚本放在 `0`（确认文件），不是 `3` |

`file_dir` 取值：

- `0` 确认文件（日终）
- `1` 日启文件（07 行情走这里）
- `2` 导出文件
- `3` 参数文件（C1～C5 标准落点）

文件名规则占位：`SSS` 销售商、`RRR` TA、`YYYYMMDD` 日期、`TT` 文件类型。

字段映射不写死在 Java 里，而在 `tbfieldmap`：按 TA 接口模板（`tbtainfo.templet`，常见 `ZD20` / `ZD21` / `ZD22`）+ `file_type` + `idno` 映射到系统字段 `sys_field`。基线脚本在：

- `app/sql/sql-pub/pub/pub/extradata/ZD22/tbfieldmap.sql`（及 ZD20、ZD21）
- 个养模板：`app/sql/sql-dxfund/pub/dxfund/extradata/Pension/ZDGY/tbfieldmap.sql`

导入时 `TaTableUtil` 按临时表名选字段描述类：

| 临时表前缀 | Bean |
|------------|------|
| `tbdxfundproductexp` | `ProductExpDesc` |
| `tbtaparamc2tmp` | `TaParamC2TmpDesc` |
| `tbdxfundprdchglimittmp` | `FundChgLimitTmp` |
| `tbtaparamc4tmp` | `TaParamC4TmpDesc` |
| `tbtaparamc5tmp` | `TaParamC5TmpDesc` |
| `tbdxfundprdreddaytmp` | `PrdRedDay` |

解析入口：`TaFileReader.taFileFactoryRead` → `getFileFromServer` / `checkTAFile` / `loadDataFile`。本地目录：`{IFMBASEPATH}/data/{taCode}/recv`。

## 3. 开关：什么时候才会真正同步

两层开关，缺一不可。

### 3.1 收文件、灌临时表：`IMP_C_MODE`

参数 ID：`IConstant.IMP_C_MODE`，**分 TA**（`ParamCache.getParamValue(taCode, ...)`）。  
含义：`0` 日启导入，`1` 日终导入。

| 节点 | 未配置时的默认值 | 行为 |
|------|------------------|------|
| 210203 取文件 | `"1"` | 仅当值为 `0` 时，文件方向列表追加 `file_dir=3` |
| 210204 导入 | `"1"` | 同上 |
| 210202 汇总 | `"0"` | 仅当值为 `0` 时，才做 C3 转换关系 + `dealTAParamFile` |

管理台勾选 C 类后会把该 TA 的 `IMP_C_MODE` 写成 `0`。未手工配置时，日启取/导默认不收参数文件，日启汇总默认会处理——两边默认值不一致，现场必须以库里该 TA 的实际值为准。

公共片区日终导入 `T210103/ImportTAFileFunc` 里，`IMP_C_MODE=1` 时追加 `file_dir=3` 的代码已被注释，**标准公共片区不会在日终再导参数文件**。交易片区 `T210103` 仍有这段，但 C 类 `area_type=0`，落在公共片区，不依赖交易片区导入。

### 3.2 临时表进正式表：`FUND_LOAD_C_FILE`

参数 ID：`IParamConstant.FUND_LOAD_C_FILE`，分 TA，默认 `0`。

- `0`：`DealTAParamFileFunc.dealTAParamFile` 直接返回；`chgLimitTmpToChgLimit` 也直接返回。临时表有数据也不会进正式表。
- `1`：才执行 C1～C6 的正式表同步（C3 还要再看 `DXFUND_LOAD_C3`，C4 还要再看 `DXFUND_LOAD_C4`）。

管理台勾选任一 C1～C5 时会把该参数写成 `1`。

### 3.3 第三层：按文件类型写费率正式表 `DAY_BEGIN_IMP_CFILES`

参数 ID：`IDxFundParamConstant.DAY_BEGIN_IMP_CFILES`，**分 TA**，默认空格。

210202 在 `IMP_C_MODE` 判断之外还会读它。非空时（例如 `C5` 或 `C1,C2,C5`）调用：

- `IS_USE_ALLFEERATE_SET=1` → `dealTAParamFileToTableNew`
- 否则 → `dealTAParamFileToTable`

当前实现里，这个方法**只对字符串中包含 `C5` 的情况写费率正式表**（`DataUtil.contains(fileTypes, "C5")`）。C1/C2/C3/C4 的正式表更新不走这里，走 `dealTAParamFile`。

## 4. 210203 取日启文件

类：`com.hundsun.lcpt.dxfund.pub.batch.adapter.T210203.T210203HSAdapter`  
Bean：`TPUB210203HSAdapter`。功能名：取日启文件。

步骤：

1. 多法人时按法人 `SysArg` 循环；单法人只用当前 `SYSARG`。
2. 夜间清算已成功（`tbdxfundnightclear` 中 `trans_code=210886`、状态成功、`use_flag<>1`，且当日已有 `tbdxfundprddaily`）时，标记跳过日启方向。若 `tbfiletype` 里该 TA 的 `file_dir=1` 还有夜间方向 `WJLB_NIGHT_IMP` 未覆盖的文件类型，则不跳过。
3. 服务器目录优先级：context 的 `SERVERPATH` → 配置 `210203.ServerPath` → `210203_{taCode}` → `200203_{taCode}_{sellerCode}`。`IS_GETPARAMS_BYDB=1` 时再从 `tbparam` 读 `lcpt.config.210203_{taCode}.ServerPath`。路径中 `YYYYMMDD` 换成系统日期。目录为空报 `ERR_PARAMETER`。
4. 文件方向：
   - 未指定 `DirFlag`：未跳过夜间时加 `file_dir=1`；`IMP_C_MODE=0` 时再加 `file_dir=3`。
   - 指定了 `DirFlag`：只用该方向（24 点批次等会传入）。
5. 每个方向：`TaFileReader` 先删当天文件信息，再 `getFileFromServer`，再 `checkTAFile` 写入 `tbfileinfo`。失败抛 `ERR_FILECHECK`。
6. 日启方向必取文件只有 `07`。参数方向没有必取列表，缺 C 类文件不会因为「必取」失败，是否报错取决于索引文件和 `checkTAFile` 规则。

本地路径与 210204、210202 相同：`{IFMBASEPATH}/data/{taCode}/recv`。

## 5. 210204 导入日启文件

类：`T210204HSAdapter`，Bean `TPUB210204HSAdapter`。功能名：导入日启文件。

文件方向选择与 210203 相同（夜间跳过 `file_dir=1`，`IMP_C_MODE=0` 才加 `file_dir=3`）。

`impTaFile`：

1. `TaFileReader.taFileFactoryRead(taCode, taCode, sellerCode, initDate, fileDir, localPath)`。
2. `getLoadDataFileList()` 取待导入数据文件（不含纯索引）。
3. 列表为空则该方向跳过。
4. `loadDataFile` 按 `tbfiletype.table_name` 和 `tbfieldmap` 写入临时表。C1 写入 `tbdxfundproductexp`，C2 写入 `tbtaparamc2tmp`，以此类推。

之后 `deleteTabData` 只处理 98/99 TA 多条行情（`tbdxfundprddailytmp`、`tbdxfundprddailyexttmp`），**不改 C 类临时表**。

特殊 TA：`SPECIAL_TAINTERFACE=1` 时，当天没有成立或到期产品则整个节点直接返回，参数文件也不会导入。

产品缓存刷新已从本节点挪到 210202（`M202204010257`）。

## 6. 210202 日启文件汇总并更新

类：`T210202HSAdapter`，Bean `TPUB210202HSAdapter`。功能名：日启文件汇总并更新。

`action` 顺序：

1. TA 代码不能是 `000000`。
2. 夜间已处理时设置 `noRunFileDir1=1`，但**不再整节点 return**。历史问题：夜间行情成功后直接 return，会把当天 C 类也跳过（`T202312146160`）。现在只把标志传给后续方法。
3. `gatherClearTableTmpData`：把 T0 / 夜市行情临时表并入 `tbdxfundprddailytmp`。与 C 类无关。
4. `deleteInvalidPrdDailyTmp`：`PRD_DAILY_FILE_SPLIT_MODE=1` 时删除产品表不存在的行情临时记录。`DELETE_PRD_NOT_IN_RSB=1` 时还要求产品在 `tbdxfundrsbprdszyh`。只动行情临时表。
5. `FormatTADayBeginFileFunc.formatTADayBeginFile`：先行情，再参数。见下节。
6. 按 TA 刷新 `DxFundProductCache`、`DxFundProductAddCache`、`DxFundPrdParamValueCache`、`FullDxFundProductCache`。失败必须抛错（`T202602054799`），不再只告警。
7. `checkYebPrdDaily`：余额宝节假日行情条数校验，与 C 类无关。

### 6.1 `formatTADayBeginFile` 里和 C 类有关的顺序

```
noRunFileDir1 != 1  →  更新净值日期、补行情、更新产品、行情临时表进正式表
noRunFileDir1 == 1  →  只按参数决定是否补更新产品状态（夜间已做过行情）
NightClearFlag=1    →  可选处理 07，然后 return（夜间任务不处理 C 类）
IMP_C_MODE=0        →  chgLimitTmpToChgLimit（C3） + dealTAParamFile（C1/C2/C4/C5/C6）
deal07Data          →  07 扩展字段，不是 C 类
DAY_BEGIN_IMP_CFILES 非空 → dealTAParamFileToTable 或 New（目前只处理 C5 进费率正式表）
```

夜间任务带 `NightClearFlag=1` 时，C 类处理在 `return` 之前，不会执行。次日日启 210202 不带该标志，才会处理 C 类。

## 7. `dealTAParamFile` 总流程

类：`DealTAParamFileFunc`。入口先看 `FUND_LOAD_C_FILE`，为 `0` 直接返回。

事务按文件分段，失败回滚当前段。

顺序固定为：

1. `dealC1DataNotFromRsb`：`DELETE_PRD_NOT_IN_RSB=1` 时，删除 `tbdxfundproductexp` 中不在人社部产品表 `tbdxfundrsbprdszyh` 的记录。失败文案：「删除非人社部产品C类文件产品失败」。
2. 读分 TA 参数 `C1_AFTER_C2`（默认 `0`）。
   - `1`：先把 C2 临时表按本行销售商过滤后写入 `tbtaparamc2`，再删掉 `tbdxfundproductexp` 里 C2 没有的产品，然后 `dealC1Data`。用于 TA 的 C1 含非本行代销产品、需要先用 C2 代理关系裁剪。
   - `0`：先 `dealC1Data`，再把 C2 临时表整 TA 写入 `tbtaparamc2`（不过滤销售商）。
3. `C2_SYNC_PRD_DAYS=1` 时 `dealC2Data`，把交收天数回写产品表。
4. `dealC4ParamFile`（内部再看 `DXFUND_LOAD_C4`）。
5. C5：按 `ta_code + serial_no` 先删后插，`tbtaparamc5tmp` → `tbtaparamc5`。这里只进参数镜像表，不进费率表。
6. C6：按联合键先删后插，`tbdxfundprdreddaytmp` → `tbdxfundprdredday`。键：`ta_code, prd_code, add_flag, share_class, register_date, allow_red_date`。

C2 正式表写入 SQL（`C1_AFTER_C2=0`）：

```sql
delete from tbtaparamc2
 where ta_code=?
   and exists (select 1 from tbtaparamc2tmp where ta_code=? and serial_no=serial_no);
insert into tbtaparamc2 select * from tbtaparamc2tmp where ta_code=?;
```

注意：`exists` 里 `serial_no = serial_no` 两侧都来自 `tbtaparamc2tmp`，恒真，效果接近按 TA 删除后再插入。`C1_AFTER_C2=1` 的 insert 多一个条件：`seller_code` 必须等于 `tbsysarg.seller_code`（本行销售商）。

正式表 `tbtaparamc2` 主键是 `(serial_no, ta_code)`，临时表主键是 `(ta_code, serial_no)`。有增量脚本把正式表主键改成与临时表一致，避免 210202 死锁（`TB202609010799`）。

## 8. C1：基金基础参数

数据来源：`tbdxfundproductexp`，条件 `cfm_date = 系统日期 and ta_code = 当前 TA`。没有记录则不做。

总行机构：`select * from tbbranch order by branch_level` 取第一行 `branch_no`，作为新产品主办机构。

### 8.1 重跑回退

开启配置文件模式时，先回退本次会覆盖的「从 C1 导入」产品。识别条件：`tbdxfundproduct.model_flag='5'` 且产品代码出现在当日 `tbdxfundproductexp`。

按 TA 收窄后删除（避免按 `prd_code` 主键锁到其他 TA，`TB202609010799`）：

- `tbdxfundprdassign`
- `tbdxfundproductadd`
- `tbprdparamvalue`
- `tbdxfundproduct`（`ta_code=? and model_flag='5'`）

`model_flag='5'` 表示该产品是 C1 导入的，尚未在管理台转成正常产品。已转正的产品（`model_flag` 不是 5）不会被这步删除。

产品表删除可加索引 hint。参数 ID 是 `hint_DealTAParamFileFunc_idx_dxfundproduct`（常量 `T210202HintUtil.HINT_DEAL_TA_PARAM_IDX_DXFUNDPRODUCT`）。值为空则不加 hint；支持 `{hintTable}` 占位。

### 8.2 两条更新路径，由 `T210204_UPD_C1_FIELDS` 决定

默认 `0`：Java 逐条。`1`：读 `lcpt-config-210204.xml` 做集合更新。

#### 路径 A：配置文件（`T210204_UPD_C1_FIELDS=1`）

1. 可选「部分产品部分字段不更新」：配置项 `T210204_NO_UPD_C1_FIELDS` 的 `PrdCodes`、`FieldCodes`（逗号分隔）。更新前把这些产品当前字段值写入 `tbprdinfonotupdatefromc1file`，C1 更新后再写回，然后删掉暂存。需要现场已有该表。
2. 统计本次将新增的产品数：`tbdxfundproductexp` 中产品表不存在的记录。
3. 读配置名 `T210204`（即 `lcpt-config-210204.xml`）。MySQL 用标签 `tableItemC1ForMysql`，其他库用 `tableItemC1`。
4. 逐条标签生成 SQL：
   - `upType=0` update
   - `upType=1` Oracle/PG 用 `merge into`；MySQL 拆成「不存在则 insert」+「存在则 update」
   - `upType=2` insert
   - `upType=3` delete
5. 占位符：`${sysDate}`、`${taCode}`、`${branchCode}`、`${prevDate}`、`${controlFlag}`、`${nvl}`、`${subString}`、`${toChar}`。
6. `C1_NOT_UPD_EXISTS_PRD=1` 时，已存在产品不做 update；只有 insert 分支还执行。Oracle 上若既不更新又没有 insert 字段，整句 SQL 置空，避免 merge 语法错误（`T202511063888`）。
7. 新产品 `model_flag` 固定 `'5'`，模板 `0102`，`prd_type='0'`，`end_date=21000101`，`trans_way='1'`，`interest_way='0'`，`agio_type='1'`，募集期/开放期账务模式 `'0'`。
8. `DEFAULT_SPONSOR_TO_MANAGER=1` 时：`update tbdxfundproduct set prd_sponsor=prd_manager where model_flag='5' and ta_code=?`。
9. 对 `model_flag=5` 的产品，再按模板 `PrdInfoFormat` 填产品表、扩展表默认值。
10. 按 TA 刷新产品缓存、扩展缓存。

基线 XML 里已启用的 C1 项（Oracle `tableItemC1` 与 MySQL `tableItemC1ForMysql` 成对）：

| 目标表 | 行为 |
|--------|------|
| `tbdxfundproduct` | 已存在则更新币种、分红方式、成立日、面值、募集起止、个人/机构认申购限额、名称、管理人、发起人、托管人、份额类别等；不存在则按 0102 模板插入 |
| `tbdxfundproduct` | 用当日 `tbdxfundprddailytmp` 最新净值更新 `nav_date/nav/prd_status`（必须同时在当日 C1 里） |
| `tbdxfundprdassign` | 产品代码分配，模板 0102，主办机构为总行 |
| `tbprdparamvalue` | 按 0102 模板页面元素补默认参数，只插入不更新 |
| `tbprdparamvalue` | 更新已存在的 `curr_scale`（产品当前规模） |
| `tbdxfundproductadd` | 只插入 `prd_code`，不更新已有扩展字段 |

XML 里注释掉、需现场打开的：个人/机构单日累计购买上限 `daily_buy_pmaxvol` / `daily_buy_omaxvol`。打开前必须先改字段映射：

```sql
update tbfieldmap set sys_field='pdaily_buy_maxvol'
 where templet in ('ZD22','ZD21','ZD20') and file_type='C1' and idno=611;
update tbfieldmap set sys_field='odaily_buy_maxvol'
 where templet in ('ZD22','ZD21','ZD20') and file_type='C1' and idno=612;
```

同类还有 `idno=613/614` → `pdaily_red_maxvol` / `odaily_red_maxvol`（部分银行增量脚本已下发）。

#### 路径 B：Java 逐条（默认）

对每条 `DxFundProductExp`：

- 产品不存在：用模板 `0102` 的 `DxFundPrdInfoFormat` 填默认值，`copy` 临时表字段，强制：
  - `model_flag=5`
  - `end_date=21000101`
  - `agio_type=1`
  - `trans_way=1`
  - `interest_way=0`
  - `template_code=0102`
  - `prd_type` 空则基金 `0`
  - `liqu_mode_iss=0`、`liqu_mode_open=0`
  - `nav_date=系统日期`
  - `branch_no=总行`
  - 插入 `tbdxfundprdassign`、`tbdxfundproduct`、`tbdxfundproductadd`
  - 再 update 与路径 A 相同的那组限额/名称字段
  - 每新增一只就按 TA 刷一次缓存
- 产品已存在：`C1_NOT_UPD_EXISTS_PRD=0`（默认）时 update 同一组字段；`=1` 时已存在产品一行都不改。

`C1_UPD_SYNC_DATE=1`（系统级，不是分 TA）时，无论哪条路径，更新扩展表：

```sql
update tbdxfundproductadd
   set ta_sync_date=?,
       shelve_status=(case when shelve_status=' ' then '0' else shelve_status end)
 where prd_code=?
```

`ta_sync_date` 为系统日期。上架状态为空则置 `0`。

`copy` 从临时表拷到产品对象的字段包括：名称、净值、面值、发起人、托管人、管理人、募集起止、成立日、分红方式、份额类别、风险等级、币种、开闭市、认申购单位与限额、赎回/分红/退款/失败天数、渠道、控制标志等。产品模板写死 `0102`，C1 不带模板号，不能靠文件自动选其他模板。

## 9. C2：代理关系与交收天数

临时表进 `tbtaparamc2` 的规则见第 7 节。

`C2_SYNC_PRD_DAYS=1`（分 TA）且该 TA 的 `tbtaparamc2` 有记录时，回写产品：

| 产品字段 | 取值 |
|----------|------|
| `red_days` | `max(redemption_pay_period) - nav_days`，小于 0 则 0 |
| `refund_days` | 与 `red_days` 相同 |
| `div_days` | `max(dividend_pay_period)` |
| `fail_days` | `max(sub_pay_back_period)` |

同时删除并重插 `tbprdparamvalue`：`table_name=tbdxfundproduct`，`field_code=redemption_pay_period`，值为该产品 `max(redemption_pay_period)` 的字符串。

同一产品多条 C2（不同份额类别）取 `max`。没有 C2 记录则打日志「C2文件未上送，跳过」并不报错。

产品表 update 可加与 C1 相同的索引 hint。

C2 表主要字段：`serial_no, ta_code, prd_code, share_class, seller_code, branch_no, is_discount, buy_pay_period, redemption_pay_period, conversion_pay_period, sub_pay_back_period, dividend_pay_period, square_way, whole_flag, modify_way, effect_date, down_date, bank_no`。

`whole_flag`：`0` 增量，`1` 全量。当前 C2 进镜像表的实现不按 `whole_flag` / `modify_way` 做差异合并，而是按流水号覆盖后整批插入。

## 10. C3：转换关系

入口：`FormatTADayBeginFileFunc.chgLimitTmpToChgLimit`，只在 `IMP_C_MODE=0` 且 `FUND_LOAD_C_FILE=1` 时调用。

再读分 TA 参数 `DXFUND_LOAD_C3`，**默认 `1`（导入）**。设为 `0` 则跳过。这是 C3 独有的：总开关打开后，C3 默认处理，C4 默认不处理。

两条分支，由分 TA 参数 `FUND_INSERT_CHGLIMIT` 决定（默认 `0`）：

### 10.1 用 C3 文件（默认）

1. 删除临时表中目标产品在 `tbdxfundproduct` 不存在的行。
2. `targ_ta_code` 为空时，用目标产品的 `ta_code` 回填。
3. `delete from tbdxfundprdchglimit where ta_code=?`（该 TA 全删）。
4. 插入生效日 `effect_date <= 系统日期` 的临时表记录。字段：`download_date, prd_code, targ_prd_code, bank_no, share_class, targ_share_class, ta_code, targ_ta_code, min_vol, max_vol, allow_client_type`。

正式表主键：`(download_date, prd_code, targ_prd_code)`。

### 10.2 TA 不给 C3，系统自己生成（`FUND_INSERT_CHGLIMIT=1`）

先按 TA 清空 `tbdxfundprdchglimit`。

- 可转入：产品状态为交易（`CPZT_TRANS`），`conv_flag` 为双向或只可转入。
- 可转出：状态为交易，`conv_flag` 为双向或只可转出。
- 转出≠转入的组合都插入。`allow_client_type='2'`（个人机构都允许），`max_vol=9999999999999.00`，`download_date=系统日期`，转入转出 TA 都是当前 TA。

## 11. C4：分红方案

`DXFUND_LOAD_C4` 分 TA，**默认 `0`，不导入**。为 `1` 才处理。

现行逻辑（旧的按 `sequence_no` + `modify_way=2` 删除的代码已注释）：

2. 从 `tbtaparamc4tmp` 插入，且 `prd_code` 必须已在 `tbdxfundproduct`。

主要字段：`reg_date, div_date, xr_date, div_per_unit, bonus_unit, xr_value, xr_value_flag, xr_type, summary, whole_flag, modify_way, down_date`。

## 12. C5：费率

分三步，不要混：

| 步骤 | 条件 | 目标 |
|------|------|------|
| 镜像 | `FUND_LOAD_C_FILE=1` 且 `IMP_C_MODE=0` | `tbtaparamc5` |
| 标准费率表 | 再加 `DAY_BEGIN_IMP_CFILES` 含 `C5`，且 `IS_USE_ALLFEERATE_SET≠1` | `tbdxfundfeerate` |
| 全量费率表 | 同上，且 `IS_USE_ALLFEERATE_SET=1` | `tbdxfundallfeerate` |

只开 `FUND_LOAD_C_FILE`、不配 `DAY_BEGIN_IMP_CFILES`，费率只停在 `tbtaparamc5`，管理台产品费率看不到。

### 12.1 镜像表

按 `ta_code + serial_no` 删除后 `insert select *`。不看 `whole_flag`。

### 12.2 标准模式 `dealTAParamFileToTable`

临时表为空则日志后返回（注意：这里 `return` 会结束整个方法，不只是跳过 C5）。

预处理：

1. `T210204_C5_DISTINCT=1`（分 TA）：按 `prd_code, busin_code, capital_type, allow_client_type, amount_lower_limit, targ_prd_code` 分组，同组只留 `effect_date` 最大的一条，删掉其余。
2. `C5_NOT_UPD_EXISTS_PRD=2`：删除临时表中、`tbdxfundfeerate` 已有该产品费率的产品。等于「已维护过费率的产品整只跳过」。
3. `C5_NOT_UPD_EXISTS_PRD=1`：删除/插入费率时加 `model_flag='5'`，只动 C1 导入且未转正的产品。`0`（默认）更新所有产品。
4. 取临时表第一条的 `whole_flag` 作为整批标志：`1` 全量，否则增量。同一文件里如果混有不同 `whole_flag`，代码只看第一行。

筛选（金额档，`get_fee_rate_method=1`，`fee_rate_flag=0` 绝对费率）：

- 默认：`capital_type in (0,1,2,3,4,5,6)`，`busin_code` 必须在字典 `K_TAJY`。
- `ISAllowBusins=1` 时改用系统参数：
  - `AllowTransferBusins` 默认 `01,02,04`（认购、申购、转托管类；注释写明默认不含 `03` 赎回）
  - `AllowCapitalTypes` 默认 `0,1,2,4`
- `IMPC5_BYPRD=1`：产品扩展参数 `imp_c5=1` 才导入（`tbprdparamvalue.field_code='imp_c5'`）。

客户类型：

- `allow_client_type` 为 `0` 机构、`1` 个人：原样写入，`client_type` 用该值。
- 全部客户：模板 `ZD22` 用 `'9'`，其他模板用 `'2'`。拆成机构、个人各一条；已存在则不插（`not exists`）。
- 只有一边时，用已插入的 `tbdxfundfeerate` 补另一边（`client_type` 对调），费率金额沿用。

固定赋值：

- `seller_type='1'`（代销）
- `sub_mode='0'`
- `min_predays=0`、`min_hold_days=0`（金额档）
- `targ_prd_code` 匹配时空格
- `unit`：业务码 `03` 为 `3`（日），否则 `2`（元）；`unit_name` 对应「日」「元」
- 金额上下限来自 `amount_lower_limit` / `amount_upper_limit`

金额上限加工：

- `IS_C5ROUNDMAXAMT=1`：上限前 14 位不是 `99999999999999` 时 `round`
- `NEW_C5_MODE=1`：上限不是该哨兵值时 `+0.01`（避免区间衔接缺口）

全量（`whole_flag=1`）：先 `deleteC5WholeFeeRate`（JOIN 改写，降低死锁，`T202608121583`），再插入。删除范围受上面的业务码、`model_flag`、`imp_c5` 约束，不会无条件清空整表。

增量（`whole_flag≠1`）：`modify_way` 为 `0` 新增、`1` 修改、`2` 删除。三种都先按键删除代销（`seller_type=1`）和直销（`seller_type=0`）记录；只有 `0` 和 `1` 再插入。删除不插。

按天数再跑一遍（`get_fee_rate_method=2`）：

- 默认只处理 `busin_code=03` 且 `capital_type=0`（赎回交易费）。
- 金额区间写成 `0 ~ 9999999999`，天数用 `days_lower_limit` / `days_upper_limit`，预约天数 `0 ~ 999999999`。
- `IS_C5ROUNDMAXAMT=1` 或 `NEW_C5_MODE=1` 时，天数上限不是 `99999` 则 `+1`。
- 全量/增量、客户类型拆分与金额档相同。`T202604163195` 起，按天数补机构/个人时 `not exists` 用 `min_hold_days = days_lower_limit`，避免误判已存在。

### 12.3 新模式 `dealTAParamFileToTableNew`（`IS_USE_ALLFEERATE_SET=1`）

目标表 `tbdxfundallfeerate`，给「基金产品费率」新菜单用。

- 同样支持 `C5_NOT_UPD_EXISTS_PRD=2` 先删临时表、`=1` 只动 `model_flag=5`。
- 业务码固定 `01,02,03`，写入时映射：`01→120`，`02→122`，`03→124`，`capital_type=7` → `124_7`。
- 资金类型只收 `0` 和 `7`。
- `fee_rate_flag=0`。不再限制 `get_fee_rate_method=1`。
- `days_upper_limit>0` 则 `fee_mode=2`（按天，单位天），否则 `fee_mode=1`（按金额，单位万元）。
- `start_date=effect_date`，`reserve1=系统日期`，`reserve2=capital_type`。
- 全量：先删该 TA、业务码 `120/122/124`、且本次临时表有的产品，再插入。
- 增量：按 `modify_way` 先删后插，逻辑与标准模式同类。

## 15. 管理台如何开通

类：`TaInfoSetService`（基金 TA 信息设置）。勾选文件类型后执行 `tbdxfundsqlscript` 里预置 SQL（`${TA_CODE}`、`${TA_NAME}` 替换），并按公募/私募（`tbtainfo.private_placement`，空当公募）过滤 `reserve1`。

若勾选列表含 C1、C2、C3、C4、C5 之一，额外：

```sql
insert into tbfiletype(..., file_dir, ...)
values (?, '00', 'OFC_SSS_RRR_YYYYMMDD.TXT', '3', ...);  -- 参数索引

delete from tbparam where ta_code=? and param_id in ('FUND_LOAD_C_FILE','IMP_C_MODE');
-- FUND_LOAD_C_FILE = 1
-- IMP_C_MODE = 0   （日启）
```

各 C 类的 `tbfiletype` 行（表名、文件名规则）来自 `tbdxfundsqlscript`，不是这段 Java 硬编码。Java 只保证索引文件和两个参数。

现场手工脚本可参考昆仑银行增量：

`spsql/spsql-dxfund/IFMS6.0V202607.03.000/pub/dxfund/IFMS6.0V202607.03.000-BANK-klyh.sql`

其中 C1～C5 的 `file_dir=3`、`area_type=0`；C6 的 `file_dir=0`。注释写明：C 类要选支持，且增值模块已下发。

## 17. 夜间清算和 C 类的关系

参数 `PRD_DAILY_IMP_MODE=1` 才启用夜间导入。

- 210203 / 210204：夜间 210886 已成功且当日已有行情时，可以不重复取/导 `file_dir=1`。`file_dir=3` 的 C 类不受这个跳过影响，`IMP_C_MODE=0` 时日启仍取、仍导。
- 若日启方向里还有夜间没配的文件类型，则日启方向也不跳过。
- 210202：夜间标志只跳过 07 行情汇总，**不跳过**后面的 C 类。带 `NightClearFlag=1` 的夜间任务本身在 C 类之前 return。
- 第三方行情（`tbdxfundnightclear.use_flag=1`，如同花顺）不算「夜间已处理」，日启仍覆盖。

## 22. 明确不是 C 类的相邻逻辑

同一节点、同一类里还有这些，整理参数同步时不要算进去：

- **07 行情**：`file_dir=1`，临时表 `tbdxfundprddailytmp` / `tbdxfundprddailyexttmp`，正式表 `tbdxfundprddaily`。可按 XML `tableItem07` 更新限额、分红方式、募集期。参数包括是否更新 `conv_flag`、七日年化、定投状态、暂停申购是否允许定投等。
- **F1/F7/F10/F11/F15/F18/F19**：`DealTAParamFileFunc` 里有对应方法，属于理财/分销非标或收益率文件，基金 C 类主流程 `dealTAParamFile` **不会调用**它们。

## 23. 现场核对清单

1. `tbfiletype`：该 TA 是否有 `file_dir=3` 的 `00` 索引，以及 C1～C5 的 `table_name` 是否与第 2 节一致；C6 的 `file_dir` 是 `0` 还是 `3`。
2. `tbtainfo.templet` 与 `tbfieldmap` 是否成套（ZD20/ZD21/ZD22）。单日购买上限若要进扩展参数，先改 `idno=611/612`。
3. `tbparam`：该 TA 的 `FUND_LOAD_C_FILE`、`IMP_C_MODE`。只灌临时表不进产品，多半是后者不是 `0` 或前者不是 `1`。
4. 费率要出现在管理台：`DAY_BEGIN_IMP_CFILES` 含 `C5`，并确认走 `tbdxfundfeerate` 还是 `tbdxfundallfeerate`。
5. 已上线产品被 C1 改掉属性：看 `C1_NOT_UPD_EXISTS_PRD` 和 `model_flag`。`5` 表示仍视为 C1 导入产品，重跑会被回退再导入。
6. 转换关系为空：看 `DXFUND_LOAD_C3`、目标产品是否已存在、`effect_date` 是否小于等于当天。
7. 分红方案查询空：`DXFUND_LOAD_C4` 默认关，且只写 `tbtaparamc4`。
8. 调度顺序必须是 210203 → 210204 → 210202，且都在公共片区 `lcpt-dxfund-pub-batch`。
