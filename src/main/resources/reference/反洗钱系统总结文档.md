# 反洗钱系统总结文档

## 1. 概述

反洗钱（AML - Anti-Money Laundering）系统是基金销售系统的重要组成部分，用于满足监管机构对客户身份识别和可疑交易监控的要求。系统通过文件接口与中登（中国证券登记结算有限责任公司）进行数据交互，实现反洗钱信息的申请导出和确认导入。

## 2. 文件交互背景

### 2.1 业务背景

根据《金融机构反洗钱规定》和《金融机构客户身份识别和客户身份资料及交易记录保存管理办法》等法规要求，金融机构需要：

1. **客户身份识别**：对客户进行身份识别，收集并保存客户身份信息
2. **持续监控**：对客户交易进行持续监控，识别可疑交易
3. **信息报送**：向监管机构报送反洗钱相关信息
4. **数据交互**：与中登等机构进行反洗钱数据交互

### 2.2 文件交互流程

系统通过文件接口与中登进行反洗钱数据交互，主要包括：

- **申请文件导出**：系统将客户反洗钱信息导出为文件，发送给中登
- **确认文件导入**：中登处理后将确认结果文件返回，系统导入确认结果

## 3. 文件类型与表结构

### 3.1 文件类型定义

系统定义了以下反洗钱相关文件类型：

| 文件类型 | 文件名称规则 | 文件方向 | 目标表 | 说明 |
|---------|------------|---------|--------|------|
| **X1** | OFD_SSS_RRR_YYYYMMDD_TT.TXT | 导出(2) | tbamlperinfoexp | 个人反洗钱信息导出 |
| **X2** | OFD_SSS_RRR_YYYYMMDD_TT.TXT | 导入(0) | tbamlperinfocfmtmp | 个人反洗钱信息确认 |
| **X3** | OFD_SSS_RRR_YYYYMMDD_TT.TXT | 导出(2) | tbamlinstinfoexp | 机构反洗钱信息导出 |
| **X4** | OFD_SSS_RRR_YYYYMMDD_TT.TXT | 导入(0) | tbamlinstinfocfmtmp | 机构反洗钱信息确认 |
| **0X** | OFX_SSS_RRR_YYYYMMDD.TXT | 双向 | - | 反洗钱申请数据与业务索引文件 |

**说明：**
- 文件方向：`2` 表示导出（系统→中登），`0` 表示导入（中登→系统）
- 文件名称规则中的占位符：
  - `SSS`: 销售商代码
  - `RRR`: 接收方代码
  - `YYYYMMDD`: 日期
  - `TT`: 文件类型

## 4. 文件映射关系

### 4.1 字段映射查询

使用以下SQL可以查询反洗钱申请文件（X1类型）与系统表的字段映射关系：

```sql
select b.*,a.sys_field,a.key_no,a.field_no 
from tbfieldmap a, tbtadict b 
where a.templet = 'ZD22' 
  and a.file_type = 'X1' 
  and a.templet = b.templet 
  and a.idno = b.idno 
order by a.field_no asc
```

**说明：**
- `tbfieldmap`: 字段映射表，定义文件字段与系统字段的对应关系
- `tbtadict`: TA字典表，定义字段的字典信息
- `templet = 'ZD22'`: 使用ZD22模板
- `file_type = 'X1'`: 个人反洗钱信息导出文件

### 4.2 映射表结构

- **tbfieldmap**: 字段映射表
  - `templet`: 模板代码（ZD22）
  - `file_type`: 文件类型（X1/X2/X3/X4）
  - `idno`: 字段序号
  - `sys_field`: 系统字段名
  - `key_no`: 关键字段标识
  - `field_no`: 文件字段序号

- **tbtadict**: TA字典表
  - `templet`: 模板代码
  - `idno`: 字段序号
  - `field_name`: 字段名称
  - `field_type`: 字段类型
  - `field_length`: 字段长度

## 6. 业务流程与代码实现

### 6.1 反洗钱申请文件导出流程

#### 6.1.1 导出节点说明

反洗钱信息导出在**申请数据导出节点（210012）**中处理，该节点分为两个片区：

- **公共片区（211012）**：`T211012HSAdapter.java`
  - 路径：`F:\Sources\app\lcpt-server\sale\lcpt-dxfund\lcpt-dxfund-pub\lcpt-dxfund-pub-batch-bootstrap\src\main\java\com\hundsun\lcpt\dxfund\pub\batch\adapter\T210012\T211012HSAdapter.java`
  - **包含反洗钱信息导出逻辑**：在`action()`方法中调用`amlToExp()`方法处理反洗钱信息导出
  - 处理公共区的账户申请数据导出和反洗钱信息导出

- **交易片区（210012）**：`T210012HSAdapter.java`
  - 路径：`F:\Sources\app\lcpt-server\sale\lcpt-dxfund\lcpt-dxfund-trans\lcpt-dxfund-batch-bootstrap\src\main\java\com\hundsun\lcpt\dxfund\batch\adapter\T210012\T210012HSAdapter.java`
  - **不包含反洗钱信息导出逻辑**：该节点只处理交易类申请数据导出（`transReqToExp()`方法），不处理反洗钱信息导出
  - 处理交易区的交易申请数据导出（购买、赎回等交易流水）

**重要说明**：
- 反洗钱信息导出**仅在公共片区（211012）**处理
- 交易片区（210012）只负责交易类申请的导出，不涉及反洗钱信息
- 反洗钱信息属于账户类申请，统一在公共片区处理

#### 6.1.2 导出处理逻辑（amlToExp方法）

**处理入口**：`T211012HSAdapter.amlToExp()` 方法

**处理步骤**：

1. **清空导出表**
   ```java
   session.execute("delete from tbamlperinfoexp where ta_code=? and bank_no=? ", taCode, sysArg.getBankNo());
   session.execute("delete from tbamlinstinfoexp where ta_code=? and bank_no=? ", taCode, sysArg.getBankNo());
   ```

2. **自动补充AccReq流水（100846交易码）**
   - 新开户自动补充：当日新开户（110100/110102）且存在反洗钱信息（tbclientaml.status='1'）的客户，自动插入一条100846流水
   - 客户信息修改自动补充：当日客户信息修改（100104）且存在反洗钱信息的客户，自动插入一条100846流水
   - 客户信息补录自动补充：当日客户信息补录（100704）且存在反洗钱信息的客户，自动插入一条100846流水
   - 首次自动补充：如果参数`AML_ADD_FIRST_FLAG`开启，且从未导出过反洗钱信息，自动为所有已开户且有反洗钱信息的客户补充100846流水

3. **数据插入到导出表**

   **个人反洗钱信息（tbamlperinfoexp）插入逻辑**：
   - 从AccReq表查询：`trans_code='100846'` 且 `status in ('1','5')` 且 `client_type='1'`（个人）
   - 关联查询以下表获取数据：
     - `tbclient{tableNum}`：客户基本信息（姓名、证件类型、证件号码、证件有效期、性别、出生日期等）
     - `tbclientseller{tableNum}`：销售商信息（手机、电话、单位电话、邮箱、传真、邮编、地址等）
     - `tbclientadd{tableNum}`：客户附加信息（国籍、职业、年收入、地址信息等）
     - `tbclientaml{tableNum}`：反洗钱信息（风险等级、特定自然人标识等）

### 13.3 校验规则

#### 13.3.1 反洗钱信息完整性校验（checkAmlCompletePub）

**校验逻辑**：
1. 查询客户反洗钱信息：`clientAmlDao.getClientAml(inClientNo, bankNo)`
2. 判断反洗钱信息是否存在且状态允许：
   - 如果`clientAml == null`，抛出异常
   - 如果`clientAml.status`不在允许状态列表中，抛出异常

**允许状态配置**：
- **参数ID**: `AML_ALLOW_STATUS`
- **说明**: 允许交易的反洗钱状态列表
- **默认值**: `1`（表示`status='1'`才允许交易）
- **取值**: 状态值列表，如`1`、`15`等

**错误提示**：
- **参数ID**: `AML_CHECK_INFO`
- **说明**: 反洗钱信息校验未通过的提示信息
- **默认值**: `应监管反洗钱加强身份识别工作要求，请您补录反洗钱身份信息`

#### 13.3.2 证件有效期校验（checkCodeExp）

**校验规则**：

1. **证件有效期缺失校验**
   - 如果`client.getIdCodeDate() == 0`或为空，抛出异常
   - **错误提示参数**: `AML_ICDATE_NULL_MSG`
   - **默认值**: `证件有效期缺失`

2. **证件有效期过期校验**
   - 计算证件有效期剩余天数：`剩余天数 = 证件有效期 - 当前日期`
   - 如果`当前日期 > (证件有效期 + 宽限天数)`，抛出异常
   - **宽限天数参数**: `AML_STOP_BUY_DAYS`
   - **默认值**: `0`
   - **错误提示参数**: `AML_ICDATE_EXP_MSG`
   - **默认值**: `证件有效期已过期，请更新证件`

3. **证件有效期即将到期提醒**
   - 如果`剩余天数 >= 0 && 剩余天数 <= 预警天数`，在请求中设置`ExpireDays`字段
   - **预警天数参数**: `ID_CODE_EXPIRE_DAYS`
   - **默认值**: `-1`（不预警）
   - **校验模式参数**: `AML_ICDATE_CK_MOD`
   - **说明**: 是否使用系统日期进行校验（`Y`-使用系统日期，`N`-使用业务日期）
   - **默认值**: `N`

#### 13.3.3 九要素校验（checkNineElements）

**前置条件**：
- **参数ID**: `REALBUY_CHECK_AML_FLAG`（按TA代码配置）
- **说明**: 是否启用购买反洗钱九要素校验
- **取值**: `0` - 否，`1` - 是
- **默认值**: `0`
- **校验范围**: 仅对个人客户（`ClientType='1'`）进行校验

**校验规则**：

1. **客户姓名校验**
   - 不能为空或`NULL`
   - 不能包含特殊字符（`?!$*！？`等，可配置）
   - 不能包含阿拉伯数字（可配置）
   - 身份证类型时，至少包含两个汉字（可配置）
   - **参数配置**:
     - `AML9ELEMENTS_CLIENTNAME_OF_SPECIALCHARS`: 特殊字符正则表达式
     - `AML9ELEMENTS_CLIENTNAME_OF_NUMBER`: 数字正则表达式
     - `AML9ELEMENTS_CLIENTNAME_OF_CHARACTERSNUM`: 汉字数量正则表达式
     - `CHECK_CLIENT_NAME_LENGTH_FORBID`: 是否校验姓名长度（`Y`-校验，`N`-不校验）

2. **证件类型和证件号码校验**
   - 证件类型为"其他"时，证件号不能以`AA`或`BB`开头
   - 身份证类型时，证件号必须为18位

3. **性别校验**（仅身份证）
   - 根据身份证倒数第二位判断性别（单数-男，双数-女）
   - 与上送的性别字段必须一致

4. **国籍校验**（仅身份证）
   - 身份证类型时，国籍必须为中国（`156`或`CHN`）
   - **参数配置**: `AML9ELEMENTS_NATIONALITY_OF_SPECIALCHARS`
   - **默认值**: `(156|CHN)`

5. **手机号码校验**
   - 如果上送手机号码，必须符合运营商号段规则
   - **参数配置**: `AML9ELEMENTS_MOBILE_OF_NUMBER`
   - **默认值**: `^1(3[0-9]|4[01456879]|5[0-35-9]|6[2567]|7[0-8]|8[0-9]|9[0-35-9])\\d{8}$`

6. **联系电话校验**
   - 如果上送联系电话，不能全为相同字符
   - **参数配置**: `AML9ELEMENTS_TEL_OF_NUMBER`
   - **默认值**: `^(.)\\1*$`（全相同字符）

7. **证件有效期校验**
   - 长期有效日期必须录入`99991231`
   - 证件有效期7日内到期，不允许交易
   - 根据年龄限制证件有效期：
     - 16周岁以下：不超过5年
     - 16-25周岁：不超过10年
     - 26-45周岁：不超过20年
     - 46周岁及以上：不超过20年或长期有效
   - 护照或港澳通行证：不允许长期有效

8. **地址校验**
   - 地址必须包含至少6个汉字
   - **参数配置**: `AML9ELEMENTS_ADDRESS_OF_CHARS`
   - **默认值**: 至少6个汉字的正则表达式
   - **错误提示参数**: `AML_CHECK_ADDRESS_ERROR_MSG`
   - **默认值**: `九要素校验错误：输入的地址有误，需要包含至少6个汉字`

**数据来源配置**：
- **参数ID**: `FINATRANS_CHEKNINE_BYLOCAL`
- **说明**: 购买反洗钱字段校验是否从本地表获取
- **取值**: `0` - 否（从请求获取），`1` - 是（从本地表获取）
- **默认值**: `0`
- **说明**: 如果为`1`，系统会从`tbclient`、`tbclientadd`、`tbclientseller`表中获取字段值进行校验

### 13.4 渠道控制校验

**参数ID**: `T110200_CTRL_AML_BY_CHANNELS`
- **说明**: 按渠道控制110200交易是否校验反洗钱
- **取值**: 渠道代码列表，用逗号分隔
- **默认值**: 空（所有渠道都校验）
- **校验逻辑**: 
  - 如果参数不为空且当前渠道不在列表中，则进行校验
  - 如果参数为空或当前渠道在列表中，则不校验

### 13.5 调用流程图

```
┌─────────────────────────────────────────────────────────────┐
│              基金购买开户反洗钱完整性校验流程                    │

      ├─ 证件有效期校验

```

## 14. 总结

反洗钱系统通过文件接口与中登进行数据交互，实现了完整的反洗钱信息管理和监管报送功能。

### 14.1 核心功能

1. **个人和机构客户区分**: 通过不同的文件类型（X1/X2 和 X3/X4）分别处理个人和机构客户的反洗钱信息
2. **申请和确认流程**: 通过导出和导入文件实现申请和确认的完整流程
3. **字段映射机制**: 通过 `tbfieldmap` 和 `tbtadict` 实现文件字段与系统字段的灵活映射
4. **配置化管理**: 通过参数配置控制反洗钱功能的启用和具体行为
5. **完整性校验**: 在基金购买开户时进行严格的反洗钱信息完整性校验，确保客户信息的完整性和准确性

### 14.2 反洗钱信息（tbclientaml）插入来源

反洗钱信息的插入主要通过以下途径实现：

#### (1) 在线交易场景
- **100001签约**：客户首次开户时录入反洗钱信息
- **100846反洗钱信息登记**：专门用于反洗钱信息登记和补录
- **100704客户信息补录**：开户后补录反洗钱信息
- **100104客户信息修改**：机构客户信息修改时更新反洗钱信息（银行定制）

#### (2) 批量任务场景
- **200604批量补录**：批量导入客户信息时插入反洗钱信息
- **银行定制批量任务**：如DBS、北京银行等银行的定制化批量任务
- **审批管理服务**：审批通过后插入反洗钱信息

#### (3) 多法人场景
- **统一签约自动复制**：客户在新法人行签约时，自动从其他法人行复制反洗钱信息

#### (4) 其他场景
- **产品投资账户服务**：产品投资账户开立时插入
- **银行定制化服务**：各银行对标准交易的定制化实现（如南京银行对100846的定制实现等）

#### (5) 统一插入方法
所有插入最终都通过`ClientAmlDao.addClientAml()`方法执行，确保了：
- 统一的数据格式化处理
- 统一的分表策略（根据客户编号哈希到16个分表）
- 统一的多法人支持（通过`bank_no`字段）

### 14.3 数据流转路径

```
【数据录入】
  前端录入/核心查询/文件导入/跨法人复制
    ↓
【在线交易/批量任务】
  100001/100846/100704/100104/200604等
    ↓
【插入数据库】
  ClientAmlDao.addClientAml()
    ↓
  tbclientaml{1-16}（分表存储）
  tbamlcontroller{1-16}（控制人）
  tbamlbenefinfo{1-16}（受益人）
    ↓
【导出到中登】
  210012节点 → amlToExp()
    ↓
  查询tbclientaml等表
    ↓
  插入tbamlperinfoexp/tbamlinstinfoexp
    ↓
  生成X1/X3文件 → 发送中登
    ↓
【确认处理】
  中登返回X2/X4文件
    ↓
  插入tbamlperinfocfmtmp/tbamlinstinfocfmtmp
    ↓
  更新业务状态
```

### 14.4 系统设计亮点

1. **多数据源支持**: 支持前端录入、核心系统查询、文件导入、跨法人复制等多种数据来源
2. **分表存储**: 通过16个分表提高查询和插入性能
3. **多法人支持**: 通过`bank_no`字段支持多法人模式
4. **统一入口**: 所有插入通过统一的DAO方法，便于维护和扩展
5. **银行定制化**: 支持各银行的定制化需求，灵活适配不同业务场景
6. **关联数据管理**: 统一管理反洗钱主信息、控制人信息、受益人信息
7. **状态管理**: 通过状态字段（`status`）管理反洗钱信息的生命周期
8. **完整性校验**: 在交易过程中进行多层次的完整性校验，确保数据质量

### 14.5 监管合规

系统设计充分考虑了监管要求和实际业务需求：
- 符合《金融机构反洗钱规定》要求
- 支持九要素完整性校验
- 支持证件有效期管理
- 支持风险等级评估
- 支持异常客户名单管理
- 支持与中登的数据交互

系统通过完善的反洗钱信息管理机制，为金融机构履行反洗钱义务提供了可靠的技术支持。
