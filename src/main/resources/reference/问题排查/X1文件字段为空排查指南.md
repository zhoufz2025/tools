# X1 文件字段为空排查指南

> 适用场景：生产 / 测试环境 X1 文件中某个（或多个）字段值全部为空。  
> 子系统：基金代销（主述）、资管代销、信托代销（结构同类）。  
> 关键代码：基金 `T211012HSAdapter`；资管 `T2B1012HSAdapter`；信托 `T271012HSAdapter`；写文件 `TaFileWriter`。

---

## 1. 背景说明

X1 是**个人反洗钱信息**上报文件，中间表为 `tbamlperinfoexp`。

生产、测试同时为空时，优先怀疑**配置 / 取数链路**问题（同脚本、同逻辑），而不是单环境偶发数据问题。

### 1.1 数据链路

```
客户源表（tbclient / tbclientseller / tbclientadd / tbclientaml 等）
    ↓ 导出节点灌数（211012 / 2B1012 / 271012）
tbamlperinfoexp（个人反洗钱导出表）
    ↓ TaFileWriter + tbfieldmap
X1 文件
```

| 子系统 | 导出节点 | 中间表 | 参数 |
|--------|----------|--------|------|
| 基金 | `T211012` | `tbamlperinfoexp` | `AML_X1X3_INTERFACE=1` 才走 X1/X3 |
| 资管 | `T2B1012` | 同上 | 同上 |
| 信托 | `T271012` | 同上 | 同上 |

---

## 2. 排查前先钉死三项

| 项 | 说明 |
|----|------|
| TA 代码 | 如某个基金公司 / 管理人代码 |
| 接口模板 | `tbtainfo.templet`，如 `SY22` |
| 空字段定位 | 文件中的 `field_no`（序号）或字段中文名 / `sys_field` |

三项不全时，容易查错映射行。

---

## 3. 排查步骤（从文件往源头追）

### 步骤 A：查字段映射（最常见）

```sql
-- 该 TA 用哪个模板
select ta_code, templet from tbtainfo where ta_code = '你的TA';

-- X1 字段映射
select templet, file_type, idno, field_no, sys_field, key_no
  from tbfieldmap
 where templet = '模板'
   and file_type = 'X1'
 order by field_no;

-- 文件类型定义（目标表一般是 tbamlperinfoexp）
select * from tbfiletype
 where file_type = 'X1'
   and (ta_code = '你的TA' or ta_code = '%TACODE%');
```

重点看空字段那一行的 `sys_field`：

| `sys_field` 情况 | 含义 |
|------------------|------|
| `SNULL` | 代码故意写空，属配置问题，不是业务数据空 |
| 某个列名（如 `address`、`vocation`） | 继续查导出表该列有没有值 |
| 列名与 `tbamlperinfoexp` 对不上 | 写出也会空 |

### 步骤 B：查导出中间表（一锤定音）

导出节点跑完后立刻查（测试可重跑节点）：

```sql
select count(*) from tbamlperinfoexp
 where ta_code = '你的TA' and bank_no = '银行号';

-- 把「空字段」换成实际列名
select serial_no, in_client_no, client_name,
       address, vocation, mobile, aml_risk
  from tbamlperinfoexp
 where ta_code = '你的TA'
   and bank_no = '银行号';
```

| 中间表 | 文件 | 结论 |
|--------|------|------|
| 该列已有值 | 文件仍空 | 映射 / `SNULL` / 写文件逻辑问题 |
| 该列也是空 | 文件空 | 灌数 SQL 没取到，或源表就空 |
| 中间表没记录 | 文件无数据或空壳 | 导出条件 / 参数 / 账户类流水问题 |

### 步骤 C：顺着 insert 反查源表

基金侧灌数在 `T211012HSAdapter`：从 `tbaccreq*` + `tbclient*` + `tbclientseller*` + `tbclientadd*` + `tbclientaml*` 拼进 `tbamlperinfoexp`。

详见 **第 4 节「插入字段来源全表」**。

快速反查示例（按空字段选表）：

```sql
-- 示例：若空的是通讯/现居地址相关
-- a=申请流水 b=客户 c=渠道客户 d=客户附加 e=反洗钱
select a.in_client_no, b.client_name,
       d.adrsta, d.adrcty, d.adrsec, e.address, e.present_nation
  from tbaccreq1 a
  left join tbclient1 b on a.in_client_no = b.in_client_no
  left join tbclientseller1 c on a.in_client_no = c.in_client_no and a.bank_no = c.bank_no
  left join tbclientadd1 d on a.in_client_no = d.in_client_no and a.bank_no = d.bank_no
  left join tbclientaml1 e on a.in_client_no = e.in_client_no and a.bank_no = e.bank_no
 where a.ta_code = '你的TA'
   and a.trans_code = '100846'
   and a.status in ('1','5');  -- 以代码实际状态为准：处理中/导出
```

| 现象 | 方向 |
|------|------|
| 源表也空 | 补录 / 开户 / 100846 未落库 |
| 源表有值、exp 空 | 看 insert/update SQL（join、case when、NVL） |
| 需字典转换 | 查 `tbdictmap`（证件类型 `K_ZJLX`、国籍 `K_GJ` 等） |

### 步骤 D：参数与节点是否真导出

```sql
select * from tbparam
 where param_id = 'AML_X1X3_INTERFACE'
   and (ta_code = '你的TA' or ta_code = '000000');
```

再看当日调度：对应 `211012` / `2B1012` / `271012` 是否成功；日志里有无写 X1、`amlWritedDataFileList` 相关信息。

## 4. 插入 `tbamlperinfoexp` 字段来源（基金 T211012）

> 资管 `T2B1012`、信托 `T271012` 结构同类；开户交易码不同（信托侧多为 `170100`/`170102`，基金为 `110100`/`110102`）。

### 4.1 Join 别名

| 别名 | 表 | 说明 |
|------|-----|------|
| **a** | `tbaccreq{N}` | 账户申请流水；条件：`trans_code='100846'`、个人客户、状态处理中/导出 |
| **b** | `tbclient{N}` | 客户主信息 |
| **c** | `tbclientseller{N}` | 渠道客户信息（手机/电话/邮箱等） |
| **d** | `tbclientadd{N}` | 客户附加信息（国籍/职业/地址省市区/代理人等） |
| **e** | `tbclientaml{N}` | 反洗钱信息（现居国/公司/风险等级等） |

`{N}` 为分表号。

### 4.2 插入时各字段来源

| exp 字段 | 来源 | 取数 / 拼装说明 |
|----------|------|-----------------|
| `serial_no` | **a** | `a.serial_no`（100846 流水号） |
| `trans_date` | **a** | `a.trans_date` |
| `trans_time` | **a** | `a.trans_time` |
| `seller_code` | **a** | `a.seller_code` |
| `branch_no` | **a** | `a.branch_no` |
| `in_client_no` | **a** | `a.in_client_no` |
| `client_type` | **a** | `a.client_type` |
| `ta_code` | **a** | `a.ta_code` |
| `asset_acc` | **a** → 后补 | 先取 `a.asset_acc`；为空时再 update 从理财账号临时表补 |
| `ta_client` | 固定 | 插入为 `' '`（空格） |
| `asso_serial` | **a** | `a.serial_no`（与本笔流水关联） |
| `ori_trans_date` | 固定 → 后补 | 插入为 `0`；无理财账号时再从开户流水回填 |
| `ori_serial_no` | 固定 → 后补 | 插入为 `' '`；同上从开户流水回填 |
| `client_name` | **b** | `b.client_name` |
| `id_type` | **b** | `b.id_type` |
| `id_code` | **b** | `b.id_code` |
| `id_code_date` | **b** | `b.id_code_date` |
| `sex` | **b** | `b.sex` |
| `birthday` | **b** | `b.birthday` |
| `nationality` | **d** | `d.nationality` |
| `vocation` | **d** | `d.vocation` |
| `mobile` | **c** + **e** | `e.mobint` + `\|` + `c.mobile`；`c.mobile` 空则只出 `\|` |
| `tel` | **c** + **e** | `e.telint` + `\|` + 区号/号码（`-` 转 `\|`）；`c.tel` 空则 `\|\|` |
| `company_tel` | **e** | `e.company_telint` + `\|` + `e.company_tel`；空则 `\|\|` |
| `email` | **c** | `c.email` |
| `fax` | **c** + **e** | `e.telint` + `\|` + `c.fax`（格式同电话）；空则 `\|\|` |
| `post_code` | **c** | `c.post_code` |
| `annual_income` | **d** | `NVL(ltrim(d.annual_income),'0')` |
| `present_nation` | **e** | `e.present_nation` |
| `address` | **d** + **e** | `d.adrsta\|adrcty\|adrsec\|e.address`；省为空则 `\|\|\|` |
| `reg_nation` | **e** | `e.reg_nation` |
| `reg_address` | **e** | `e.reg_adrsta\|reg_adrcty\|reg_adrsec\|reg_adrdet`；省为空则 `\|\|\|` |
| `company` | **e** | `e.company` |
| `is_natural` | **e** | `e.is_natural` |
| `asso_info` | **d**+**e** → 后补 | 插入时先拼代理人；再追加控制人/受益人（见 4.3） |
| `aml_risk` | **e** | `e.aml_risk` |
| `add_flag` | 固定 | `' '` |
| `reserve1`~`4` | 固定 | `' '` |
| `bank_no` | **a** | `a.bank_no` |

### 4.3 插入后还会改的字段

| 字段 | 后续动作 |
|------|----------|
| `asset_acc` | 仍为空时，从 `tbassetacc` 临时/备份表按 `in_client_no+ta_code+bank_no` 取 `max(asset_acc)` |
| `ori_trans_date` / `ori_serial_no` | 仍无理财账号时，从同客户 `110100`/`110102` 且状态为处理中/导出的流水回填 |
| `asso_info` | ① 插入：有代理人则拼 `0\|代理人信息\|#END#\|`（证件类型/国籍走 `tbdictmap`）② 再拼控制人 `tbamlcontroller`（类型 `1\|…`）③ 再拼受益人 `tbamlbenefinfo`；总长截断到 500 |

### 4.4 字段空了怎么反查（按表）

| 空字段类型 | 优先查 |
|------------|--------|
| 姓名/证件/性别/生日 | `tbclient` |
| 手机/固话/邮箱/邮编/传真 | `tbclientseller`（区号在 `tbclientaml` 的 `*int`） |
| 国籍/职业/年收入/现居省市区/代理人 | `tbclientadd` |
| 现居国/注册国址/单位/是否自然人/风险等级/单位电话 | `tbclientaml` |
| 流水号、日期、销售商、TA、银行号 | `tbaccreq`（`100846`） |
| 理财账号、原开户流水 | 插入后 update；查资产账号表 + `110100/110102` |
| 关联人整段 | `tbclientadd` 代理人 + `tbamlcontroller` + `tbamlbenefinfo` + `tbdictmap` |

### 4.5 示例：某客户 `address` 为空

1. 看 exp：`select address from tbamlperinfoexp where in_client_no=…`
2. 看源：`tbclientadd.adrsta/adrcty/adrsec` 与 `tbclientaml.address`
3. 若 `adrsta` 为空，代码会直接写成 `|||`（占位格式，不是完整业务地址）

详见下一节：省市区字段何时写入、各交易应上送哪些请求字段。

## 5. `tbclientadd.adrsta/adrcty/adrsec` 为空专项说明

这三个字段是**现居地址的省 / 市 / 区（县）行政区划代码**，落在 `tbclientadd`。  
**X1 导出只读、不写**；若表里为空，说明签约或补录从未带上有效值。

### 5.1 字段含义与落库对照

| 库字段 | 含义 | 请求 Tag | 值格式 |
|--------|------|----------|--------|
| `adrsta` | 省（自治区/直辖市） | `Adrsta` | 通常 **6 位行政区划代码**（如浙江 `330000`） |
| `adrcty` | 市（地区/州） | `Adrcty` | 6 位代码（如杭州 `330100`） |
| `adrsec` | 区/县 | `Adrsec` | 6 位代码（如西湖区 `330106`） |

配套详细地址（拼进 X1 `address` 末段）在 **`tbclientaml.address`**，对应请求 Tag **`Adrdet`**，不要和省市区混在一张表里查。

特殊省代码（港澳台等，市可不强制）：`660000`、`710000`、`810000`、`820000`。  
中国现居国代码默认 `156`（参数 `CNN_NATION_CODE` 可配）。

> 勿与通讯地址 `CommAdrsta` / `CommAdrcty` / `CommAdrsec` 混淆：那组字段进 **`tbclientseller`**，**不会**写入 `tbclientadd.adrsta` 等，也**不会**参与 X1 的 `d.adrsta|adrcty|adrsec` 拼接。

### 5.2 什么时候插入 / 更新

| 时机 | 交易 | 行为 |
|------|------|------|
| 签约建客 | **100001** | 写 `tbclientadd`：`Adrsta` 直接落库；`Adrcty`/`Adrsec` **非空才写** |
| 开户类 | 100A15 等 | 同签约逻辑，请求带省市区则写入 |
| 客户信息变更 | **100104** | 请求上送对应 Tag 且**非空**时才更新 |
| 反洗钱补录 | **100846** | 按请求 `Adrsta`/`Adrcty`/`Adrsec` 更新（与 X1 最相关） |
| 适当性/反洗钱补录 | 100704 | 扩展信息开启时更新；**不送会写成空格** |
| 核心反洗钱文件批量导入 | 200604 → 组请求调补录联机 | 临时表有值才塞进请求，最终仍落到补录逻辑 |
| 管理台维护 | 机构反洗钱等相关 Service | 管理台改客户/反洗钱信息时回写 |

底层均为 `ClientAddDao` insert/update。

### 5.3 各交易应上送的请求字段（值约定）

以下为写入 `tbclientadd.adrsta/adrcty/adrsec`（及 X1 地址相关）时，渠道/柜面**应上送的请求字段名与取值要求**。

#### （1）签约 `100001`

| 请求字段 | 应上送的值 | 是否写入 `tbclientadd` | 说明 |
|----------|------------|------------------------|------|
| `Adrsta` | 6 位省代码，须在字典 **`K_DQDM`** 中存在（如 `330000`） | 是（直接 `set`，空则落空） | 非空时会做 `K_DQDM` 校验，不存在报「客户所在省份异常」 |
| `Adrcty` | 6 位市代码（如 `330100`） | 仅非空时写入 | 不上送则库中保持默认空格 |
| `Adrsec` | 6 位区县代码（如 `330106`） | 仅非空时写入 | 同上 |

示例（杭州西湖区）：

```text
Adrsta=330000
Adrcty=330100
Adrsec=330106
```

注意：只上送 `CommAdrsta`/`CommAdrcty`/`CommAdrsec` **不能**替代上述字段，现居省市区仍会空。

#### （2）反洗钱补录 `100846`（推荐补数入口）

| 请求字段 | 应上送的值 | 落库位置 | 说明 |
|----------|------------|----------|------|
| `Nation` | 现居国家，中国一般为 **`156`** | `tbclientaml.present_nation` | 中国时通常要求上送省；与市校验联动 |
| `Adrsta` | 6 位省代码（如 `330000`） | `tbclientadd.adrsta` | `Nation=156` 且校验开启时必输；港澳台等特殊省码时市可不强制 |
| `Adrcty` | 6 位市代码（如 `330100`） | `tbclientadd.adrcty` | 普通省份在校验开启时必输 |
| `Adrsec` | 6 位区县代码（如 `330106`） | `tbclientadd.adrsec` | 建议上送；空则可能落空格（受参数 `T100846_NOT_CHECK_ADRSTATION_CITY_SEC` 等影响） |
| `Adrdet` | 现居**详细地址**中文（街道门牌等） | `tbclientaml.address` | 拼进 X1 `address` 的最后一段；`Nation` 有值且校验开启时常必输 |

示例：

```text
Nation=156
Adrsta=330000
Adrcty=330100
Adrsec=330106
Adrdet=杭州市西湖区文三路xxx号
```

若只补省市区、不补详细地址，X1 可能变成 `330000|330100|330106|`（末段仍空）；若省为空，则整段变成 `|||`。

#### （3）客户信息变更 `100104`

| 请求字段 | 应上送的值 | 是否更新 `tbclientadd` | 说明 |
|----------|------------|------------------------|------|
| `Adrsta` | 6 位省代码（如 `330000`） | **仅非空才更新** | 不上送 / 送空 → **原值不变**（不会凭空补上） |
| `Adrcty` | 6 位市代码（如 `330100`） | 仅非空才更新 | 同上 |
| `Adrsec` | 6 位区县代码（如 `330106`） | 仅非空才更新 | 同上 |

示例（变更现居省市区）：

```text
Adrsta=330000
Adrcty=330100
Adrsec=330106
```

说明：`100104`  alone 往往只改客户附加信息；完整反洗钱现居国/详细地址通常仍需走 **`100846`**（或变更联动补录）。要保证 X1 `address` 完整，建议省市区 + `Adrdet`（经 100846）一起齐。

### 5.4 怎么确认库里是否已有值

```sql
-- 省市区
select in_client_no, bank_no, adrsta, adrcty, adrsec
  from tbclientadd1   -- 分表号按实际
 where in_client_no = '内部客户号';

-- 详细地址（X1 address 末段）
select in_client_no, bank_no, present_nation, address
  from tbclientaml1
 where in_client_no = '内部客户号';

-- 是否走过反洗钱补录
select serial_no, trans_date, status, trans_code
  from tbaccreq1
 where in_client_no = '内部客户号'
   and trans_code = '100846'
 order by trans_date desc;
```

补数后重跑对应导出节点（如 `211012`），再看 `tbamlperinfoexp.address` / X1 文件。

### 5.5 常见为空原因

1. 签约 `100001` 渠道未上送 `Adrsta`/`Adrcty`/`Adrsec`（只送了通讯地址 `Comm*`）
2. 从未做 `100846`，或补录未上送省市区 / `Adrdet`
3. `100104` 变更也未带这三项（非空才更新）

## 6. 生产 = 测试都空时，优先怀疑

1. **`tbfieldmap` 配成 `SNULL` 或 `sys_field` 错误**（两套环境同脚本）
2. **灌数 SQL 根本没赋该列**（标准逻辑或个性化漏改）
3. **源业务字段普遍未维护**（反洗钱补录未做；尤其 `adrsta` 等省市区未上送）
4. **需要字典映射但 `tbdictmap` 未配**

不太像：单机故障、单日文件损坏（否则测试/生产不会一致）。

---

## 7. 实操最短路径（约 10 分钟）

1. 记下：TA + 模板 + 空字段序号/名  
2. 查 `tbfieldmap` → 是不是 `SNULL`  
3. 查 `tbamlperinfoexp` 同列有没有值  
4. 有值看映射/写文件；无值按第 4 节找源表，再查 `T211012`（或资管/信托对应类）里该列从哪来  
5. 若空在 `address` / 省市区：按第 5 节查 `tbclientadd` + `tbclientaml`，用 `100846`（或签约/变更带齐 Tag）补数后重导
