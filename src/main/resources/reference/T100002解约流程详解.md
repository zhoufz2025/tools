# T100002 解约流程详解（入口：T100002HSAdapter）

## 1. 文档范围
- 入口类：`T100002HSAdapter`
- 入口文件：`app/lcpt-server/sale/lcpt-pub/lcpt-pub-common/lcpt-pub-online-adapter/src/main/java/com/hundsun/lcpt/pub/online/adapter/T100002/T100002HSAdapter.java`
- 目标：梳理“客户解约（100002）”完整处理链路，明确：
  - 流程步骤
  - 操作到的数据库表
  - 参数开关与控制逻辑
  - 分业务解约与全量解约的差异

## 1.1 关键字典语义（来自 `IDict`）
- 签约状态 `K_QYZT`
  - `QYZT_NORMAL=0`：正常
  - `QYZT_SINGOFF=1`：解约
  - `QYZT_CHANGE=2`：换卡
- 账户状态 `K_ZHZT`（理财账户/资产账户常用）
  - `ZHZT_PRE_CLOSE=5`：预销户
  - `ZHZT_CLOSE=X`：销户
- 产品类型 `K_CPLX`（100002 常见）
  - `0` 基金（`CPLX_FUND`）
  - `1` 理财产品（`CPLX_FINA`）
  - `2` QDII（`CPLX_QDII`）
  - `3` 贵金属（`CPLX_METAL`）
  - `4` 银保（`CPLX_INSURE`）
  - `5` 积存金（`CPLX_GOLD`）
  - `8` 信托产品（`CPLX_TRUST`）
  - `A` 大额存单（`CPLX_DECD`）
  - `B` 资管计划产品（`CPLX_ZGJH`）
  - `E` 结构性存款模板（`CPLX_JGXCK`）
  - `X` 商业养老金（`CPLX_COMMERCIALPENSION`）

## 2. 总体流程（主干）

`action()` 主流程：
1. `transRequest`：请求字段校验、基础上下文装配
2. 判断是否走分业务解约 `signOffByPrdType`
3. 预校验：
   - 分业务：`checkDataByPrdType`（按 `PrdTypes` 逐个业务校验）
   - 非分业务：`checkData`
4. `toLocalFirst`：先落交易流水 `tbaccreq*`
5. 发外围系统：
   - 非分业务可能发组合中心 `toHstc`
   - 发核心/主机 `toHost`
   - 发 ECIF `toEcif`（参数控制）
6. 本地落地：
   - 分业务：`toLocalByPrdType`（主要更新产品标识）
   - 非分业务：`toLocal`（完整解约状态落地）
7. `packAnswer` 组装应答

## 3. 两类流程分支

## 3.1 全量解约（非分业务）
- 关键方法：`checkData -> toLocalFirst -> toHstc(可选) -> toHost -> toEcif(可选) -> toLocal`
- 特点：
  - 客户级别状态会更新为解约
  - 银行账号可能做自动解登记（发 100014/100814）
  - 可触发自动销户（基金/信托/资管/结构性存款/商养等子系统）

## 3.2 分业务解约
- 触发条件：`SIGN_BY_PRDTYPES` 已配置，且请求上送 `PrdTypes`，并且“客户当前签约业务数 > 本次解约业务数”
- 关键方法：`checkDataByPrdType -> toLocalFirst -> toHost(可能跳过) -> toEcif(可选) -> toLocalByPrdType`
- 特点：
  - 只剔除对应业务类型标记，不一定把客户整体置为解约
  - 银行账号 `prd_types` 会同步剔除
  - 当某张卡剔除后 `prd_types=' '` 时，卡状态更新为解约

## 4. 详细步骤说明

## 4.1 请求转换与基础校验（`transRequest`）
- 必输：`AccType`、`Account`
- 若请求 `SignOffFlag != N`，会强制置为 `Y`（作为自动销户参与标志）
- 设置统一签约模式标记：`MUTI_BANK_ONLY_SING_ONE`

## 4.2 分业务判断（`signOffByPrdType`）
- 读取 `SIGN_BY_PRDTYPES` 决定是否启用分业务模式
- 校验请求 `PrdTypes` 合法性（是否存在于 `K_CPLX` 字典）
- 若上送 `BankAcc`，会校验该卡是否包含请求业务类型（卡维度 `prd_types`）
- 若请求业务不是客户已签约业务，报错
- 若“不是最后一个业务”则置 `transVar.signOffByPrdType=true`

## 4.3 非分业务主校验（`checkData`）
核心校验点：
- 客户状态校验：已解约直接报错
- 日终/BTA 禁止交易校验（`DAILY_END_FORBIDDEN_TRANS`、`BTA_FORBIDDEN_TRANS` 等）
- 自动销户路径校验（`AutoCloseAcc`、`AUTO_CLOSE_PRD_TYPES`）
- 在途异步换卡限制：`T100002_CHECK_ONWAY_ASYNC_CHGCARD`
- 预校验/解登记前置（`isPreCheck100002`、`CHECK_TRANSFER_SWITCH`）
- 自动解登记（`SIGNOFF_BANKACC`）调用 `T100014HSAdapter/T1L0014HSAdapter/T100814HSAdapter`
- 可选发大额存单校验（`SIGNOFF_CHK_DECD`）与积存金校验（`SIGNOFF_CHK_GOLD`）

## 4.4 分业务校验（`checkDataByPrdType`）
按每个 `prdType` 分别执行：
- 基金/理财/QDII/信托/资管/商养等资产账户状态校验（重点判断是否仍存在 `acc_status` 不为 `ZHZT_CLOSE(X)`，或不在 `ZHZT_PRE_CLOSE(5)`、`ZHZT_CLOSE(X)` 范围内的记录）
- 根据参数决定是否自动发子系统销户交易
- 贵金属、银保、黄金二级代理等专门校验
- 合约信息通知条件判断（`IS_SEND_ARINFO`）

## 4.5 本地流水预落地（`toLocalFirst`）
- 先生成序列号与 `AccReq`
- 写入交易流水（`AccReqService.addAccReq`）
- 作用：先有流水，再发外围系统，便于失败回写

## 4.6 发核心（`toHost`）
- 关键跳过条件：
  - 已标记发组合中心
  - 分业务且参数 `TO_HOST_100002=Y`（分业务解约不发核心）
  - 请求 `IsPrd=Y` 或 `NotToHost=Y`
  - 参数 `SIGN_SEND_300905=Y`（不发 300905）
- 正常时组包 `R300905Dataset` 并发送
- 成功回填 `hostSerial`、`contrId`

## 4.7 发 ECIF（`toEcif`）
- 开关：`JNNS_SEND_ECIF_FLAG` 或 `T100002_SEND_ECIF_FLAG`
- 可配置交易码：`T100002_TOECIF_TRANSCODE`
- 支持参数 `T100002_SEND_HOST_USE_PUB` 控制使用公共接口方式
- 超时按成功处理（仅超时场景）

## 4.8 本地落地（全量）`toLocal`
- 更新 `tbclientseller*` 为解约状态（含 `prd_type_msg_flag` 清空）
- 根据多法人参数决定是否更新 `tbclient*` 为解约
- 成功更新 `tbaccreq*` 状态为成功
- 根据参数删除 `tbtransaccount*`
- 根据参数更新 `tbbankacc*` 为解约/签解约日期/清空 `prd_types`
- 根据参数更新 `tbclientriskinfo*` 风险字段
- 双核心场景更新 `tbclientnomap2`
- 根据参数更新反洗钱状态（`tbclientaml*`）

## 4.9 本地落地（分业务）`toLocalByPrdType`
- 从 `clientSeller.prdTypes` 与 `prdTypeMsgFlag` 中剔除本次业务
- 更新 `tbclient*` 与 `tbclientseller*`
- 更新 `tbaccreq*`（摘要写“本次解约业务[...]”）
- 可删除 `tbtransaccount*`（仅当剔除后已无业务）
- 更新 `tbbankacc*`：
  - 先更新 `prd_types`
  - 若 `prd_types=' '` 则更新卡状态为解约
- 支持“分业务解约不送卡”场景：对客户下所有卡批量剔除

## 5. 涉及数据库表清单（按职责）

## 5.1 客户与签约主数据
- `tbclient*`：客户基本状态（签约状态字段，常见 `0=正常`/`1=解约`）与最近修改时间
- `tbclientseller*`：客户在机构/法人维度签约状态（`K_QYZT`）、产品标记、短信标记
- `tbbankacc*`：银行卡签约状态（`K_QYZT`）、签约产品标记、签解约日期
- `tbtransaccount*`：交易介质映射，解约可删除
- `tbclientmap`：ECIF/核心补卡号时兜底查询
- `tbclientnomap2`：双核心客户号映射状态同步

## 5.2 交易流水与扩展
- `tbaccreq*`（通过 `AccReqService`）：解约交易主流水
- `tbaccreqext*`（通过 `AccReqExtService`）：扩展信息（全局流水号等）

## 5.3 资产账户/TA 相关
- `tbassetacc*`：核心校验与自动销户判断主表（按产品类型）；100002 解约核心判断是该客户在目标业务下是否仍存在“未销户账户”（即 `acc_status != ZHZT_CLOSE(X)`，部分分支要求进一步达到 `acc_status in [ZHZT_PRE_CLOSE(5), ZHZT_CLOSE(X)]`）
- `tbtainfo`：TA 状态、公私募属性校验

## 5.4 银行卡解登记与虚拟卡
- `tbvirbankaccmap`：解登记时过滤虚拟卡
- `tbmsgnoticesync`：在途换卡异步消息校验

## 5.5 组合中心/组合签约
- `tbgrpbankmap`：组合虚拟卡映射
- `tbclientgrpsign*`：组合签约关系（可控制是否按此发组合中心）

## 5.6 风险与反洗钱
- `tbclientriskinfo*`：风险等级清零/重置
- `tbclientaml*`（经 `ClientAmlDao`）：反洗钱状态更新

## 5.7 业务在途/限制校验表
- 贵金属：`tbmetalreq`、`tbmetalautoinvest`、`tbmsharedetail`
- 银保：`tbshareinsure`、`tbinsurereq`
- 黄金二级代理：`tbgoldacc`、`tbgoldsign`
- 大额存单扩展校验：`tbinstext`

## 6. 参数控制逻辑总表（重点）

以下为 100002 解约流程中出现频率高、影响主路径的参数：

- `SIGN_BY_PRDTYPES`
  - 含义：启用分业务签解约模式
  - 影响：决定是否走 `signOffByPrdType` 分支

- `TO_HOST_100002`
  - 含义：分业务模式下是否不发核心（注释语义）
  - 影响：`toHost` 早退

- `SIGN_SEND_300905`
  - 含义：是否发送 300905（解约发核心交易）
  - 影响：为 `Y` 时不发 300905

- `T100002_SEND_ECIF_FLAG` / `JNNS_SEND_ECIF_FLAG`
  - 含义：是否发 ECIF
  - 影响：调用 `toEcif`

- `T100002_TOECIF_TRANSCODE`
  - 含义：ECIF 交易码覆盖
  - 影响：`toEcif` functionId 由参数替换

- `T100002_SEND_HOST_USE_PUB`
  - 含义：发 ECIF/核心是否走公共接口
  - 影响：选择 `IHostService.execute300002` 或 `HostServiceClient`

- `T100002_TOHOST_BANKACC`
  - 含义：发核心是否强制带 `BankAcc`
  - 影响：`setBankAcc` 是否执行兜底取卡

- `AutoCloseAcc`
  - 含义：是否启用自动销户总开关
  - 影响：自动销户前置校验与实际发起

- `AUTO_CLOSE_PRD_TYPES`
  - 含义：可自动销户产品类型集合
  - 影响：`checkData` 中 `tbassetacc*` 条件

- `IS_FUND_AUTO_CLOSE_ACC` / `IS_FINA_AUTO_CLOSE_ACC` / `IS_ASSET_AUTO_CLOSE_ACC` / `IS_DXCP_AUTO_CLOSE_ACC`
  - 含义：基金/理财/资管/商养分产品自动销户开关
  - 影响：`checkDataByPrdType`、`checkAutoCloseAssetAccByPrdType` 的自动销户路径

- `CLIENT_OFF_ENTER_APP`
  - 含义：多子系统自动销户入口系统标识
  - 影响：决定调本地 Bean 还是跨子系统远程发送

- `CHECK_TRANSFER_SWITCH`
  - 含义：是否启用取消登记校验与转发检查
  - 影响：100014 预校验 + transfer 通知链路

- `SIGNOFF_BANKACC`
  - 含义：客户解约时是否自动发银行卡解登记
  - 影响：批量发 100014/100814

- `T100002_SIGNOFF_100814`
  - 含义：是否改用 100814 取消登记
  - 影响：`pack100014Dataset` 中交易码切换

- `TERMINATE_TO_UNREGISTER_FILTER_VIRBANK`
  - 含义：取消登记时是否过滤虚拟卡
  - 影响：`not exists tbvirbankaccmap` 条件拼接

- `T100002_CHECK_ONWAY_ASYNC_CHGCARD`
  - 含义：是否校验在途换卡
  - 影响：存在未完成换卡时拒绝解约

- `DELCLIENTBANKACC`
  - 含义：是否删除/保留银行账号关系
  - 影响：`toLocal` 中是否更新 `tbbankacc*`

- `TRANSACCOUNT_DEL`
  - 含义：解约是否删除 `tbtransaccount*`
  - 影响：全量/分业务本地落地的删除动作

- `APPROP_RISK_PRDTYPE`
  - 含义：解约后是否重置客户风险信息
  - 影响：更新 `tbclientriskinfo*`

- `IS_CHECK_TWO_HOST_100001`
  - 含义：双核心模式下是否同步客户号映射状态
  - 影响：更新 `tbclientnomap2`

- `T100002_MODIFY_CLIENTAML_STATUS`
  - 含义：解约是否重置客户反洗钱状态
  - 影响：更新 `tbclientaml*`

- `IS_SEND_ARINFO`
  - 含义：是否发送合约管理信息
  - 影响：触发 `SendARInfoService.SignoffSendARInfo`

- `T100002_MUTI_BANK_SIGN_OFF`
  - 含义：多法人模式下是否仅最后一行解约时更新客户主状态
  - 影响：控制 `tbclient*` 状态更新时机

- `T100002_UPT_MODIFY_DATE`
  - 含义：是否更新客户最近修改日期
  - 影响：更新 `last_modify_date/modi_time`

- `SIGNOFF_CHK_DECD` / `SIGNOFF_CHK_GOLD`
  - 含义：是否发大额存单/积存金解约校验
  - 影响：调用 `checkSendDecd/checkSendGold`

## 7. 外部系统/交易码交互清单
- 300905：核心客户号解约
- 300002/309003/309004：ECIF 交互
- 180609：组合中心解约
- 100014 / 100814 / 1L0014：银行账号取消登记
- 100101 / 110101 / 1B0101 / 170101 / 1L0101 / 1X5101：各子系统自动销户
- 1A0102：大额存单校验
- 1G0018：积存金校验

## 8. 常见失败点（排障优先顺序）
- 参数缺失：`AccType`/`Account`/分业务缺少 `PrdTypes`
- 客户已解约或状态异常
- `tbassetacc*` 账户状态未达到解约要求：仍存在 `acc_status != ZHZT_CLOSE(X)`，或（在需要预销户收敛的分支）仍存在不在 `ZHZT_PRE_CLOSE(5)`、`ZHZT_CLOSE(X)` 范围内的记录（常见原因是自动销户参数未对齐）
- 在途换卡（`tbmsgnoticesync`）
- 银行账号取消登记失败（100014/100814）
- 子系统自动销户服务 Bean 未配置（`NoSuchBeanDefinitionException`）
- ECIF/主机返回非成功（ECIF 超时除外）

## 9. 结论
- `T100002` 是“先流水、后外围、再本地落地”的典型强一致交易编排。
- 实际行为高度依赖参数，尤其是：
  - 分业务开关
  - 自动销户开关族
  - 是否发核心/ECIF/取消登记
- 排查解约问题时，建议先确认 `PrdTypes + 参数快照 + tbassetacc*.acc_status（按 K_ZHZT 翻译）+ tbaccreq*流水` 四要素。
