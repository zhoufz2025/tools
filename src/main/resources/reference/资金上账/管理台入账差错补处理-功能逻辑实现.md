```
                    │ 内部户：HostServiceClient → 300404          │
```

## 3. `tbdxfundsquareerr` 表结构与关键字段

表注释：入帐差错表。主键 `(square_date, serial_no, seq_no)`。

公共库、交易库均有同名表。管理台查询默认公共会话；指定客户标识时可能切交易会话（见 queryService 会话选择）。

### 3.2 `reserve1` 生命周期（最关键）

```
导入          发起补处理         110500 成功            110500 失败
  │                │                  │                     │
  ▼                ▼                  ▼                     ▼
 '0'  ──store──►  '2'  ──toLocal──►  '1'                  '0'
未处理           处理中            已成功                还原未处理
                                    reserve2=说明
                                    reserve3=柜员
                                    batch_status=对齐 square
```

| 值 | 谁写入 | 前端行为 |
|----|--------|----------|
| 空 / 0 | T210213 导入固定 `'0'`；强制失败；补处理失败还原 | 可补处理 |
| 1 | T110500 toLocal 成功 / 强制成功 | 隐藏补处理、入挂账 |
| 2 | 管理台 `storeErrStatus`：`update ... set reserve1='2' where serial_no=?`（**未带 seq_no**） | 隐藏补处理；checkData 拒绝 |
| P | 换户待审批 | 待审批 |

文件模式：发送链把所选流水 `reserve1` 置 `2`，并写 `file_serial_no=批次流水`；回盘成功置 `1`，失败还原 `0` 且清空 `file_serial_no`。MethodTrack.`reserve1` 另存**批次流水**，与差错表 `reserve1`（补处理状态）不是同一语义。详见第 9 章。

### 3.3 与清算表状态对照

补处理成功（T110500.toLocal，非强制、非挂账）：

| 表 | 字段 | 新值 |
|----|------|------|
| tbdxfundsquare / hissquare | status | 7 补处理成功 |
| | batch_status | 2 已完成 |
| | host_date / host_serial | 核心返回 |
| | err_msg | 原值或追加 |
| tbdxfundsquareerr | reserve1 | 1 |
| | reserve2 | 补处理成功 |
| | reserve3 | OperNo |
| | new_bank_acc | 换卡账号 |
| | batch_status | 与 square.batch_status 一致 |
| | prd_code | 用 square 产品回写 |

强制成功：square.status=**2**，reserve2=强制处理成功。  
强制失败：square.status=**5**，reserve1=**0**，reserve2=强制处理失败。  
入挂账：square.status=**9**，reserve2=入挂账账号成功。  
超时：square.status=**8**，batch_status=8；差错 reserve1 视失败路径可能回 0。

参数 `SQUAREERR_COMP=1` 时，补处理成功额外插入 `tbbatchreq` 参与对账。

## 4. 数据来源实现

### 4.1 标准主路径：T210213 导入 `bkerrsquare`

**文件列（标准注释约定）**

```
square_date | serial_no | seq_no | client_no | bank_acc | prd_code | amt | err_msg | curr_type | bank_no | err_code
```

| 列下标 | 表字段 | 规则 |
|--------|--------|------|
| 0 | square_date | int |
| 1 | serial_no | 关联键 |
| 2 | seq_no | |
| 3 | client_no | CTRL_SQUAREERR_PARAM=0 直用；=1 由 bank_acc 反查 |
| 4 | bank_acc | |
| 5 | prd_code | |
| 6 | amt | |
| 7 | err_msg | 可截断（T210213_SUBSTR_ERRMSG） |
| 8 | curr_type | 缺省 156 |
| 9 | bank_no | ENABLE_THIRD_SELLER=1 才取文件 |
| 10 | err_code | 可缺 |
| — | in_client_no | tbclientmap 反查 |
| — | reserve1 | 固定 `'0'` |

调度：

```
J210213T01 PUB210213   公共取文件、导入公共库、按 in_client_no 拆片区
J210213T02 DXFUND210213 交易片区导入
J210213T03 DXFUND211213 交易差错导出
J210213T04 PUB211213    公共覆盖导入（补处理结果也走这条回公共）
```

交易片区 `sysMdSquStatus`（`MDSQUFLAG=1`）：

- 关联：`square.{square_no|serial_no} = err.serial_no` + seq_no + prd_code
- 回写 square：`status`、`err_msg`、`reserve1`（= err.err_msg）
- 目标 status：`SQUARE_ERR_REDEAL=1` → `6`，否则 `5`
- 排除：已补处理成功 `7`、`err_msg='0000'`、默认排除 `is_daily='1'`
- `EXCLUDE_SUSPEND=1` 排除 `hang_flag='Y'`
- `SQUARERRFILE_DATE=1` 用当日 square 表，否则 hissquare；日间强制当日 square

`repSquareerr`：用 square 回补空 `prd_code` / `branch_no`。  
`BACK_HOST_TRANS_SERIAL=1`：把 `trans_serial_no` 回写 square，并删除 `reserve3='S'` 临时成功行。

日启删除条件默认 **`is_daily <> '1'`**，避免冲掉 T210314 轮询差错。

### 4.2 日间轮询：T210314

- INSERT 固定 `is_daily='1'`，`batch_no` = 本轮主机文件流水
- 删除范围：`is_daily='1' and batch_no=?`
- 同样可 `sysMdSquStatus`（条件改为 is_daily=1）

与 `batch_flag='1'`（日间**业务**入账，T210213 的 DAILY_SQUARE_FLAG 路径）不是同一标记。

### 4.3 联机失败直写：TaskBatch2OnlineSquare

T210013 日间/联机入账失败：

```sql
insert into tbdxfundsquareerr(
  bank_no, square_date, serial_no, seq_no, client_no, bank_acc, prd_code,
  curr_type, amt, err_msg, amt1, amt2, reserve1, reserve2, reserve3, reserve4,
  err_code, in_client_no)
```

- `serial_no` 默认 square_no，`SQUARENO_IS_SERIALNO=1` 时用交易 serial_no
- reserve1~4 空格；**未显式写 is_daily / batch_flag**
- 随后 `PubDxFundApiFactory.addSquareerr2` 同步公共库

### 4.4 其它写入

| 场景 | 特征 |
|------|------|
| 组合宝对账不平 Task210455 | reserve4='yeb' |
| 广东华兴反洗钱 T219012 | reserve4='219012'，reserve1='0' |

### 5.2 主 SQL

status 查询映射到 reserve1：

| 传入 status | reserve1 |
|-------------|----------|
| Z 处理中 | 2 |
| 6 未处理 | 0 |

### 5.3 formatResult

有 `in_client_no` 时，按 `SQUARENO_IS_SERIALNO` 从 `tbdxfundsquare{N}` ∪ `tbdxfundhissquare{N}` 取：liqu_dir, host_serial, host_date, channel, branch_no, open_branch, busin_code, summary, status, batch_status, square_no。

无内部客户号且 `SQAURE_ERR_NO_CLIENTINFO_MODE=1`：`noInClientNoFormat` 扫片区找 square，回填 `square_table` / `square_session` 供内部户补处理。

字典：金额格式化、日期 10 位、产品名、K_BZ、K_RZBZ、K_CCCLZT、机构名；客户姓名证件从 client 服务取；账号脱敏。

## 7. 单笔补处理实现

### 7.1 管理台 `dealSquareService`

```
noInClientNoFlag=1  → noInClientNoReDeal（内部户）
否则：
  checkData
  storeErrStatus   // reserve1='2' where serial_no=?
  pack110500
  OnlineServiceClient.sendAndReceive(DXFUND_TRADE)
```

### 7.2 checkData

1. inClientNo 空 → 报「可能为内部户，不支持补处理」
2. `DEAL_SQUARE_BUSIN_CODES` 非空则业务码必须包含
3. `DEAL_SQUARE_LIQU_DIRS` 非空则账务方向必须包含
4. bankAcc、seqNo 必填
5. status 必须在 `DEAL_SQUARE_STATUS`（默认 `6`）内；forceFlag 为 0 或 1 时追加允许 `8`
6. 库中该 serial_no+seq_no 的 reserve1 已是 `2` → 「正在处理中」
7. 可选 SPI：`IDxFundSquareErrCheckService.checkBankAcc`

### 7.3 pack110500

| 字段 | 来源 |
|------|------|
| FunctionId | 110500 |
| Channel | 管理台 |
| SquareNo / SerialNo / SeqNo / InClientNo / Status / BankNo | DTO |
| Account / NewBankAcc | bankAcc；含 `*` 则用 realBankAcc |
| ForceFlag | forceFlag；**若为 2 则不上送** |
| AddForPrdGzAccount | DTO 非空则上送 |
| BankAccVer | REDEAL_CHANGE_BANKACC=1 且有 newBankAcc |
| HostSquareNo | REDEAL_SEND_BATCH_NO=1 时从 tbhostfile(PUB219301) 取 |

### 7.4 T110500 主流程

```
action:
  DealTrans=对账补处理 → T110500HostCheckErrBclAdapter（核心对账差错，非 squareerr 主路径）
  transRequest → checkData → toLocalFirst（补全局流水）
  recordNewClientNoAndCheckApproval 需要审批则返回
  toHost → toLocal → packAnswer
  异常 → repErrStatus 回滚差错处理中状态
```

**toHost**

- ForceFlag 非空（0/1）→ **直接 return，不发核心**
- 否则 pack300404：
  - AddForPrdGzAccount=1 → BankAcc = 参数 PrdGzAccount
  - NewBankAcc 非空 → 覆盖 BankAcc
  - DXFUND_SQUARE_ERR_DEAL_ACCOUNT 非空 → PayAccount 行内中间户
  - 赎回直接买入计划可改 LiquDir（参数/标志）
- execute300404
  - 成功：square.status 先置 7（后续 toLocal 再细化）
  - 超时：unlock 为 8，记 host_date

| 强制成功 | 2 | 2 | 1 | 强制处理成功 |
| 强制失败 | 5 | （失败侧） | 0 | 强制处理失败 |

UPDATE 差错（非解冻扣款路径）：


## 9. 文件模式实现

> 需求见《需求说明书》FR-08。代码引入：`T202305164194` / IFMS6.0V202304.04.000（管理台 `remedyPostFileByCond` / `remedyGetFileByCond` + 批量 210713/210813/211713）。
>
> 与联机 110500 **并行存在**：银行按核心是否支持文件补账启用；标准 Vue 两个按钮按 PostFile/GetFile 权限显示。

### 9.1 总体时序

```
柜员勾选 serialNo + inClientNo
  → POST ifmCQsglSquareErrPostFileByCond
  → DxfundSquareErrService.remedyPostFileByCond
       getAndLockMethod（校验 reserve1、调度状态、MethodTrack）
       MethodTrack(RepairSquare/remedyPostFileByCond): deal_status=DOING, reserve1=新批次流水
       toBatch 异步 ScheJobCode=J210713（带 SerialNos / InClientNos / SerialNo=批次流水）
  → 调度 J210713（典型子步，以行内作业配置为准）
       ┌─ PUB211713：校验 square.status=6；insert tbhostfile；err.reserve1 0→2
       ├─ DXFUND210713：片区锁清算、生成 squarerepair 分片文件、写 file_serial_no、上传共享目录
       └─ PUB210713：合并分片 → 送核心 → MethodTrack → WITHDRAW；err.file_serial_no=批次流水
  → 柜员确认核心已处理
  → POST ifmCQsglSquareErrGetFileByCond
  → remedyGetFileByCond：MethodTrack 必须 WITHDRAW → toBatch J210813
  → 调度 J210813
       ┌─ PUB210813：取 bkerrsquarerepair（或行内结果文件并格式化）
       │            失败行 reserve1=0；同批其余 →1「补处理成功」
       │            按 in_client_no 拆片区差错文件；失败行清空 file_serial_no
       │            MethodTrack → SUCC
       └─ DXFUND210813：取片区文件 → 再回写 squareerr → sysMdSquStatus 回写 square/hissquare
```

### 9.2 管理台入口

| 项 | 说明 |
|----|------|
| Controller | `postFileByCond` / `getFileByConde` → `remedyPostFileByCond` / `remedyGetFileByCond` |
| 前端上送 | 发送：`ids`（流水逗号串）、`inClientNos`；取结果：不强制勾选，复用 MethodTrack 批次 |
| 异步 | `batchServiceClientUtils.sendAsync`，管理台不阻塞等批量结束 |

#### 9.2.1 `getAndLockMethod`（发送/取结果共用骨架）

1. `select * from tbdxfundsquareerr where serial_no in (ids)`：`reserve1=1` 抛「状态不允许」；`=2` 抛「正在处理中」。
2. `update tbmethodtrack ... where method=remedyPostFileByCond` 行锁。
3. 查 `tbscheduleprocess`：节点 START → 「节点正在执行中...」；J210713 且 FAIL 时把 MethodTrack 置 FAIL（便于重试）。
4. `getSureMethodTrack(initDate, DEFAULT_CODE, "RepairSquare", "remedyPostFileByCond", …)`。

**注意**：发送与取结果共用**同一条** MethodTrack 业务键（`RepairSquare`/`remedyPostFileByCond`），用 `deal_status` 串行两步；取结果传入的 `schCode=J210813` 仅用于判断该调度是否在跑。

#### 9.2.2 `remedyPostFileByCond`

```
MethodTrack 已 DOING 且 reserve1 非空 → 拒绝「有数据正在处理」
MethodTrack 已 WITHDRAW               → 拒绝「请先获取结果」
否则：reserve1 = 新序列号；deal_status = DOING；modifyMethodTrack
toBatch(批次流水, J210713, dto)   // SerialNo=批次流水，SerialNos/InClientNos=勾选
```

#### 9.2.3 `remedyGetFileByCond`

```
MethodTrack 非 WITHDRAW → 「账务未成功发送核心,请先发送账务给核心」
toBatch(原 MethodTrack.reserve1, J210813, dto)
```

#### 9.2.4 `toBatch` 请求字段

| Tag | 来源 |
|-----|------|
| FunctionId / ScheJobCode | J210713 或 J210813 |
| SerialNo | MethodTrack 批次流水 |
| SerialNos / InClientNos | 勾选 ids / inClientNos |
| OperNo / Channel / TransDate | 柜员、管理台、系统日 |
| PrdCode / AccType / Account / 日期区间等 | 当前查询条件透传（JSON 进 REQPARAM） |

批量适配器从 `REQPARAM` JSON 再回填到 request Dataset。

### 9.3 MethodTrack 状态机

业务键：`trans_date=系统日`，`prd_code=DEFAULT_CODE`，`trans_code=RepairSquare`，`method=remedyPostFileByCond`。

| deal_status | 写入点 | 含义 |
|-------------|--------|------|
| DOING | 管理台发起发送；各子步失败前 | 发送链进行中 |
| WITHDRAW | PUB210713 `updateSendSuccess` | 已送核心，允许取结果 |
| SUCC | PUB210813 取结果成功末尾 | 本轮闭环完成，可再发新批 |
| FAIL | 211713/210713 异常；调度 FAIL 复位 | 允许排查后重发 |

**语义区分**：MethodTrack.`reserve1` = **批次流水**；差错表 `reserve1` = **补处理状态 K_CCCLZT**。二者同名不同义。

### 9.4 发送链 J210713

#### 9.4.1 PUB211713（`T211713HSAdapter`）— 登记批次

1. `checkData`：对所选 err 调 `getSquareBySquareNo`，要求 `square.status=6`（未处理），否则「存在不为未处理状态的账务流水」。
2. 文件名：`squarerepair[.6.0].{taCode}.{SerialNo}.{initDate}`（受 `HOST_FILE_NAME_MODE`）。
3. `tbhostfile`：若同日同 trans_code=210713 且（serial_no=本批 或 已落在所选 err 的 file_serial_no）已存在 → 「不允许重复生成」。
4. insert `tbhostfile`：`file_type=1`（发送）、`status=处理中`、`file_name=上文件名`。
5. `update tbdxfundsquareerr set reserve1='2' where reserve1='0' and serial_no in (...)`。
6. 异常：MethodTrack 置 FAIL。

#### 9.4.2 DXFUND210713（`TDXFUND210713HSAdapter`）— 片区生成

1. MethodTrack 子键：`FunctionId=J210713`，method=`createAndSendSquareFile`，`reserve1` 对齐批次流水防重入。
2. 本地路径：内部清算文件目录；文件名同 9.4.1。
3. SPI：`T210713_CreateRepairSquareFile`（无 Bean 则跳过创建）。
4. 成功后 `updateSquareStatus`：`update tbdxfundsquareerr set file_serial_no=? where serial_no in (SerialNos)`。

**广农商 `T210713CreateRepairSquareFileService` 要点**

- 校验 square/hissquare 中对应流水 `status` 只能是 5/6 之外不可（代码：`status not in('5','6')` 则报错——即只允许失败/未处理类进入）。
- 按 `InClientNos` 过滤本片区；`update square/hissquare`：`batch_status/status=Z（处理中）`，`square_status=处理中`；条件含 `status=6` 且 `batch_status in (' ','0','6')`，锁不到则「并发不允许补处理」。
- 写文件行：关联冻结信息；若 err.`err_code=3` 则账号换 `PrdGzAccount`（挂账）。
- 生成后 FTP/内部文件传输到 `远程路径/{areaId}/`。

#### 9.4.3 PUB210713（`TPUB210713HSAdapter`）— 合并送核心

1. MethodTrack 子键 method=`mergeSquareFile`。
2. SPI：`T210713_MergeSquareFileService`。
3. `updateSendSuccess`：再次写 `file_serial_no`；**MethodTrack(RepairSquare) → WITHDRAW**。
4. 失败：子 MethodTrack FAIL，且 RepairSquare MethodTrack → FAIL。

**广农商 `T210713MergeSquareFileService`**

- 按 `tbhostfile.file_name` 收集各片区分片 → 合并为行内名（如 `xzhlc_qs.156.{日期}.{批次}`）。
- `SquareUtil.sendFiles`（复用 210213 送文件能力，compCode=210713）。
- `pack400002` / `execute400002` 通知核心：Reserve=文件名，Reserve2=笔数，Reserve3=金额，Reserve1=日期。
- 回写 `tbhostfile.status=已发送`，并把核心返回批次日/批次号写入 reserve1/reserve2。

### 9.5 取结果链 J210813

#### 9.5.1 PUB210813（`TPUB210813HSAdapter`）

1. MethodTrack 子键 method=`getHostFile`，`reserve1` 对齐批次流水。
2. 取文件：优先 SPI `T210813_GetHostFileService`；否则默认 `getHostFile`（可联机 400005 触发，文件名 `bkerrsquarerepair[.6.0].{ta}.{批次}.{日期}`）。
3. 导入：优先 SPI `T210813_LoadSquareErrService`；否则 `loadTransResultFile`：
   - 结果文件**每一行视为失败**：`reserve1='0'`，写 `err_msg`/`err_code`/`reserve3=柜员`，匹配 `serial_no + file_serial_no=批次`。
   - 随后：`update ... set reserve1='1', reserve2='补处理成功' where file_serial_no=批次 and serial_no not in (失败列表)`。
4. `spiltAreaFile`：把公共库中本批仍 `reserve1='0'` 的失败行按 `in_client_no` 拆到 `tbdxfundsquareerr_{ta}_{areaId}`，可选结束符 `!#@END@#!`（参数 `T210813_CHECK_FILE_END`）。
5. `restFailRecord`：失败流水 `reserve1='0', file_serial_no=' '`（清空批次号便于再次发送）。
6. RepairSquare MethodTrack → **SUCC**。

**广农商取回盘**：查 `tbhostfile` 必须存在本批 210713；轮询主机结果文件 `result_xzhlc_qs...`；格式化为标准 `bkerrsquarerepair...`；`tbhostfile.status=已处理`。

标准回盘列（`T210813CommonGetHostFile` 注释）：

```
入账日期|流水号|序号|客户号|银行账号|产品代码|金额|失败原因|...
```

公共默认解析：列 1=serial_no，列 7=err_msg，列 10=err_code（`|` 分隔；`SQU_ERR_CUT_LENGTH` 截断错误信息）。

#### 9.5.2 DXFUND210813（`TDXFUND210813HSAdapter`）

1. 从公共共享目录取 `tbdxfundsquareerr_{ta}_{本片区}`。
2. `loadTransResultFile`：跳过表头；结束符校验（`T210813_CHECK_FILE_END`）；失败行更新 reserve1=0；同批其余置成功（与公共侧逻辑一致，依赖片区文件内容）。
3. `sysMdSquStatus`（square + hissquare 各分片表）：
   - 失败（err.reserve1=0 且 file_serial_no=批次）：`status/batch_status` ← `SQUARE_ERR_REDEAL=1` 则为 6（未处理），否则 5（失败）；回写 err_msg、host_date。
   - 成功（err.reserve1=1 且 file_serial_no=批次）：`status=7`（补处理成功），`batch_status=7`，`square_status=成功`。
4. `restFailRecord`：再次清空失败行的 file_serial_no。

## 13. 排查清单

| 现象 | 排查 |
|------|------|
| 管理台查不到日启差错 | T211213 公共导入是否完成；公共/交易 square_date 是否一致；会话是否查到公共库 |
| 关联不上清算信息 | SQUARENO_IS_SERIALNO；in_client_no 是否反查成功；是否已归档 hissquare |
| 补处理按钮没有 | 权限 Deal；reserve1=1/2；batchStatus 为 Z/8/2 |
| 提示正在处理中 | reserve1 残留 2（storeErrStatus 只按 serial_no，同流水多 seq 会一起锁） |
| 状态不允许补处理 | DEAL_SQUARE_STATUS 默认仅 6；超时需走强制或先同步 |
| 日间差错被日启删掉 | 日启 delete 是否误包含 is_daily=1；轮询应用 T210314 |
| 结果同步后差错状态不变 | Sync 不更新 reserve1，只改 square |
| 换卡不生效 | REDEAL_CHANGE_BANK_ACC（弹窗）与 REDEAL_CHANGE_BANKACC（上送）需同时理解 |
| 内部户失败 | EMPTY_INCLIENTNO_REDEAL、SQAURE_ERR_NO_CLIENTINFO_MODE |
| 文件模式提示先获取结果 | MethodTrack 为 WITHDRAW，先执行 J210813 |
| 文件模式重复生成被拒 | tbhostfile 已有 210713 本批或 err 已带 file_serial_no |
| 文件回盘后状态不对 | 结果文件列下标；SQUARE_ERR_REDEAL；片区 DXFUND210813 是否跑完 |

## 14. 端到端时序（标准客户，正常补处理）

## 15. 端到端时序（文件模式）

```
柜员勾选多笔 →「生成发送补处理」
  → MethodTrack DOING + 批次流水 S
  → J210713
      → 211713：tbhostfile 登记；err.reserve1=2
      → DXFUND210713：锁 square；生成 squarerepair…S…；err.file_serial_no=S
      → PUB210713：合并送核心；MethodTrack=WITHDRAW
  → 柜员「获取补处理结果」
  → J210813
      → PUB210813：取 bkerrsquarerepair…S…
            失败行 → reserve1=0 + 记 err_msg；成功行 → reserve1=1
            拆片区；失败清空 file_serial_no；MethodTrack=SUCC
      → DXFUND210813：回写 square status 7/6(或5)
  → 页面刷新；失败笔可再次勾选发送或改走联机补处理
```

发送失败（MethodTrack=FAIL）时须确认核心是否已收文件，再决定重发或强制处理，避免双入账。
