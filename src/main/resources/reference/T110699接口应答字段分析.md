# T110699个人资产总额查询接口应答字段分析文档

## 一、接口概述

**接口名称**：T110699 - 个人资产总额查询  
**文件路径**：`com.hundsun.lcpt.dxfund.online.adapter.T110699.T110699NewAction`  
**功能说明**：查询客户的基金资产总额、份额、市值、盈亏等综合信息

### 2.4 资产相关字段（重点）

#### 2.4.1 TotPrdValue（总市值/prdValue）⭐

**字段标识**：`TotPrdValue`  
**数据类型**：Double  
**字段含义**：总市值，即客户持有产品的当前市场价值

**计算方式**：
```java
// 普通基金产品
TotPrdValue = sum(总份额 * 产品净值)
// 按每个产品分别计算：tot_vol * nav，然后汇总

// 余额宝产品（特殊处理）
TotPrdValue = 可用份额 + 冻结份额 - 快速过户冻结部分
// 其中可用份额已包含未付收益
```

**数据来源**：
- 份额数据：从`tbdxfundshare`表查询
- 净值数据：从产品信息表获取（`DxFundProductInfo.getNav()`）

**计算位置**：
- 主要计算：`getShare0()`方法（第878-879行）
- 余额宝特殊处理：`getAnswerByPrdType()`方法（第621行）

**精度处理**：
- 每个产品的市值计算：`BigDecimalUtil.round(tot_vol * nav, 2)`（保留2位小数）
- 最终汇总：`BigDecimalUtil.add()`累加

**注意事项**：
1. 余额宝产品的总市值计算逻辑与普通基金不同，需要减去快速过户冻结部分
2. 精度修复：V6.0.0.23版本修复了prdTotValue精度不一致问题，改为按产品分别计算再汇总

#### 2.4.2 TotValue（总资产/totAmt）⭐

**字段标识**：`TotValue`  
**数据类型**：Double  
**字段含义**：总资产，包含市值、在途金额和未付收益

**计算方式**：

**普通基金产品**：
```java
TotValue = TotPrdValue + OnwayAmt + IncomeOnway
// 总资产 = 总市值 + 在途金额 + 未付收益
```

**余额宝产品**：
```java
TotValue = TotPrdValue + SquareAmt
// 总资产 = 总市值 + 在途入账资金
```

**数据来源**：
- `TotPrdValue`：总市值（见2.4.1）
- `OnwayAmt`：在途金额（见2.5.1）
- `IncomeOnway`：未付收益（见2.4.3）
- `SquareAmt`：在途入账资金（余额宝专用）

**计算位置**：
- `getAnswerByPrdType()`方法（第624行、第626行）

**业务含义**：
- 总资产反映客户当前实际拥有的资产总额
- 包括已确认的市值、正在处理中的资金和尚未到账的收益

#### 2.4.3 IncomeOnway（未付收益）

**字段标识**：`IncomeOnway`  
**数据类型**：Double  
**字段含义**：在途未付收益

**计算方式**：
```sql
-- 从份额表汇总
sum(a.income_onway)
```

**数据来源**：`tbdxfundshare`表的`income_onway`字段

### 2.5 在途资金相关字段

#### 2.5.1 OnwayAmt（在途金额）

**字段标识**：`OnwayAmt`  
**数据类型**：Double  
**字段含义**：总在途金额

**计算方式**：
```java
OnwayAmt = BuyAmtOnWay + SquareAmt
// 在途金额 = 在途申请资金 + 在途入账资金
```

**数据来源**：
- `BuyAmtOnWay`：在途申请资金（见2.5.2）
- `SquareAmt`：在途入账资金（见2.5.3）

#### 2.5.2 BuyAmtOnWay（在途申请资金）

**字段标识**：`BuyAmtOnWay`  
**数据类型**：Double  
**字段含义**：在途申请资金，即已提交但未确认的申购等交易金额

**计算方式**：
```sql
-- 从交易申请表汇总
select sum(a.amt) onway_amt
from tbdxfundtransreq a
where a.status in ('0', '1', 'P', '5', '6', 'A', 'Z', 'C')
  and a.trans_code in (实际买入交易代码列表)
```

**数据来源**：`tbdxfundtransreq`表

**状态说明**：
- `'0'`：待处理
- `'1'`：处理中
- `'P'`：部分确认
- `'5'`：待确认
- `'6'`：确认中
- `'A'`：已确认
- `'Z'`：待撤销
- `'C'`：已撤销

#### 2.5.3 SquareAmt（在途入账资金）

**字段标识**：`SquareAmt`  
**数据类型**：Double  
**字段含义**：在途入账资金，即已确认但未到账的资金

**计算方式**：
```sql
-- 从入账表汇总
select sum(a.amt) as square_amt
from tbdxfundsquare a
where a.status != '2' and a.status != '7'
  and (a.busin_code in ('150', '151', '124', '142', '163', '143') 
       or (a.busin_code in ('120','122','130','139') and a.liqu_dir ='1'))
```

**数据来源**：`tbdxfundsquare`表（可能包括历史表`tbdxfundhissquare`）

**业务代码说明**：
- `150`、`151`、`124`、`142`、`163`、`143`：入账类业务
- `120`、`122`、`130`、`139`：需要`liqu_dir='1'`的入账业务

## 三、重点字段详细说明

### 3.1 TotPrdValue（总市值/prdValue）详细说明

#### 3.1.1 业务含义
`TotPrdValue`表示客户持有产品的当前市场价值，是份额与净值的乘积。

#### 3.1.2 计算逻辑

**普通基金产品**：
1. 从`tbdxfundshare`表查询每个产品的总份额（`tot_vol`）
2. 从产品信息获取每个产品的净值（`nav`）
3. 按产品计算：`tot_vol * nav`，保留2位小数
4. 汇总所有产品的市值

**余额宝产品**（特殊处理）：
1. 获取可用份额（`UseVol`），已包含未付收益
2. 获取冻结份额（`FrozenVol`）
3. 获取快速过户冻结部分（`getYebRapFrozenVol()`）
4. 计算：`TotPrdValue = UseVol + FrozenVol - 快速过户冻结部分`

#### 3.1.3 代码实现位置

```java:820:889:T110699NewAction.java
// getShare0方法中计算普通基金的总市值
totPrdValue = BigDecimalUtil.add(totPrdValue,
    BigDecimalUtil.round(BigDecimalUtil.mul(ds.getDouble("totvol"),
        map.get(ds.getString("prd_code")).getNav()), 2));
```

```java:615:623:T110699NewAction.java
// getAnswerByPrdType方法中计算余额宝的总市值
if (prdType.equals(IDict.K_CPLX.CPLX_YEBQUE)){
    double useVol = answerDataset.getAnswerDataset().getDouble(ITag.UseVol);
    useVol = BigDecimalUtil.add(useVol, incomeOnway);
    answerDataset.setValue(ITag.UseVol, useVol);
    double frozenVol = answerDataset.getAnswerDataset().getDouble(ITag.FrozenVol);
    totPrdValue=BigDecimalUtil.sub(BigDecimalUtil.add(useVol, frozenVol), 
        getYebRapFrozenVol(context,transVar));
    answerDataset.setValue(ITag.TotPrdValue,totPrdValue );
}
```

#### 3.1.4 精度处理
- V6.0.0.23版本修复了精度不一致问题
- 修改前：在SQL中直接计算`sum(round(tot_vol*nav,2))`，可能导致精度丢失
- 修改后：按产品分别计算再汇总，确保精度准确

#### 3.1.5 注意事项
1. 余额宝产品的计算逻辑与普通基金不同
2. 需要减去快速过户冻结部分（快速赎回已确认但未到账的份额）
3. 余额宝的可用份额需要加上未付收益

### 3.2 TotValue（总资产/totAmt）详细说明

#### 3.2.1 业务含义
`TotValue`表示客户的总资产，包括已确认的市值、正在处理中的资金和尚未到账的收益。

#### 3.2.2 计算逻辑

**普通基金产品**：
```java
TotValue = TotPrdValue + OnwayAmt + IncomeOnway
```
- `TotPrdValue`：总市值（份额×净值）
- `OnwayAmt`：在途金额（在途申请资金+在途入账资金）
- `IncomeOnway`：未付收益

**余额宝产品**：
```java
TotValue = TotPrdValue + SquareAmt
```
- `TotPrdValue`：总市值（已包含未付收益）
- `SquareAmt`：在途入账资金

#### 3.2.3 代码实现位置

```java:609:627:T110699NewAction.java
// 资产=市值+在途金额+未付收益
double totPrdValue = answerDataset.getAnswerDataset().getDouble(ITag.TotPrdValue);
double onwayAmt = answerDataset.getAnswerDataset().getDouble(ITag.OnwayAmt);
double incomeOnway = answerDataset.getAnswerDataset().getDouble(ITag.IncomeOnway);

if (prdType.equals(IDict.K_CPLX.CPLX_YEBQUE)){
    // 余额宝特殊处理
    answerDataset.setValue(ITag.TotValue, BigDecimalUtil.add(totPrdValue,
        answerDataset.getAnswerDataset().getDouble(ITag.SquareAmt)));
}else {
    // 普通基金
    answerDataset.setValue(ITag.TotValue, BigDecimalUtil.add(totPrdValue, onwayAmt, incomeOnway));
}
```

#### 3.2.4 业务场景
1. **资产查询**：客户查询总资产时，需要看到包括在途资金在内的全部资产
2. **资产统计**：银行或机构需要统计客户的总资产规模
3. **风险评估**：根据总资产评估客户的风险承受能力

#### 3.2.5 与TotPrdValue的区别
- `TotPrdValue`：仅包含已确认的市值（份额×净值）
- `TotValue`：包含市值+在途资金+未付收益，更全面地反映客户资产

#### 3.2.6 注意事项
1. 余额宝产品的计算方式与普通基金不同
2. 在途金额包括在途申请资金和在途入账资金两部分
3. 未付收益只对普通基金产品计入总资产

## 四、字段取值流程

### 4.1 数据查询流程

1. **客户信息查询**：`checkData()`方法
   - 查询客户基本信息
   - 获取分表信息

2. **产品列表获取**：`getClientProductList()`和`getProductList()`方法
   - 查询客户持有的产品列表
   - 查询在途交易涉及的产品
   - 查询在途入账涉及的产品

3. **按产品类型查询**：`getAnswerByPrdType()`方法
   - 初始化字段
   - 按产品查询数据：`getDataByPrd()`
   - 查询在途数据：`getOnWay()`

4. **数据汇总**：`getSumAnswer()`方法
   - 汇总所有产品类型的字段值

### 4.2 字段计算顺序

```
1. 初始化所有字段为0
2. 查询份额信息（getShare0）
   - TotVol, UseVol, FrozenVol, TotPrdValue, IncomeOnway
3. 查询历史累计收益（getShareextaccum）
   - HisProfitLoss, HisTotCost, HisProfitLossRate
4. 查询浮动盈亏（getProfitData）
   - ProfitLoss, TotCost, ProfitLossRate
   - HoldProfitLoss, HoldTotCost, HoldProfitLossRate
   - YstdyProfitLoss, YstdyIncome, TodayIncome
5. 查询在途资金（getOnWay）
   - OnwayAmt, BuyAmtOnWay, SquareAmt
6. 计算总资产（TotValue）
   - 普通基金：TotPrdValue + OnwayAmt + IncomeOnway
   - 余额宝：TotPrdValue + SquareAmt
7. 汇总所有字段（getSumAnswer）
```

## 七、常见问题

### Q1: TotPrdValue和TotValue的区别是什么？
**A**: 
- `TotPrdValue`：总市值，仅包含已确认的份额×净值
- `TotValue`：总资产，包含市值+在途资金+未付收益，更全面地反映客户资产

### Q2: 余额宝产品的TotPrdValue为什么与普通基金不同？
**A**: 余额宝产品需要特殊处理：
- 需要减去快速过户冻结部分（快速赎回已确认但未到账的份额）
- 可用份额需要加上未付收益

### Q3: 在途金额包括哪些？
**A**: 在途金额包括两部分：
- `BuyAmtOnWay`：在途申请资金（已提交但未确认的交易）
- `SquareAmt`：在途入账资金（已确认但未到账的资金）

### Q4: 为什么余额宝的TotValue计算方式不同？
**A**: 余额宝产品的总市值已经包含了未付收益，所以总资产只需要加上在途入账资金即可，不需要再加未付收益。

### Q5: 如何判断收益是否计算完成？
**A**: 通过`YstdyCompleteFlag`和`TodayCompleteFlag`字段判断：
- `"1"`：已完成
- `"0"`：未完成

## 八、总结

T110699接口提供了全面的客户资产查询功能，主要字段包括：

1. **TotPrdValue（总市值/prdValue）**：反映客户持有产品的当前市场价值
2. **TotValue（总资产/totAmt）**：反映客户的总资产，包括市值、在途资金和未付收益

这两个字段是接口的核心字段，准确反映了客户的资产状况。在计算时需要注意：
- 普通基金和余额宝产品的计算逻辑不同
- 精度处理需要特别注意
- 在途资金和未付收益的计入方式不同

接口还提供了丰富的盈亏、收益、在途资金等字段，满足各种业务场景的需求。
