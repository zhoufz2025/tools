# 基金账务状态流转分析

## 一、账务状态概述

### 1.1 账务状态定义

账务状态（`liqu_status`）是流水表（`tbdxfundtransreq`）中的核心字段，用于标识交易的资金处理状态。

**字典定义**：`K_ZWZT`（账务状态）

**数据类型**：`varchar(1)`

**字段位置**：
- 流水表：`tbdxfundtransreq{1-16}.liqu_status`
- 历史流水表：`tbdxfundhistransreq{1-16}.liqu_status`
- 批量流水表：`tbdxfundbatchreq.liqu_status`

### 1.2 账务状态字典值

| 字典值 | 常量名 | 说明 | 应用场景 |
|--------|--------|------|---------|
| `'0'` | `ZWZT_NO` | 账务无关 | 不涉及资金处理的交易（查询、撤单等） |
| `'1'` | `ZWZT_FORFROZEN` | 待冻结 | 预受理模式下，账务模式为冻结，交易尚未发送主机 |
| `'2'` | `ZWZT_FORTRANSFER` | 待扣款 | 预受理模式下，账务模式为转账，交易尚未发送主机 |
| `'3'` | `ZWZT_FROZEN` | 已冻结 | 主机冻结成功，资金已冻结 |
| `'4'` | `ZWZT_TRANSFER` | 已扣款 | 主机扣款成功，资金已扣款 |
| `'5'` | `ZWZT_FORUNF2T` | 待解冻扣款 | 需要解冻并扣款（实时赎回等场景） |
| `'6'` | `ZWZT_ADD` | 已上账 | 主机上账成功，资金已入账 |
| `'7'` | `ZWZT_FORADD` | 待上账 | 待上账（较少使用） |
| `'8'` | `ZWZT_UNFROZEN` | 已解冻 | 主机解冻成功，已解冻资金 |
| `'9'` | `ZWZT_ADDFROZEN` | 上账并冻结 | 主机上账并冻结（实时赎回场景） |
| `'Z'` | `ZWZT_DOING` | 处理中 | 主机处理中（临时状态） |
| `'A'` | `ZWZT_UNTRANSFER` | 扣款失败 | 主机扣款失败（清算环节差错） |
| `'B'` | `ZWZT_FORCHECK` | 待查证 | 待查证状态 |

### 1.3 账务模式定义

账务模式（`liqu_mode`）是产品级别的配置，决定了购买交易的资金处理方式。

**字典定义**：`K_ZWMS`（账务模式）

**账务模式字典值**：

| 字典值 | 常量名 | 说明 | 资金处理方式 |
|--------|--------|------|-------------|
| `'0'` | `ZWMS_TRANSFER` | 转账模式 | 购买时直接扣款，不经过冻结 |
| `'1'` | `ZWMS_FROZEN` | 冻结模式 | 购买时先冻结，确认后扣款 |

**产品配置字段**：
- `liqu_mode_iss`：募集期账务模式（产品状态为发行中）
- `liqu_mode_open`：开放期账务模式（产品状态为开放、存续等）

**配置位置**：
- 产品表：`tbdxfundproduct.liqu_mode_iss`、`tbdxfundproduct.liqu_mode_open`

### 1.4 交易状态定义（status）

交易状态（`status`）是流水表（`tbdxfundtransreq`）中的另一个核心字段，用于标识交易的**业务处理状态**（交易生命周期状态），与**账务状态**（liqu_status）是两个不同维度的状态。

**字典定义**：`K_JYZT`（交易状态）

**数据类型**：`varchar(1)`

**常用交易状态字典值**：

| 字典值 | 常量名 | 说明 | 应用场景 |
|--------|--------|------|---------|
| `'0'` | `JYZT_PREPROCESS` | 预受理 | 预受理模式（非开市时间），待批量处理 |
| `'1'` | `JYZT_PROCESS` | 受理 | 受理模式（开市时间），已受理 |
| `'2'` | `JYZT_CANCEL` | 已撤单 | 交易已撤单 |
| `'3'` | `JYZT_ERASE` | 已抹账 | 交易已抹账 |
| `'4'` | `JYZT_FAIL` | 失败 | 交易失败 |
| `'8'` | `JYZT_CFM_SUCC` | 确认成功 | TA确认成功 |
| `'9'` | `JYZT_CFM_FAIL` | 确认失败 | TA确认失败 |
| `'F'` | `JYZT_BATCHFAIL` | 批处理失败 | 批量处理失败（如T210207批量扣款失败） |
| `'S'` | `JYZT_SUCC` | 成功 | 联机交易成功 |
| `'Z'` | `JYZT_DOING` | 交易中 | 交易中（临时状态） |
| `'P'` | `JYZT_PREAPPROVE` | 待审批 | 待审批 |

**status字段设置逻辑**（`DxFundTransStatusService.checkTransStatus()`）：

```java
// 根据 交易是否导出、受理方式 赋值交易状态
if (IDict.K_SLFS.SLFS_PREPROCESS.equals(dealModeSet.getDealMode())) {
    dealModeSet.setStatus(IDict.K_JYZT.JYZT_PREPROCESS);  // '0' 预受理
} else {
    dealModeSet.setStatus(IDict.K_JYZT.JYZT_PROCESS);      // '1' 受理
}
```

**处理模式与交易状态的对应关系**：

| 处理模式 | deal_mode | 交易时机 | 初始status | 说明 |
|---------|-----------|---------|-----------|------|
| 受理模式 | `'0'` | 开市时间内 | `'1'`（受理） | 立即发送主机，实时处理 |
| 预受理模式 | `'1'` | 非开市时间 | `'0'`（预受理） | 待批量处理（T210207） |

**参考代码**：
- `DxFundTransStatusService.java` 第194-225行：交易状态赋值逻辑
- `DxFundTransReqService.java` 第237行：`transReq.setStatus(transPub.getDealModeSet().getStatus())`
- `IDict.java` 第1676-1821行：`K_JYZT` 字典定义

**重要说明**：
- **`status`** 表示交易的业务处理状态（预受理、受理、确认成功等）
- **`liqu_status`** 表示交易的账务处理状态（待扣款、已扣款、已上账等）
- 两者相互独立，分别记录不同维度的状态信息

## 二、影响账务状态流转的因素

### 2.1 产品状态（prd_status）

产品状态决定了使用哪个账务模式配置：

| 产品状态 | 说明 | 使用的账务模式 |
|---------|------|--------------|
| `'0'`（发行中 - CPZT_ISS） | 募集期 | `liqu_mode_iss` |
| `'V'`（预约期 - CPZT_BOOKING） | 预约认购期 | `liqu_mode_iss` |
| `'1'`（开放 - CPZT_OPEN） | 开放期 | `liqu_mode_open` |
| `'2'`（存续 - CPZT_EXIST） | 存续期 | `liqu_mode_open` |
| `'3'`（封闭 - CPZT_CLOSE） | 封闭期 | `liqu_mode_open` |
| 其他状态 | 其他 | `liqu_mode_open` |

### 2.2 处理模式（deal_mode）

处理模式决定了交易的处理方式：

| 处理模式 | 说明 | 初始账务状态 |
|---------|------|------------|
| `'0'`（受理 - SLFS_ACCEPT） | 直接受理，立即发送主机 | 发送主机成功后：`'3'`（已冻结）或 `'4'`（已扣款） |
| `'1'`（预受理 - SLFS_PREPROCESS） | 预受理，不立即发送主机 | `'1'`（待冻结）或 `'2'`（待扣款） |

**处理模式判断逻辑**：
- 由交易状态控制服务（`DxFundTransStatusService`）根据产品开闭市时间、工作日、交易时段等判断
- 在开市时间内，且为工作日，且交易允许的时段内：受理模式
- 在闭市、非工作日、或不允许的时段：预受理模式

### 2.3 账务模式（liqu_mode）

根据产品状态选择的账务模式（`liqu_mode_iss` 或 `liqu_mode_open`）：

**转账模式（`liqu_mode='0'`）**：
- 预受理时：`liqu_status='2'`（待扣款）
- 发送主机后：`liqu_status='4'`（已扣款）
- 主机交易码：`300200`（扣款）

**冻结模式（`liqu_mode='1'`）**：
- 预受理时：`liqu_status='1'`（待冻结）
- 发送主机后：`liqu_status='3'`（已冻结）
- 主机交易码：`300201`（冻结）
- 确认成功后：`liqu_status='4'`（已扣款，通过批量解冻扣款）

### 2.4 主机交易代码（host_trans_code）

主机交易代码决定了调用主机的哪个接口，从而影响账务状态：

| 主机交易码 | 常量名 | 说明 | 执行后账务状态 |
|-----------|--------|------|---------------|
| `300200` | `HOSTDRAWMONEY` | 扣款（资金转出） | `'4'`（已扣款） |
| `300201` | `HOSTFROZENMONEY` | 冻结（资金冻结） | `'3'`（已冻结） |
| `300202` | `HOSTDEPOSITMONEY` | 入账（撤资金转出） | `'6'`（已上账） |
| `300203` | `HOSTUNFROZENMONEY` | 解冻（撤资金冻结） | `'8'`（已解冻） |
| `300204` | `HOSTCANCELLQUICKMONEY` | 撤资金转入 | `'4'`（已扣款） |
| `300209` | `HOSTQUICKMONEY` | 资金转入 | `'6'`（已上账） |
| `300301` | `HOSTCHECKACC` | 验密（账户校验） | 不改变账务状态 |
| `300404` | `HOSTUNFROZENDRAWMONEY` | 解冻扣款 | `'4'`（已扣款） |

**参考代码**：`com.hundsun.lcpt.constant.IConstant`

### 2.5 主机交易码设置流程（购买交易）

**核心调用链路**：

```
T110200HSAdapter.action()
  ↓
checkData() - 调用getTransPub获取交易公共数据
  ↓
DxFundServiceFactory.getTransPubService().getTransPub()
  ↓
toLocalFirst() - 发送主机前本地处理
  ↓
transToTransReq() - 调用getHostCodeAndLiquStatus设置主机交易码
  ↓
DxFundTransPubService.getHostCodeAndLiquStatus(transPub)
  ↓
将主机交易码和账务状态设置到流水表
```

**关键代码位置**：

1. **主机交易码设置入口**：`T110200HSAdapter.transToTransReq()`

```java
// 第485行：调用getHostCodeAndLiquStatus方法
DxFundServiceFactory.getTransPubService().getHostCodeAndLiquStatus(transVar.getTransPub());

// 第487-489行：将设置结果赋值到流水表
transVar.getTransPub().getTransReq().setHostTransCode(transVar.getTransPub().getHostTransCode());
transVar.getTransPub().getTransReq().setLiquStatus(transVar.getTransPub().getLiquStatus());
```

2. **主机交易码设置核心方法**：`DxFundTransPubService.getHostCodeAndLiquStatus()`

该方法根据以下因素决定主机交易码和账务状态：

**（1）特殊产品类型优先处理**：

- **货币净值产品（开放期）**：
  ```java
  transPub.setHostTransCode(IConstant.HOSTDRAWMONEY);     // 300200
  transPub.setLiquStatus(IDict.K_ZWZT.ZWZT_FORTRANSFER);  // '2'
  ```

- **定开产品预约期**（参数`CYCLE_PRD_PRE_LIQU_MODE`控制）：
  - `=0`：不处理账务
    ```java
    transPub.setHostTransCode(IConstant.HOSTCHECKACC);      // 300301
    transPub.setLiquStatus(IDict.K_ZWZT.ZWZT_FORTRANSFER);  // '2'
    ```
  - `=1`：冻结模式
    ```java
    transPub.setHostTransCode(IConstant.HOSTFROZENMONEY);   // 300201
    transPub.setLiquStatus(IDict.K_ZWZT.ZWZT_FROZEN);       // '3'
    ```

**（2）根据产品状态选择账务模式**：

```java
String liquMode = null;
if (IDict.K_CPZT.CPZT_ISS.equals(transPub.getProduct().getPrdStatus())
        || IDict.K_CPZT.CPZT_BOOKING.equals(transPub.getProduct().getPrdStatus())) {
    liquMode = transPub.getProduct().getLiquModeIss();    // 募集期/预约期账务模式
} else {
    liquMode = transPub.getProduct().getLiquModeOpen();   // 开放期账务模式
}
```

**（3）根据受理模式和账务模式设置**：

| 受理模式 | 账务模式 | 产品控制位 | 主机交易码 | 账务状态 | 说明 |
|---------|---------|----------|----------|---------|------|
| 预受理 | 冻结 | 第23位=0（默认） | `300301`（验密） | `'1'`（待冻结） | 不冻结资金 |
| 预受理 | 冻结 | 第23位=1 | `300201`（冻结） | `'1'`（待冻结） | 冻结资金 |
| 预受理 | 转账 | 第45位=0（默认） | `300301`（验密） | `'2'`（待扣款） | 不处理账务 |
| 预受理 | 转账 | 第45位=1 | `300201`（冻结） | `'1'`（待冻结） | 预受理冻结 |
| 预受理 | 转账 | 第45位=2 | `300200`（扣款） | `'2'`（待扣款） | 预受理扣款 |
| 受理 | 冻结 | - | `300201`（冻结） | `'1'`（待冻结） | 立即冻结 |
| 受理 | 转账 | - | `300200`（扣款） | `'2'`（待扣款） | 立即扣款 |

3. **特殊场景覆盖**：

```java
// （1）行外卡收款确认模式：强制扣款
if (transVar.isPayConfirm()) {
    transVar.getTransPub().getTransReq().setHostTransCode(IConstant.HOSTDRAWMONEY);      // 300200
    transVar.getTransPub().getTransReq().setLiquStatus(IDict.K_ZWZT.ZWZT_FORTRANSFER);   // '2'
}

// （2）同业客户审批模式：强制冻结
String mode = DxFundParamUtil.getDxFundSysParamValue(IDxFundParamConstant.Need_Check_Mode, "0");
if (IDict.K_YORN.YORN_YES.equals(mode) && 
    IDict.K_JYQD.JYQD_JGEZT.equals(getRequestDataset(context).getString(ITag.Channel))) {
    transVar.getTransPub().getTransReq().setHostTransCode(IConstant.HOSTFROZENMONEY);    // 300201
    transVar.getTransPub().getTransReq().setLiquStatus(IDict.K_ZWZT.ZWZT_FORFROZEN);     // '1'
}

// （3）同业基金账务模式根据渠道上送（第505-528行）
String tradeClientType = ParamCache.getInstance().getSysParamValue(IParamConstant.TRADE_CLIENT_TYPE, "");
if (!DataUtil.isNullStr(tradeClientType) &&
        tradeClientType.contains(transVar.getTransPub().getClientSeller().getHostClientType())) {
    String liquModeRequest = context.getRequestDataset().getString(ITag.LiquMode);
    if (IDict.K_ZWMS.ZWMS_FROZEN.equals(liquModeRequest)) {
        // 冻结模式
        transVar.getTransPub().getTransReq().setHostTransCode(IConstant.HOSTFROZENMONEY);    // 300201
        transVar.getTransPub().getTransReq().setLiquStatus(IDict.K_ZWZT.ZWZT_FROZEN);        // '3'
    } else if (IDict.K_ZWMS.ZWMS_TRANSFER.equals(liquModeRequest)) {
        // 转账模式
        transVar.getTransPub().getTransReq().setHostTransCode(IConstant.HOSTDRAWMONEY);      // 300200
        transVar.getTransPub().getTransReq().setLiquStatus(IDict.K_ZWZT.ZWZT_TRANSFER);      // '4'
    }
}
```

**设置逻辑总结**：

主机交易码的设置遵循以下优先级：
1. **特殊场景覆盖**（行外卡、同业等）优先级最高
2. **特殊产品类型**（货币净值、定开预约期等）次之
3. **常规逻辑**（受理模式+账务模式+产品控制位）最后

### 2.7 交易代码（trans_code）

不同的交易代码有不同的账务处理逻辑：

**购买类交易**：
- **110200**：`基金代销产品购买`（普通购买）
- **110254**：`基金代销个人/机构定向预约`
- **110256**：`基金代销个人/机构定向购买`
- **110204**：`基金产品转换`
- **110205**：`基金产品转托管入`
- **110206**：`基金产品转托管出`
- 初始账务状态：根据账务模式，`'1'`（待冻结）或 `'2'`（待扣款）
- 目标账务状态：`'3'`（已冻结）或 `'4'`（已扣款）

**定投协议类交易**（不涉及账务）：
- **110208**：`基金代销定期定额开通`（开通定投协议）
- **110209**：`基金代销定期定额修改`（修改定投协议）
- **110210**：`基金代销定期定额关闭`（关闭定投协议）
- 账务状态：`'0'`（账务无关）
- 主机交易码：`300301`（验密）
- 说明：这些交易只生成/修改/关闭定投协议，不进行资金处理

**赎回类交易**（110202、110203等）：
- **110202**：`基金代销产品赎回`（普通赎回）
- **110203**：`基金代销产品预约赎回`
- **110406**：`强行赎回`（TA发起）
- 初始账务状态：`'0'`（账务无关，先扣份额）
- 份额确认后：生成入账流水
- 目标账务状态：`'6'`（已上账）

**快速赎回交易**（110516、118516等）：
- 初始账务状态：`'0'`（账务无关）
- 发送TA后：`'6'`（已上账，先预上账）
- TA确认成功后：`'9'`（上账并冻结）
- 批量解冻扣款后：`'4'`（已扣款）
- **说明**：110516为基金代销快速赎回，118516为组合宝批量快赎

**定向购买交易**（110254、110256）：
- 110254：基金代销个人/机构定向预约
- 110256：基金代销个人/机构定向购买
- 账务处理与常规购买类似

**分红交易**（TA发起）：
- 初始账务状态：`'0'`（账务无关）
- 确认导入后：生成入账流水
- 目标账务状态：`'6'`（已上账）

**撤单交易**：
- **110219**：`基金代销客户交易类交易撤单`
- **110880**：`撤单交易`（联机撤单）
- **110998**：`基金代销定向预约撤销`
- 如果原交易已冻结（`'3'`）：解冻，目标状态 `'8'`（已解冻）
- 如果原交易已扣款（`'4'`）：不处理账务或上账退款，目标状态 `'6'`（已上账）

## 三、账务状态流转场景

### 3.1 购买交易 - 转账模式

**适用交易**：
- **110200**（基金代销产品购买）
- **110256**（定向购买）

**账务流转**：购买交易是**扣客户资金**购买基金份额，账务流转到**已扣款**即结束

**流程**：

```
[交易发起]
  ↓
判断处理模式
  ├─ 受理模式（deal_mode='0'）
  │   ├─ 设置初始账务状态：liqu_status='2'（待扣款）
  │   │   host_trans_code='300200'（扣款）
  │   │   status='1'（受理）
  │   ├─ 发送主机扣款
  │   └─ 主机扣款成功
  │       └─ liqu_status='4'（已扣款）✅ 账务完成
  │           status='S'（成功）
  │
  └─ 预受理模式（deal_mode='1'）
      ├─ 设置初始账务状态：liqu_status='2'（待扣款）

### 3.4 赎回交易 - 给客户上账

**适用交易**：
- **110202**（基金代销产品赎回）- 普通赎回
- **110203**（基金代销产品预约赎回）
- **110406**（强行赎回）- TA发起

**账务流转**：赎回交易是**给客户上账**赎回款，账务流转到**已上账**才完成

**流程**：

```

  ├─ 计算赎回金额（根据净值、份额等）
  └─ 生成入账流水
      ├─ 入账流水：liqu_status='0'（待上账）
      └─ 入账流水：status='1'（受理）
        ↓

  ├─ 发送主机上账（host_trans_code='300202'）

```

**关键节点**：
1. **交易创建**：`liqu_status='0'`（账务无关，先扣除客户份额）

**说明**：
- 赎回交易是**给客户上账**的典型场景
- 先扣份额（不涉及资金账务状态）
- TA确认后，通过入账流水给客户上账赎回款
- 账务状态流转：`'0'`（待上账）→ `'6'`（已上账）

  │       ├─ 查询预受理流水（status='0', deal_mode='1'）
  │       ├─ 判断交易状态是否允许
  │       │   ├─ 交易状态允许：status='1'（正常交易）
  │       │   └─ 交易状态不允许：status='0'（不允许）
  │       │
  │       └─ 调用batchSendToHost()处理账务
  │           ├─ packBatchSendToHost()：组装主机请求
  │           │   ├─ status='1'：正常扣款/冻结
  │           │   │   ├─ liqu_status='2'：hostTransCode='300200'（扣款）
  │           │   │   └─ liqu_status='1'：hostTransCode='300201'（冻结）
  │           │   └─ status='0'：交易不允许，需要解冻/退款
  │           │       ├─ liqu_status='3'：hostTransCode='300203'（解冻）
  │           │       └─ liqu_status='4'：hostTransCode='300202'（上账退款）
  │           │
  │           └─ executeBatchSendToHost()：发送主机并更新状态
  │               ├─ 发送主机请求
  │               ├─ 更新交易状态：
  │               │   ├─ 成功：status='1'（受理）
  │               │   └─ 失败：status='F'（批量失败）
  │               └─ 更新账务状态（成功时）：
  │                   ├─ liqu_status='1'（待冻结）→ '3'（已冻结）
  │                   ├─ liqu_status='2'（待扣款）→ '4'（已扣款）
  │                   └─ liqu_status='3'（已冻结）→ '4'（已扣款）[解冻扣款]
  │
  └─ 第三步：batchFailUnFrozen()
      └─ 已冻结资金的购买交易未能转受理，做解冻操作
```

### 5.2 账务处理核心方法

**方法调用链**：
```
T210207HSAdapter.action()
  └─ Task210207.run()
      └─ DxFundHostService.batchSendToHost()
          ├─ packBatchSendToHost()：组装请求
          └─ executeBatchSendToHost()：执行并更新
```

**executeBatchSendToHost核心逻辑**：

```java
// 1. 发送主机
response = HostServiceFactory.getHostClient().sendReceive(hostRequest);

// 2. 根据主机响应更新账务状态
if (IErrMsg.ERR_HOSTSUCC.equals(response.getString(ITag.ErrorNo))) {
    // 主机成功
    transReq.setStatus(IDict.K_JYZT.JYZT_PROCESS); // 处理中
    transReq.setHostDate(response.getInt(ITag.HostDate));
    transReq.setHostSerial(response.getString(ITag.HostSerial));
    
    // 更新账务状态
    if (IDict.K_ZWZT.ZWZT_FORFROZEN.equals(transReq.getLiquStatus())) {
        transReq.setLiquStatus(IDict.K_ZWZT.ZWZT_FROZEN); // 1→3
    } else if (IDict.K_ZWZT.ZWZT_FORTRANSFER.equals(transReq.getLiquStatus())) {
        transReq.setLiquStatus(IDict.K_ZWZT.ZWZT_TRANSFER); // 2→4
    } else if (IDict.K_ZWZT.ZWZT_FROZEN.equals(transReq.getLiquStatus())
            && IConstant.HOSTUNFROZENDRAWMONEY.equals(transReq.getHostTransCode())) {
        // 预约产品解冻扣款
        transReq.setLiquStatus(IDict.K_ZWZT.ZWZT_TRANSFER); // 3→4
        addBatchReq(context, transReq, status, taInfo, hostRequest, response);
    }
} else {
    // 主机失败或交易状态不允许
    transReq.setStatus(IDict.K_JYZT.JYZT_BATCHFAIL); // 批量失败
    
    // 交易状态不允许，发送了解冻
    if (IDict.K_ZWZT.ZWZT_FROZEN.equals(transReq.getLiquStatus()) 
        || IDict.K_ZWZT.ZWZT_FORUNF2T.equals(transReq.getLiquStatus())) {
        transReq.setLiquStatus(IDict.K_ZWZT.ZWZT_UNFROZEN); // 3→8
    }
    addBatchReq(context, transReq, status, taInfo, hostRequest, response);
}

// 3. 更新流水
DxFundServiceFactory.getTransReqService().modifyTransReq(transReq);
```

| '1' | 交易状态允许，正常交易 | 发送扣款/冻结 | 300200/300202 |
| '0' | 交易状态不允许 | 发送解冻/退款 | 300203/300209 |

## 七、需要给客户上账的场景总结

### 7.1 场景分类

基金业务中，**给客户上账**（`liqu_status='6'`）的场景包括：

#### 1. 赎回类交易（客户卖出基金获得资金）
- **普通赎回**（110202）- 基金代销产品赎回
- **预约赎回**（110203）- 基金代销产品预约赎回
- **快速赎回**（110516、118516）- 基金代销快速赎回、组合宝批量快赎
- **强行赎回**（110406）- TA发起的强行赎回

**特点**：
- 客户先扣除份额
- TA确认后，根据净值计算赎回金额
- 生成入账流水，**给客户上账赎回款**
- 账务状态：`'0'`（待上账）→ `'6'`（已上账）

#### 2. 分红类交易（客户获得分红收益）
- **现金分红**（TA发起）
- **红利到账**（TA发起）

**特点**：
- TA发起分红，销售系统导入确认数据
- 计算分红金额
- 生成入账流水，**给客户上账分红款**
- 账务状态：`'0'`（待上账）→ `'6'`（已上账）

#### 3. 退款类交易（退还客户资金）
- **购买确认失败退款**（已扣款的购买交易）
- **购买撤单退款**（已扣款的购买交易撤单）
- **认购失败退款**（募集失败退款）

**特点**：
- 原交易已扣除客户资金（`liqu_status='4'`）
- 确认失败或撤单需要退款
- 生成入账流水，**给客户上账退款**
- 账务状态：`'0'`（待上账）→ `'6'`（已上账）

#### 4. 到期类交易（产品到期返还本金收益）
- **到期兑付**（TA发起）
- **产品清算**（TA发起）

**特点**：
- 产品到期，TA发起兑付
- 计算本金+收益
- 生成入账流水，**给客户上账兑付款**
- 账务状态：`'0'`（待上账）→ `'6'`（已上账）

#### 5. 调账类交易（人工调账）
- **资金强增**（人工操作）
- **资金调账**（人工操作）

**特点**：
- 人工发起的调账
- 生成入账流水，**给客户上账调整金额**
- 账务状态：`'0'`（待上账）→ `'6'`（已上账）

### 7.2 不需要给客户上账的场景

#### 1. 购买类交易（客户买入基金支付资金）
- **认购**（110100、110102等）
- **申购**（110200、110204等）
- **定投**（110300等）

**特点**：
- **扣除客户资金**，不是上账
- 账务状态流转到 `'4'`（已扣款）即完成
- **不生成入账流水**
- 客户获得的是基金份额，不是资金

#### 2. 购买撤单（已冻结流水）
- **撤单**（原交易已冻结）

**特点**：
- 原交易只是冻结资金（`liqu_status='3'`），未实际扣款
- 撤单直接解冻（`liqu_status='8'`）
- **资金自动返还客户账户**，不需要生成入账流水

#### 3. 查询类交易
- **账户查询**、**份额查询**等

**特点**：
- 不涉及资金处理
- `liqu_status='0'`（账务无关）

### 7.3 入账流水表（tbdxfundsquare）

**用途**：专门记录需要**给客户上账**的流水

**主要字段**：
- `square_no`：入账流水号
- `serial_no`：关联的交易流水号
- `trans_code`：交易代码
- `amt`：入账金额
- `liqu_status`：账务状态（`'0'` 待上账 → `'6'` 已上账）
- `status`：入账标志（`'0'` 未入账 → `'2'` 已入账）

**生成时机**：
- 赎回TA确认成功后（T210110清算）
- 分红TA确认导入后（T210110清算）
- 购买确认失败后（T210110清算）
- 购买撤单成功后（T210110清算）
- 到期兑付确认后（T210110清算）

**上账时机**：
- T210013节点生成入账文件
- 发送主机上账（`host_trans_code='300202'`）
- 更新账务状态为 `'6'`（已上账）

## 九、常见问题与注意事项

### 9.1 账务状态错误流转

**错误案例**：
```
扣款失败：'4'（已扣款）→ 'A'（扣款失败） ❌
```

**正确流转**：
```
差错处理：'Z'（处理中）→ '3'（已冻结，差错）或 '8'（已解冻，成功）
```

**原因**：
- `'A'`（扣款失败）不是从 `'4'`（已扣款）流转来的
- 是批量解冻扣款差错处理时，从 `'Z'`（处理中）恢复为 `'3'`（已冻结）
- 在入账环节，使用 `status='5'` 或 `'6'` 标识入账失败

### 9.2 预受理与受理模式

**区别**：
- **受理模式**（`deal_mode='0'`）：立即发送主机，账务状态直接更新
- **预受理模式**（`deal_mode='1'`）：先设置待处理状态，批量发送主机

**判断逻辑**：
- 由 `DxFundTransStatusService` 根据开闭市时间、工作日等判断
- 在开市时间内：受理模式
- 在闭市、非工作日：预受理模式

### 9.3 账务模式与主机交易码

**对应关系**：
| 账务模式 | 预受理状态 | 批量节点 | 主机交易码 | 结果状态 |
|---------|-----------|---------|-----------|---------|
| 转账（0） | 待扣款（2） | T210207（交易片区） | 300200 | 已扣款（4） |
| 冻结（1） | 待冻结（1） | T210207（交易片区） | 300201 | 已冻结（3） |
| 冻结（1） | 已冻结（3） | T210207（交易片区） | 300404 | 已扣款（4） |
| - | 已冻结（3） | T210600（交易片区） | 300404 | 已扣款（4） |

### 9.4 购买与赎回的本质区别

**购买交易**（客户付款买基金）：
- **资金方向**：客户 → 基金公司（扣款）
- **账务状态**：`'1'`或`'2'`（待处理）→ `'3'`或`'4'`（已冻结/已扣款）✅ **结束**
- **不生成入账流水**
- **客户获得**：基金份额

**赎回交易**（客户卖基金获款）：
- **资金方向**：基金公司 → 客户（上账）
- **账务状态**：`'0'`（待上账）→ `'6'`（已上账）✅ **结束**
- **生成入账流水**：`tbdxfundsquare`
- **客户获得**：资金

### 9.5 入账流水与交易流水

**区别**：
- **交易流水**（`tbdxfundtransreq`）：记录客户交易信息
  - 购买：`liqu_status='1'、'2'、'3'、'4'`
  - 赎回：`liqu_status='0'`（账务无关）
  
- **入账流水**（`tbdxfundsquare`）：记录资金入账信息
  - 初始：`liqu_status='0'`（待上账）
  - 上账后：`liqu_status='6'`（已上账）
  - 使用 `status` 字段标识入账状态

### 9.6 对账范围

**参与对账的账务状态**（默认）：
- `'3'`（已冻结）
- `'4'`（已扣款）
- `'6'`（已上账）
- `'9'`（上账并冻结）

**不参与对账的账务状态**：
- `'0'`（账务无关）
- `'1'`（待冻结）
- `'2'`（待扣款）
- `'5'`（待解冻扣款）
- `'7'`（待上账）
- `'8'`（已解冻）
- `'Z'`（处理中）
- `'A'`（扣款失败）
- `'B'`（待查证）

**可个性化配置**：
- 通过参数 `LiquStatusConfig` 自定义参与对账的账务状态列表
- 格式：`'3'~'4'~'6'~'9'`
