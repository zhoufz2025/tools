# T210503 查询库数据同步 —— 功能实现与设计说明

> 子系统：基金代销（dxfund）  
> 节点号：`210503` / Job：`J210503`  
> 节点名称：查询库数据同步  
> 片区形态：交易片区导出 + 公共片区导入（标准双节点）  
> 文档依据：交易侧 `TDXFUND210503HSAdapter`、公共侧 `TPUB210503HSAdapter` 及各 `Sync*Task` 源码  
> 整理日期：20260916

---

## 1. 节点定位与设计目标

210503 是基金代销日终链路中的**查询库数据同步**节点，作用是把交易片区（BN）中的业务明细表，按参数选择性导出为标准文件，再由公共片区（BC）导入到**查询表（*qry）或公共侧同名表**，供管理台查询、报表、资金监控、销售看板等依赖公共库数据的场景使用。

设计要点：

1. **先交易后公共**：调度上 `J210503T01(DXFUND210503)` → `J210503T02(PUB210503)`。
2. **按位开关控制同步表**：份额表另有「每日/指定日期」开关；其余表由 `T210503_SYNC_TABLE_CONTROL_FLAG` 按位控制。
3. **多线程并发**：各同步 Task 并发执行，线程数/队列由 `PROCNUM210503`、`QUEUESIZE210503` 控制（默认均为 5）。
4. **与 DataX 互斥**：公共侧导入前对目标表加锁（`LockUtil`），降低与 DataX 同步冲突风险。

### 2.1 调度结构

## 3. 总体数据流转

```text
日终调度
   │
   ▼
┌──────────────────────────────────────────────────────────┐
│ J210503T01  DXFUND210503（交易片区）                       │
│  1. 读参数，组装启用的 Sync*Task                            │
│  2. 线程池并发执行各 Task                                   │
│  3. Task.collectData：分表 UNION ALL 拼导出 SQL             │
│  4. BaseStatsTask.expAreaStatsFile：                        │
│       StandardFileWriter 写文件 → sendFileToServer          │
│  5. 应答回传 SyncTables / SyncFileNames / AreaId            │
└────────────────────────────┬─────────────────────────────┘
                             │ 标准同步文件
                             │ 命名：{目标表名}~{taCode}~{yyyyMMdd}~{areaId}.txt
                             │ taCode 通常为 000000；areaId=1..总片区数
                             ▼
┌──────────────────────────────────────────────────────────┐
│ J210503T02  PUB210503（公共片区）                          │
│  1. 按**同一套参数**独立组装 Task（不解析 T01 应答串选型）   │
│  2. 并发执行：Lock →（按模式 truncate）→ getBnData          │
│  3. getBnData：按片区收齐文件 → StandardFileReader 导入     │
│     （DataInOne=1 同库场景直接跳过文件收发）                 │
└──────────────────────────────────────────────────────────┘
                             │
                             ▼
               公共库查询表 / 公共侧当前流水表
               （管理台、报表、监控等读取）
```

**说明**：交易应答中的 `SyncTables`/`SyncFileNames` 主要用于监控与 BC 报文展示；公共侧导入决策以本侧参数为准，**不依赖**应答串内容选择 Task。

## 4. 功能实现说明

### 4.1 Adapter 主流程（两侧一致）

1. 读取份额同步日控参数：`T210503_SHARE_SYNC_EVERY_DAY`、`T210503_SHARE_SYNC_DATE`，结合 `sysArg.initDate` 决定是否挂载 `SyncShareInfo`。
2. 读取 `T210503_SYNC_TABLE_CONTROL_FLAG`，按位决定挂载其它 Task。
3. 将 Task 放入 `statsMap`，调用 `concurrentProcess` 提交线程池。
4. 汇总各线程 `failNum`；任一无失败则成功，否则抛业务异常。
5. 交易侧额外 `packAnswer`，回传同步表名与文件名。

### 4.2 控制位与 Task 对照（`T210503_SYNC_TABLE_CONTROL_FLAG`）

取值通过 `ControlFlagUtil.getControlFlagValue("N,0", flag)` 取第 N 位（从 1 起算，缺省 `0`）。

| 位 | 启用条件 | 交易 Task | 公共 Task | 源表 → 目标表 |
|----|----------|-----------|-----------|---------------|
| （非控制位） | 每日同步=1 **或** 系统日=指定同步日 | `SyncShareInfoTask` | 同左 | `tbdxfundshare` → `tbdxfundshareqry` |
| 第1位 | =1 | `SyncShareDtlTask` | 同左 | `tbdxfundsharedtl` → `tbdxfundsharedtlqry` |
| 第2位 | =1 | `SyncShareChgTask` | 同左 | `tbdxfundsharechg` → `tbdxfundsharechgqry` |
| 第3位 | =1 | `SyncTransreqQry` | 同左 | `tbdxfundtransreq` → **`tbdxfundtransreq`**（公共同名，非 *qry） |
| 第4位 | =1 | `SyncShareExtTask` + **`SyncHisShareExtTask`** | **`SyncShareExtTask`（一次导入两张）** | `tbdxfundshareext` → `tbdxfundshareextqry`；`tbdxfundhisshareext` → `tbdxfundhisshareextqry` |
| 第5位 | =1 | `SyncShareExtAccumTask` | 同左 | `tbdxfundshareextaccum` → `tbdxfundshareextaccumqry` |
| 第6位 | =1 | `SyncShareDetailTask` | 同左 | `tbdxfundtasharedetail` → `tbdxfundtasharedetailqry` |
| 第7、8位 | — | **未使用** | **未使用** | 预留 |
| 第9位 | =1 | `SyncSquareQry` | 同左 | `tbdxfundsquare` → `tbdxfundsquareqry` |

**SyncHisShareExtTask**：仅交易侧存在；公共侧由 `SyncShareExtTask` 统一导入 `shareextqry` 与 `hisshareextqry`，增量时再按当日 his 键删除 shareextqry 中重复数据。

现场参数示例（仅示意）：

- `010000001`：开份额变动 + 入账记录（第2、9位）
- `0010` / `00100`：开当前流水（第3位）
- `000111`：开浮动盈亏相关（第4~6位）

## 5. 流转数据条件（全量 / 增量）

### 5.1 模式参数体系

| 参数 | 含义 | 默认 |
|------|------|------|
| `T210503_SYNC_MODE` | 总开关：0 全量 / 1 增量 | 1 |
| `T210503_SHARE_SYNC_MODE` | 份额表分模式（公共 ImpMode 也受其影响） | 1 |
| `T210503_SHARE_DTL_SYNC_MODE` | 份额明细 sharedtl | 1 |
| `T210503_SHARE_CHG_SYNC_MODE` | 份额变动 | 1 |
| `T210503_TRANSREQ_SYNC_MODE` | 当前流水 | 1 |
| `T210503_SHARE_EXT_SYNC_MODE` | 浮动盈亏 | 1 |
| `T210503_HIS_SHARE_EXT_SYNC_MODE` | 历史浮动盈亏 | 1 |
| `T210503_SHARE_EXT_ACCUM_SYNC_MODE` | 累计浮动盈亏 / 历史收益率 | 1 |

**判定规则**：`总参数=1` **且** `分表参数=1` → **增量**；任一为 0 → **全量**。

公共导入 `ImpMode`：默认 merge（0）；份额表在 `T210503_SHARE_SYNC_MODE=0` 时可用 insert（1）。份额查询表公共侧**固定先 truncate**。

### 5.2 各表导出 / 导入条件明细

#### （1）份额 `tbdxfundshare` → `tbdxfundshareqry`

| 项 | 条件 / 行为 |
|----|-------------|
| 是否执行 | `T210503_SHARE_SYNC_EVERY_DAY=1`（默认）**或** `initDate == T210503_SHARE_SYNC_DATE` |
| 交易导出 | 分表 `UNION ALL` 全量 `select a.*`（导出 SQL **不读**增量 where） |
| 公共导入 | 加锁 → **固定 truncate** → `getBnData` |
| 备注 | 业务上「是否跑份额同步」由日控参数决定；表内增量逻辑在交易导出侧当前未按日过滤 |

#### （2）份额明细 `tbdxfundsharedtl` → `tbdxfundsharedtlqry`（第1位）

| 模式 | 交易侧过滤 | 公共侧 |
|------|------------|--------|
| 增量 | `cfm_date = initDate` **或**（`cfm_date <> initDate` 且 `last_modify_date = initDate`） | 不加 truncate，merge 导入 |
| 全量 | 无 where | truncate 后导入 |
| 附加 | — | 若 `SHARE_DTL_MARK_DAYS>0`，再维护 `tbdxfundsharedtlmark`（按 sum_date 删旧+insert） |

#### （3）份额变动 `tbdxfundsharechg` → `tbdxfundsharechgqry`（第2位）

| 模式 | 交易侧过滤 | 公共侧 |
|------|------------|--------|
| 增量 | `cfm_date >= DateUtil.getDate()`（**物理日**，非系统 initDate） | 不 truncate，merge |
| 全量 | 无 where | truncate + 导入 |

> 注意：增量使用物理日，若物理日与清算系统日不一致，现场需按约定评估数据覆盖范围。

#### （4）当前流水 `tbdxfundtransreq` → 公共 `tbdxfundtransreq`（第3位）

| 模式 | 交易侧过滤 | 公共侧 |
|------|------------|--------|
| 增量 | `modify_timestamp >= yyyyMMdd000000`（物理日 0 点，`getTableBy16WithTimeStamp`） | merge |
| 全量 | 无 where | truncate + 导入 |

#### （5）浮动盈亏（第4位）

| 子表 | 交易过滤（增量） | 公共处理 |
|------|------------------|----------|
| `shareext` → `shareextqry` | `last_date >= initDate` | 按 MODE 决定是否 truncate，再 `getBnData` |
| `hisshareext` → `hisshareextqry` | `end_date = initDate` | 同上；若 shareext 为增量，执行 `deleteData`：删除 shareextqry 中已出现在当日 his 中的同键记录 |

#### （6）累计浮动盈亏 `shareextaccum` → `shareextaccumqry`（第5位）

| 模式 | 交易侧过滤 | 公共侧 |
|------|------------|--------|
| 增量 | `last_date >= initDate` | merge |
| 全量 | 无 where | truncate + 导入 |

#### （7）TA 份额明细 `tasharedetail` → `tasharedetailqry`（第6位）

- 交易：**始终全量** select（不读 SYNC_MODE）
- 公共：**固定 truncate + getBnData**

#### （8）入账记录 `square` → `squareqry`（第9位）

- 交易：分表全量 select
- 公共：固定 truncate + getBnData
- 无独立增量参数分支

### 5.3 分表与文件约定

- 交易导出：`getTableBy16(tablename[, where])` 对 `tbxxx1..N`（`N=ShardingUtil.getShardingTableNum(CPLX_FUND)`）做 `UNION ALL`。
- 文件名：`{目标表名}~{taCode}~{yyyyMMdd}~{areaId}.txt`。
- 公共侧按 `1..totAreaNum` 收齐各片区文件后导入。

## 6. 后续影响

### 6.1 对日终链路的影响

| 影响点 | 说明 |
|--------|------|
| 执行顺序 | 必须先 T01 导出成功，再 T02 导入；T02 失败会导致公共查询库数据过期或缺数 |
| 后置节点 | 依赖公共查询库的后续 Job（如部分环境主机对账挂在本 Job 之后）会读到同步结果 |
| 失败策略 | 任一 Task `failNum>0` 整节点失败；需查批量日志定位具体表 |
| 与 DataX | 公共侧表锁降低冲突；若现场仍用 DataX 同步同名表，需避免双通道同时写（部分银行已改为仅走 210503） |

### 6.2 对查询 / 管理台 / 报表的影响

同步成功后，公共库下列数据成为管理台与公共查询的主要来源（联机交易多数仍读交易分表）：

| 目标表 | 典型下游（据代码引用归纳） |
|--------|----------------------------|
| `tbdxfundshareqry` | 份额查询、持仓收益、销售看板、换卡相关更新等 |
| `tbdxfundsharedtlqry` | 份额明细查询、部分银行市值/头寸类汇总 |
| `tbdxfundsharechgqry` | 客户份额变动查询 |
| `tbdxfundtransreq`（公共） | 当前流水查询、产品主页快照、销售看板等 |
| `tbdxfundshareextqry` / `hisshareextqry` | 浮动盈亏、持仓收益展示；his 表部分场景仍读交易分表 |
| `tbdxfundshareextaccumqry` | 历史收益率 / 累计浮动盈亏展示 |
| `tbdxfundtasharedetailqry` | 份额明细/费用类查询（MxFe 等） |
| `tbdxfundsquareqry` | 当前入账查询、T0 入账、在途资金、资金监控（常与 `hissquareqry` 联合）、销售看板等 |

### 6.3 参数变更影响

| 变更 | 影响 |
|------|------|
| 关闭某控制位 | 当日公共侧对应表**不会更新**（全量表若未 truncate 则保留旧数；固定 truncate 的表在未跑 Task 时也不会被本节点清空——仅 Task 执行时才 truncate） |
| 份额日控改为非每日且未到指定日 | **不跑**份额同步，公共 `shareqry` 可能滞后 |
| 增量改全量 | 导出/导入数据量显著增大，拉长跑批窗口 |
| 仅改交易侧或仅改公共侧参数 | 两侧独立读参，不一致会导致「一侧导出、一侧不导入」或反向；**两侧参数必须对齐** |
| 开启第9位入账同步 | 公共 `squareqry` 覆盖当日全量入账，支撑管理台入账/资金类查询；需评估与历史入账归档（如 T210015 相关）的衔接 |

### 6.4 数据一致性注意点

1. **公共侧选型不读 T01 应答**：现场排障时不能假设「应答有表名就一定导入了」——需核对公共侧控制位是否同步打开。
2. **份额变动增量用物理日**：系统日切日前后可能与清算日不完全一致。
3. **流水增量用 modify_timestamp**：漏改时间戳的数据可能进不了增量包。
4. **第4位 his/shareext 去重**：公共侧增量导入后会删 shareextqry 中已进 his 的键，避免浮盈重复展示。
5. **第7、8位预留**：扩展新表时应顺延位数并同步两侧 Adapter，避免与现场已配长控制串冲突。

## 7. 关键参数速查

| 参数 ID | 用途 |
|---------|------|
| `T210503_SYNC_TABLE_CONTROL_FLAG` | 按位开关同步表（1/2/3/4/5/6/9） |
| `T210503_SHARE_SYNC_EVERY_DAY` | 份额是否每日同步（默认 1） |

| `QUEUESIZE210503` | 每线程等待队列（默认 5） |

## 8. 设计小结

```text
交易片区业务表（分表）
        │  条件：日控 / 控制位 / 全量·增量 where
        ▼
   标准同步文件（按 areaId）
        │
        ▼
公共片区查询表（*qry 或同名 transreq）
        │
        ▼
管理台查询 · 报表 · 资金监控 · 销售看板 …
```

210503 不改写交易主业务结果，只做**查询库投影**；其正确性直接影响管理台与公共查询口径，不影响联机成交路径（联机仍以交易分表为准）。投产与排障时优先核对：**调度顺序、两侧控制位一致性、全量/增量模式、文件是否按片区收齐、表锁与 DataX 是否冲突**。

## 9. 待确认 / 现场差异

1. 具体银行父 Job、是否扩展 T03/T04 反向同步，以该行 `spsql` 为准。  
2. 调度平台是否消费 `SyncTables`/`SyncFileNames`（代码公共侧未用于选型）。  
3. 个别联机是否直读 `*qry`（多数联机读交易分表；qry 以管理台/公共批量为主）。  
4. `tbdxfundhisshareextqry` 完整只读清单以各管理台 Service 为准。  
5. 控制位第7、8位若现场已有约定用途，扩展前需先盘点参数串长度与含义。
