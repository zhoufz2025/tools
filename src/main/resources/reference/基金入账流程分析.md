# 基金业务入账流程分析

> 文档说明：本文基于标准实现梳理。入账文件、主机差错文件格式以标准类为准；各银行可通过个性化 Bean 覆盖，实际落地以该行实现为准（见第十章）。

## 一、流程概述

基金客户上账流程是指将TA确认后的交易资金通过主机系统进行入账处理，并处理主机返回的入账差错记录的完整流程。整个流程包括：

1. **入账流程**：入账前处理、生成入账文件、发送文件到主机
2. **主机处理**：主机系统处理入账文件，给客户上账
3. **入账差错处理**：获取主机返回的差错文件、导入差错记录、同步到各片区
4. **差错补处理**：根据差错记录进行补处理（如重新入账）

这是一个完整的闭环流程，确保客户资金能够正确上账，并处理入账失败的情况。

**两类核心文件（详见第十章）**：

| 文件类型 | 方向 | 标准文件名示例 | 生成/消费节点 |
|----------|------|----------------|---------------|
| 入账文件 | 理财 → 主机 | `square.{taCode}.{YYYYMMDD}` | T210013 生成，T210302 发送 |
| 主机入账差错文件 | 主机 → 理财 | `bkerrsquare.{taCode}.{YYYYMMDD}` | T210213 获取并导入 |

### 2.1 日启流程：处理前一天的入账差错

```

    ↓
[公共片区] 取主机入账差错文件 (PUB210213 / T210213) - J210213T01

    ├─ 导入到主机差错表 (tbdxfundsquareerr)
    └─ 按内部客户号拆分文件发送到对应交易片区
    ↓
[交易片区] 取主机入账差错文件 (DXFUND210213 / T210213) - J210213T02

```

## 三、详细流程分析

### 流程说明

客户上账流程分为两个主要部分：
1. **日启流程**：处理前一天的入账差错（3.5-3.8节）
2. **日终流程**：生成并发送当天的入账文件（3.1-3.4节）

两个流程形成闭环，确保入账成功和差错处理。

### 3.0 前置流程：单TA清算结束（T210110）

**位置**：`lcpt-dxfund-trans-batch-bootstrap/src/main/java/com/hundsun/lcpt/dxfund/batch/adapter/T210110/T210110HSAdapter.java`

**说明**：虽然T210110不在入账流程的主要节点中，但它为入账流程做了重要的数据准备工作。

**主要功能**：
- 完成单TA清算结束后的数据处理
- 更新资金清算表的清算日期
- 将账务状态从未入账更新为待入账

**关键处理步骤**：

1. **备份数据**（`backupRedoData()`）
   - 备份关键表数据，用于清算重做
   - 涉及表：`tbdxfundtranscfm`、`tbdxfundsquare`、`tbdxfundshare` 等

2. **临时表导入正式表**（`bakDataIntoCurData()`）
   - 将临时表数据导入正式表
   - 涉及表：`tbdxfundtranscfm00` → `tbdxfundtranscfm`
   - 涉及表：`tbdxfundsquare00` → `tbdxfundsquare`

3. **更新资金清算表清算日期**（`updateSquareDate()`）
   - 从确认表（`tbdxfundtranscfm`）更新清算日期到资金清算表（`tbdxfundsquare`）
   - 关联关系：`tbdxfundtranscfm.clear_date` → `tbdxfundsquare.clear_date`
   - 更新条件：`tbdxfundtranscfm.serial_no = tbdxfundsquare.serial_no`

4. **账务状态更新**
   - 将资金清算表的入账标志从"未入账"更新为"处理中"
   - 更新字段：`tbdxfundsquare.status` 从 `K_RZBZ.RZBZ_NO`（`'0'`）更新为 `K_RZBZ.RZBZ_DOING`（`'1'`）

**涉及表**：
- `tbdxfundtranscfm{1-16}`：确认表（分表）
- `tbdxfundsquare{1-16}`：资金清算入账表（分表）
- `tbdxfundsquare00`：资金清算入账临时表

### 3.1 公共片区入账前处理（PUB211013 / T211013）

**位置**：`lcpt-dxfund-pub-batch-bootstrap/src/main/java/com/hundsun/lcpt/dxfund/pub/batch/adapter/T210013/T211013HSAdapter.java`

**调度节点**：`J210013T01`

**主要功能**：
- 校验日间入账是否完成
- 校验入账日调整（可选）
- 更新资金录入表和资金划付表状态
- 更新资金划付表的入账日期

**关键处理步骤**：

1. **校验日间入账是否完成**（`action()`）
   - 如果非日间入账（`DAILY_SQUARE_FLAG != '1'`），校验是否存在未完成的日间入账
   - 查询 `tbdxfunddaytimesquarerecord` 表
   - 如果存在未完成的日间入账，抛出异常
   - 参数 `DXFUND_211013_THROW_UNCOMPLETED_DAILY_SQUARE` 控制是否校验

2. **校验入账日调整**（`checkReceiptAdjust()`，可选）
   - 如果参数 `CHECK_RECEIPT_ADJUST='1'`，校验当天入账的交易是否做过入账日调整
   - 查询 `tbdxfundpayment` 表中是否有未做入账日调整的记录
   - 如果存在，抛出警告或异常

3. **更新资金录入表和资金划付表状态**（`updatePaymentDateAll()`）
   - 根据参数 `SQUAREMODE` 控制更新逻辑：
     - **`SQUAREMODE='0'`（正向勾对，默认不入账）**：
       - 更新 `tbdxfundreceipt.deal_status = '处理中'`（`K_RZBZ.RZBZ_DOING`，值为 `'1'`）
       - 条件：存在对应的 `tbdxfundpayment` 记录且 `deal_status = '未处理'`（`K_RZBZ.RZBZ_NO`，值为 `'0'`）
       - 更新 `tbdxfundpayment.deal_status = '处理中'`（`K_RZBZ.RZBZ_DOING`，值为 `'1'`）
       - 如果参数 `UPD_PMT_SQUARE_DATE='1'`，同时更新 `tbdxfundpayment.square_date`
     - **`SQUAREMODE='1'`（反向勾对，默认入账）**：
       - 更新 `tbdxfundreceipt.deal_status = '处理中'`（`K_RZBZ.RZBZ_DOING`，值为 `'1'`）
       - 条件：存在对应的 `tbdxfundpayment` 记录且 `deal_status = '未处理'`（`K_RZBZ.RZBZ_NO`，值为 `'0'`）
       - 如果参数 `UPD_PMT_SQUARE_DATE='1'`，更新 `tbdxfundpayment.square_date` 为 `tbdxfundreceipt.square_date`
   - 如果参数 `RECEIPT_SUPPORT_BUSIN='1'`，支持分业务划款
   - 支持日间入账时，可添加产品代码条件

**涉及表**：
- `tbdxfundreceipt`：资金录入表
- `tbdxfundpayment`：资金划付表
- `tbdxfunddaytimesquarerecord`：日间入账记录表

**关联关系**：
- `tbdxfundreceipt` 与 `tbdxfundpayment` 关联：
  - 关联字段：`clear_date`、`prd_code`、`trans_date`、`tot_amt`
  - 如果支持分业务：还需要匹配 `busin_code`
- `tbdxfundpayment.square_date` 从 `tbdxfundreceipt.square_date` 更新

**可个性化点**：
- ✅ **校验逻辑**：可通过参数 `CHECK_RECEIPT_ADJUST` 控制是否校验入账日调整
- ✅ **更新逻辑**：可通过参数 `SQUAREMODE` 和 `UPD_PMT_SQUARE_DATE` 控制

### 3.2 交易片区生成入账文件（DXFUND210013 / T210013-TRANS）

**位置**：`lcpt-dxfund-trans-batch-bootstrap/src/main/java/com/hundsun/lcpt/dxfund/batch/adapter/T210013/T210013HSAdapter.java`

**调度节点**：`J210013T02`（依赖 `J210013T01`）

**主要功能**：
- 更新资金清算表的清算日期和入账日期
- 处理收益本金拆分
- 生成入账文件并发送到分布式文件服务器
- 更新资金清算表状态为已导出

**关键处理步骤**：

1. **更新资金清算表清算日期**（`updateSquareDate()`）
   - 从确认表更新清算日期到资金清算表
   - 更新入账日期（`square_date`）
   - 关联关系：
     ```sql
     UPDATE tbdxfundsquare 
     SET clear_date = (SELECT clear_date FROM tbdxfundtranscfm WHERE serial_no = tbdxfundsquare.serial_no),
         square_date = ?
     WHERE ...
     ```

2. **收益本金拆分处理**（`dealSquareSplit()`）
   - 如果参数 `FUND_SPLITDZINCOME='1'`，支持本金收益分开入账
   - 将一条记录拆分为两条记录（本金和收益）
   - 更新 `amt_flag` 字段区分本金和收益

3. **生成入账文件**（`createAndSendSquareFile()`）
   - 从资金清算表（`tbdxfundsquare`）查询待入账记录
   - 查询条件（标准 `CreateSquareFileService`）：
     - `square_date = 系统日期（init_date）`
     - `square_status <> '2'` 且 `square_status <> 'P'`（排除已入账、已导出）
     - 可选：`FUND_SPLITDZINCOME='1'` 时排除 `amt_flag='3'`
   - 生成入账文件：Bean `T210013_CreateSquareFile`（接口 `IDxFundCreateHostFile`）
   - **标准行格式、字段顺序、命名规则见第十章 10.1**
   - **文件发送到分布式文件服务器**，供公共片区合并
   - 本地/片区路径示例：`{SQUARE本地路径}/square.{taCode}.{date}`，远程：`{SQUARE远程路径}/{areaId}/`

4. **更新资金清算表状态**（`updateSquareStatus()`）
   - 更新 `square_status = '已导出'`（`K_JKCLBZ.K_JKCLBZ_EXPORT`，值为 `'P'`）
   - 更新条件由参数 `UpdateSquareCon` 控制

5. **内部户余额校验**（可选）
   - 如果参数 `SQUARE_NEED_CHECK_BALANCE='1'`，生成内部户余额对账文件
   - 用于联机进行余额校验

**涉及表**：
- `tbdxfundsquare{1-16}`：资金清算入账表（分表）
- `tbdxfundtranscfm{1-16}`：确认表（分表）

**关联关系**：
- `tbdxfundtranscfm` 与 `tbdxfundsquare` 关联：
  - 关联字段：`serial_no`（主键）
  - 清算日期关联：`tbdxfundtranscfm.clear_date` → `tbdxfundsquare.clear_date`

**可个性化点**：
- ✅ **生成入账文件格式**：可通过实现 `IDxFundCreateHostFile` 接口个性化
  - Bean名称：`T210013_CreateSquareFile`
  - 方法：`createHostFile(IContext context, String fileName)`
  - 字段级格式说明见 **第十章 10.1**

### 3.3 公共片区合并入账文件（PUB210013 / T210013-PUB）

**位置**：`lcpt-dxfund-pub-batch-bootstrap/src/main/java/com/hundsun/lcpt/dxfund/pub/batch/adapter/T210013/T210013HSAdapter.java`

**调度节点**：`J210013T03`（依赖 `J210013T02`）

**主要功能**：
- 更新资金录入表和资金划付表状态为已处理
- 合并多个交易片区的入账文件
- 生成最终的入账文件

**关键处理步骤**：

1. **处理内部户余额校验文件**（`dealCheckFile()`）
   - 如果参数 `SQUARE_NEED_CHECK_BALANCE='1'`，处理内部户余额对账文件
   - 从分布式文件服务器获取各交易片区的校验文件
   - 合并校验文件

2. **更新资金录入表和资金划付表状态**（`udpateReceiptStatus()` / `udpateReceiptStatusAll()`）
   - 根据参数 `SQUAREMODE` 控制更新逻辑：
     - `SQUAREMODE='0'`（正向勾对，默认不入账）：
       - 更新 `tbdxfundreceipt.deal_status = '已处理'`（`K_RZBZ.RZBZ_OVER`，值为 `'2'`）
       - 更新 `tbdxfundpayment.deal_status = '已处理'`（`K_RZBZ.RZBZ_OVER`，值为 `'2'`）
     - `SQUAREMODE='1'`（反向勾对，默认入账）：

#### 3.9.3 业务处理流程

```
管理台查询差错记录（SqaureErrQry）
    ↓
分析差错原因（err_code / err_msg）
    ↓
必要时修正数据（SqaureErrEdit，如换卡/改账号）
    ↓
发起补处理（SqaureErrDeal / BatchDeal → 联机发核心）
    ↓
（可选）结果同步 / 审批（Sync / Approve）
```

**详细步骤**：

1. **查询差错记录**（菜单：基金代销资金清算差错记录查询）
   - 数据来源：`tbdxfundsquareerr`（日启 T210213 / T211213 导入、同步后）
   - 常见条件：入账日期、账务状态（如未处理 `'6'`）、`batch_flag`（`'0'` 日终 / `'1'` 日间）、补处理状态等
   - 通过 `serial_no` 关联 `tbdxfundsquare{1-16}` 查看原清算记录

2. **分析差错原因**
   - 根据 `err_code`、`err_msg` 判断：账号错误/销户、余额不足、账户冻结止付、金额不符、超时/系统异常等

3. **修正数据**（可选）
   - 页面编辑或更新原清算相关字段（如 `bank_acc`）后再发起补处理
   - 勿在未核对流水的情况下直接改库

4. **发起补处理**
   - **单笔**：`ifmCCxglDxfundSqaureErrDeal` → `dealSquareService` 组包联机发核心
   - **批量**：`ifmCCxglDxfundSqaureErrBatchDeal` → 多选逐条处理，汇总成功/失败
   - 成功后更新差错/清算相关状态（如补处理成功 `'7'` 等，见第六章账务状态）

**涉及表**：
- `tbdxfundsquareerr`：入账差错表（公共片区和交易片区）
- `tbdxfundsquare{1-16}`：资金清算入账表（分表）

**关联关系**：
- `tbdxfundsquareerr.serial_no` = `tbdxfundsquare.serial_no`（一对一关系）
- 通过 `serial_no` 可以追溯到原始入账记录的所有信息

**注意事项**：
- 差错补处理需要仔细分析差错原因，避免重复错误与重复上账
- 修正数据后需要重新验证数据的正确性
- 日间入账的差错需单独筛选（`batch_flag='1'`）
- 补处理子交易/按钮依赖菜单权限与银行增量脚本，现场以已下发 `tsys_subtrans` 为准

## 八、注意事项

1. **数据一致性**：
   - `tbdxfundtranscfm.clear_date` 应该与 `tbdxfundsquare.clear_date` 保持一致
   - 如果两者不一致，可能导致入账日期错误

2. **分表处理**：
   - `tbdxfundsquare` 和 `tbdxfundtranscfm` 都是分表（1-16），需要循环处理
   - 分表规则：根据 `in_client_no` 的哈希值分片

3. **事务控制**：
   - 入账文件生成和状态更新需要在同一事务中完成
   - 避免文件生成成功但状态未更新的情况

4. **差错处理**：
   - 入账失败的记录会写入 `tbdxfundsquareerr` 表
   - 日启流程会自动获取并导入差错记录
   - 需要根据差错代码和差错信息进行补处理
   - 差错数据会在公共片区和交易片区之间同步

5. **日间入账**：
   - 支持日间入账时，需要设置 `DAILY_SQUARE_FLAG='1'`
   - 日间入账的差错记录 `batch_flag='1'`

6. **并发控制**：
   - 多个交易片区同时生成入账文件时，需要注意文件合并的顺序
   - 公共片区合并文件时需要保证数据完整性
   - 多个交易片区同时同步差错数据时，需要保证数据一致性

7. **差错处理时机**：
   - 入账差错文件在次日日启时获取
   - 文件日期由参数 `SQUARERRFILE_DATE` 控制
   - 日间入账的差错记录 `batch_flag='1'`，需要单独处理

8. **数据同步**：
   - 差错数据需要在公共片区和交易片区之间同步
   - 交易片区处理差错后，需要同步回公共片区
   - 确保公共片区有完整的差错数据用于查询和管理

   - 这样可以避免硬编码，提高代码的可维护性

2. **数据库存储字符值**：
   - 数据库中存储的是字典的字符值（如 `'0'`、`'1'`、`'P'` 等）
   - 查询和更新时需要使用字符值

3. **字典配置**：
   - 字典值在数据库的字典表中配置
   - 字典表名称通常为 `tbdict` 或类似名称
   - 字典代码对应 `IDict` 接口中的 `NAME` 常量

4. **个性化扩展**：
   - 如果需要扩展字典值，需要在 `IDict.java` 中添加新的常量
   - 同时在数据库的字典表中添加对应的配置

## 十、入账文件与差错文件格式详解

本章说明**标准实现**下的文件约定。多数银行会对主机接口做个性化，字段顺序、分隔符、摘要码可能完全不同；对接某行时请同时核对该行 `CreateSquareFile*` / `*LoadSquareErr*` 实现。

### 10.1 发给主机的入账文件（square）

#### 10.1.1 文件角色与流转

```
tbdxfundsquare{1-N}
        │  T210013-TRANS（各交易片区并行）
        ▼
片区本地：square[.6.0].{taCode}[.{prdCode}.{businCode}|.{pollSeq}].{YYYYMMDD}
        │  上传分布式文件服务 {remote}/{areaId}/
        ▼
T210013-PUB 合并各片区文件
        │
        ▼
合并后：{IFMBASEPATH}/detail/{taCode}/ 或 {SQUAREFILEPATH}/
        │  T210302 发送
        ▼
主机目录（HOSTCHECKPATH 等配置）
```

#### 10.1.2 文件命名

| 场景 | 命名规则 | 说明 |
|------|----------|------|
| 默认 | `{prefix}.{taCode}.{initDate}` | `prefix` 默认 `square`，来自配置 `T210013.fileNamePrefix` |
| `HOST_FILE_NAME_MODE=1` | `{prefix}.6.0.{taCode}.{initDate}` | 带版本段 `6.0` |
| 日间入账 | 在 taCode 后追加 `.{prdCode}`、`.{businCode}`（有值才拼） | 防多批次文件名冲突 |
| 日间轮询 | 追加 `.{当日轮询批次号}` | 批次号来自参数 `211013_DAILY_POLL_COUNT_{YYYYMMDD}` |

示例：

- 日终、默认 TA：`square.000000.20260805`
- 带版本：`square.6.0.000000.20260805`
- 日间某产品赎回：`square.000000.PRD001.124.20260805`

#### 10.1.3 通用物理属性（标准 CreateSquareFileService）

| 项 | 标准值 | 说明 |
|----|--------|------|
| 编码 | **GBK** | `CreateSquareFileTemplate` 默认则为 UTF-8，以实际 Bean 为准 |
| 行分隔 | `\n`（`writeBytes("\n")`） | 一行一笔 |
| 字段分隔 | **竖线 `\|`** | 末字段后仍可能带分隔符 |
| 表头 | **无** | 纯数据行，无字段名行 |
| 金额 | `DataUtil.formatDouble` | 一般两位小数文本 |
| 空值 | 空串或空格，仍占位 | 不要省略字段导致列错位 |

代码位置：

- 标准：`.../T210013/CreateSquareFileService.java`（Bean：`T210013_CreateSquareFile`）
- 模板：`.../T210013/CreateSquareFileTemplate.java`（银行继承后只改 `formatResultLine`）

#### 10.1.4 标准数据行字段顺序（按列号）

标准 `formatResultSplit` 按下列顺序写出（分隔符 `|`）。序号从 0 起：

| 序号 | 字段 | 来源 / 含义 |
|------|------|-------------|
| 0 | square_no | 清算流水号 |
| 1 | bank_no | 法人行号 |
| 2 | trans_date | 交易日期 YYYYMMDD |
| 3 | clear_date | 清算日期 |
| 4 | serial_no | 业务流水号（关联确认/差错） |
| 5 | busin_code | 业务代码（如 124 赎回等） |
| 6 | client_type | 客户类型 |
| 7 | client_no | 客户号 |
| 8 | bank_acc | 银行账号（投顾虚拟卡场景可能已换成 `ori_bank_acc` 真实卡） |
| 9 | ta_code | TA 代码 |
| 10 | branch_no | 机构号 |
| 11 | oper_no | 柜员号 |
| 12 | prd_code | 产品代码 |
| 13 | curr_type | 币种 |
| 14 | cash_flag | 钞汇标志 |
| 15 | channel | 渠道 |
| 16 | liqu_dir | 账务方向（借/贷/解冻扣等，见 `K_ZWFX`） |
| 17 | amt | 入账金额 |
| 18 | unfrozen_amt | 解冻金额 |
| 19 | frozen_amt | 冻结金额 |
| 20 | reserve1 | 保留字段 |
| 21 | status | 入账标志 `K_RZBZ` |
| 22 | square_date | 入账日期 |
| 23 | prd_account | 产品归集/相关账号 |
| 24 | host_trans_code | 主机交易码 |
| 25 | host_date | 主机日期 |
| 26 | host_serial | 主机流水 |
| 27 | square_status | 接口处理标志 `K_JKCLBZ` |
| 28 | distrib_flag | 分配标志 |
| 29 | amt_flag | 金额标志（0 本金 / 1 收益 / 2 本金+收益 / 3 其他等） |
| 30 | seq_no | 序号（拆分本金收益时常见） |
| 31 | acc_relation_flag | 账户关系标志（标准常写空格） |
| 32 | err_code | 错误码（生成时多为空） |
| 33 | err_msg | 错误信息（生成时多为空） |

其后为**条件扩展列**（有则追加，无则不写，因此列数可变）：

| 条件 | 追加字段 |
|------|----------|
| 参数 `SquareHaveCardType=1` | `card_type`（或空格） |
| `liqu_dir` 为募集期解冻扣款（业务 120/130 且解冻扣） | 验资户账号、户名、开户行号、开户行名（`PrdBankAcc` 验资账户） |
| `liqu_dir` 为解冻扣 / 扣款 | 上划（注册登记）账号、户名、行号、行名 |
| `liqu_dir` 为上账（贷） | 下划（兑付）账号、户名、行号、行名 |

```text
20260805000001|000|20260805|20260805|SN20260805001|124|1|C0001|6222********|000000|001|0000|PRD001|156|0|1|1|1000.00|0.00|0.00| |1|20260805|ACCTDOWN|300202|0| |0| |0|0| | | |
```

#### 10.1.5 查询范围（标准）

从各分表 `tbdxfundsquare{i}` 取数，核心条件：

- `square_date = sysArg.initDate`
- 非默认 TA 时：`ta_code = ?`
- `square_status` 不等于已入账 `'2'`、不等于已导出 `'P'`
- `FUND_SPLITDZINCOME=1` 时：`amt_flag <> '3'`
- 日间：可再按 `prd_code`、`busin_code` 过滤

#### 10.1.6 个性化提示

银行个性化往往**不再使用**上表字段顺序，例如东莞银行按「组序号 + 借/贷明细」拼核心批量记账格式。判断某行是否标准：看 Spring 是否覆盖了 `T210013_CreateSquareFile`。

### 10.2 主机返回的入账差错文件（bkerrsquare）

#### 10.2.1 文件角色与流转

```
主机处理 square 文件后，对失败记录生成差错文件
        │
        ▼
本地：{IFMBASEPATH}/detail/{taCode}/bkerrsquare[.6.0].{taCode}.{文件日期}
        │  T210213-PUB loadTransResultFile
        ▼
tbdxfundsquareerr（公共）
        │  spiltAreaFile 按 in_client_no 拆片区
        ▼
tbdxfundsquareerr_{taCode}_{areaId} → 各交易片区导入
        │  T211213 标准交换再同步回公共（补处理后）
```

#### 10.2.2 文件命名与日期

| 项 | 规则 |
|----|------|
| 默认文件名 | `bkerrsquare.{taCode}.{fileDate}` |
| `HOST_FILE_NAME_MODE=1` | `bkerrsquare.6.0.{taCode}.{fileDate}` |
| `fileDate` | `SQUARERRFILE_DATE=1` → 当天 `init_date`；否则 → `prev_date`（常见：日启取**前一日**入账差错） |
| 本地目录 | `{IFMBASEPATH}/detail/{taCode}/` |
| 联机触发生成 | 交易 `HostOnline=1` 时发 400005，主机返回路径在应答 `Reserve` |

示例：日启取前一日、`ta=000000`、日期 `20260804` → `bkerrsquare.000000.20260804`

#### 10.2.3 物理属性与解析

| 项 | 标准值 |
|----|--------|
| 编码 | 参数 `FILE_ENDCODE_210213`，默认 **UTF-8** |
| 分隔符 | **竖线 `\|`**（`readLine.split("\\|")`） |
| 表头 | **无**（每行一笔差错） |
| 空行 | 跳过 |

代码位置：`.../T210213/T210213HSAdapter.java` → `loadTransResultFile`

#### 10.2.4 标准数据行字段（主机约定）

代码注释约定（列下标从 0）：

```text
square_date|流水号|seq_no|client_no|bank_acc|prd_code|amt|err_msg|curr_type|bank_no|err_code
```

| 序号 | 字段 | 导入到 tbdxfundsquareerr | 说明 |
|------|------|---------------------------|------|
| 0 | square_date | square_date | 入账日期，整型 YYYYMMDD |
| 1 | 流水号 | serial_no | **对应入账侧流水**（实现里按 square_no / serial_no 关联使用，与主机约定一致即可） |
| 2 | seq_no | seq_no | 与 square 拆分序号对应 |
| 3 | client_no | client_no | `CTRL_SQUAREERR_PARAM=0` 时直接用；`=1` 时改由 bank_acc 反查后写入 |
| 4 | bank_acc | bank_acc | 入账账号；`CTRL_SQUAREERR_PARAM=1` 时用其查 `tbclientmap` |
| 5 | prd_code | prd_code | 产品代码（组合宝等可能为 `000000`） |
| 6 | amt | amt | 失败金额 |
| 7 | err_msg | err_msg | 失败原因；默认截断约 100 字符（`T210213_SUBSTR_ERRMSG`） |
| 8 | curr_type | curr_type | **可缺省**，缺省按 `156`（人民币） |
| 9 | bank_no | bank_no | 仅 `ENABLE_THIRD_SELLER=1` 时取文件值，否则写默认法人行 |
| 10 | err_code | err_code | 可缺省，缺省空格 |

**样例行**：

```text
20260804|20260804000001|0|C0001|6222********|PRD001|1000.00|账户已销户|156|000|E001
```

日间入账导入时，还可能固定写入 `batch_flag='1'`，以及请求中的 `busin_code`。

#### 10.2.5 导入后关联与客户解析

- 表主键关联：差错 `serial_no`（+ `seq_no`）应对齐原 `tbdxfundsquare` 记录，便于补处理。
- `in_client_no`：**不由主机文件直接给出**，导入时反查：
  - `CTRL_SQUAREERR_PARAM=0`：`client_no` → `tbclientmap.in_client_no`
  - `CTRL_SQUAREERR_PARAM=1`：`bank_acc` → `tbclientmap`，再取卖出方客户号
- 公对公 / 无客户：`SQAURE_ERR_NO_CLIENTINFO_MODE=1` 时允许 `in_client_no` 为空；拆片区时此类记录写入**所有**交易片区。

#### 10.2.6 个性化提示

若配置了 `T210213_LoadSquareErrService` / `T210213_GetHostFileService`，主机文件名、列序、是否定长可能完全不同（如南京银行、江苏银行等实现）。联调时以该行解析代码为准。

### 10.3 片区间差错交换文件（非主机格式）

主机差错导入公共库后，公共片区再导出给交易片区；交易片区补处理后再同步回公共。这两类**不是** `bkerrsquare` 主机格式。

#### 10.3.1 公共 → 交易拆分文件（T210213 `spiltAreaFile`）

| 项 | 说明 |
|----|------|
| 文件名 | `tbdxfundsquareerr_{taCode}[_{prdCode}_{businCode}]_{areaId}` |
| 路径 | `ResourceUtil.getInnerFileLocalPath(SQUARE)`，再 `DfsPubBatchInnerFileTransferUtil.sendFile` |
| 格式 | **标准交换文件**：首行为字段名（`\|` 分隔），随后每行 `select *` 的字段值 |
| 编码 | `StandardFileContext.ENCODE` |
| 拆分键 | `ShardingUtil.getAreaId(in_client_no, 基金)` |

#### 10.3.2 交易 → 公共同步文件（T211213）

| 项 | 说明 |
|----|------|
| 导出 | `StandardFileWriter`，`select * from tbdxfundsquareerr where square_date=?` |
| 日期 | 同 `SQUARERRFILE_DATE` 规则 |
| 用途 | 各片区差错处理结果汇总回公共，供查询/管理台 |

---

### 10.4 两类文件对照速查

| 对比项 | 入账文件 square | 主机差错文件 bkerrsquare |
|--------|-----------------|--------------------------|
| 方向 | 理财 → 主机 | 主机 → 理财 |
| 内容 | 待上账明细（多字段） | 仅失败明细（少字段） |
| 标准分隔符 | `\|` | `\|` |
| 标准有无表头 | 无 | 无 |
| 标准编码 | GBK（标准生成） | UTF-8（默认导入） |
| 关键关联键 | square_no / serial_no / seq_no | serial_no + seq_no（+ prd_code 等） |
| 个性化频率 | 高（几乎每行核心接口不同） | 高（主机回盘格式因行而异） |

### 10.5 排查建议

1. 先确认当前环境是否注册个性化 Bean（`T210013_CreateSquareFile`、`T210213_LoadSquareErrService`）。
2. 对照实际文件：分隔符、编码、首行是否表头、列数是否与代码 `split` 下标一致。
3. 差错对不上 square：核对流水号字段是 `square_no` 还是 `serial_no`，以及 `seq_no`、`SQUARERRFILE_DATE` 取的是当天还是前一天。
4. 片区无差错：查 `in_client_no` 是否为空、是否开启无客户模式、拆分文件是否上传成功。
